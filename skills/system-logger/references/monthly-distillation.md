> 渐进披露：仅当触发「系统月报 / 月度系统蒸馏」时按需 Read。
> 主文件：`../SKILL.md`

## 月度系统蒸馏工作流（Trigger: "系统月报" / "月度系统蒸馏"）

> 每月初（次月1号）运行一次，或用户主动触发时运行。从上月系统日志中提取**数据→模式→洞察→建议**四层递进分析。

### 蒸馏步骤（4步）

#### 步骤 D1：定位上月日志文件

📦 **产出物**：定位到的上月日志文件列表（绝对路径）

🔌 **熔断器**
├─ 成功条件：Glob返回至少1个匹配的日志文件
├─ 失败处理：中止
├─ 可修正参数：日志文件路径模式 → 检查 [记忆共享中心]/工作日志/系统日志/ 目录是否存在
├─ 重试次数：1
└─ 降级方案：⚠️ "上月无系统日志文件，无法执行蒸馏"，中止流程不继续D2

**写入前Read确认（前置防误）**：
- ✅DO：定位文件后必须 Read 每个文件全文确认内容非空——空文件=物理阻断，中止流程。
- ✅DO：Read 返回的内容记录为蒸馏的原始数据源，后续D2-D4写入时以此为基准。
- ⛔DO NOT：跳过 Read 直接进入 D2 分析——原因是无数据源=分析是空中楼阁。
- 来源：v3.6.1 月度蒸馏防御对齐——与日写入步骤2.5同级Poka-Yoke防覆盖。

```bash
date -v-1m "+%Y-%m"  # macOS：获取上个月YYYY-MM
```

目标文件范围：`[记忆共享中心]/工作日志/系统日志/系统日志_{上个月}-*.md`

#### 步骤 D2：结论导向分析

📦 **产出物**：数据层统计 + 模式层发现 + 洞察提炼 + 行动建议（四层递进输出）

> 不是"先堆数据再找结论"，是"先问自己要验证什么，再去看数据"。
> 
> 三问定方向：
> 1. 这个月节奏健康吗？（比前月/基线，任务密度和方向是否一致）
> 2. 有什么反常？（异常点、趋势转折、跨工具/跨文件模式）
> 3. 下个月该停什么、启动什么、继续什么？（行动建议）

读取上个月所有日志文件，围绕上述三问提取：

##### 数据层（支撑结论的基础）

| 维度 | 提取方式 |
|------|---------|
| **总任务数** | 统计所有`### [标题]`条目（排除辅助条目如"格式完整性校验"） |
| **按工具分布** | 提取每条`- **工具**`字段 |
| **按类型分布** | 提取每条`- **类型**`字段，归类聚合 |
| **按周分布** | 按周统计任务数，看波动 |
| **对比上个月** | 如有上月蒸馏记录，读取并对比：总量变化(±N/±%)+一句话定性变化 | 首次基线月标注"无上月数据" |

##### 模式层（支撑结论的发现）

```
🔍 异常检测：找基线偏离——某天任务数翻倍或骤降、某类操作占比异常高、某周空窗
📈 趋势检测：上半月vs下半月对比——任务密度升/降、修改vs创建占比变化
🔗 关联分析：跨文件/跨工具协同——某文件反复修改、工具A→B→A的序列模式
```

> 三个方向按以下维度审视数据，无有价值发现时标注"无显著模式"。

##### 第三层：洞察提炼

```
🟢 好态势 / 🟡 混合态势 / 🔴 问题态势
[一句核心判断，纯数据驱动]
```

##### 第四层：行动建议

输出1-2条对下个月最直接的行动建议。**与每日伙伴的伙伴建议不重复**——每日伙伴建议个人效率，系统日志建议工作节奏和方向选择。

##### 🪞 成就证据提取（"最伟大的我"联动）

> 系统日志记"让AI做了什么工作"=人的工作成就。日记不会记这些，系统日志是成就证据的独立主数据源。

从本月日志中提取工作成就，写入 `[记忆共享中心]/最伟大的我/成就证据/`：

1. **筛选**：扫描所有任务条目，排除纯维护性操作（如版本号对齐、格式修正），保留有实质产出的条目
2. **视角转换**："AI做了什么" → "我决策并推动完成了什么"——每个日志条目背后都是人的决策
3. **补充字段**：日志只有"做了什么"，需补充"为什么能做成"+"反事实分析"（从日记/周报交叉验证）
4. **写入**：按 `成就证据/_模板.md` 格式写入 `[记忆共享中心]/最伟大的我/成就证据/{YYYY-MM-DD}-{事件简称}.md`
   - ⚠️ 文件须含 YAML frontmatter（格式见 `最伟大的我/文件格式约定.md` §3.2）

🔌 **熔断器**：成功=写入至少1条成就证据 | 失败=标注"⚠️本月无显著工作成就" | 不阻塞蒸馏流程

#### 步骤 D3：输出月度综览（结论先行）

📦 **产出物**：月度综览报告写入当前日志文件 + 验证外显输出

🔌 **熔断器**
├─ 成功条件：月度综览完整输出（含态势判断+佐证+建议）且成功写入当前日志文件
├─ 失败处理：降级
├─ 可修正参数：日志文件路径 → 检查日期和文件权限
├─ 重试次数：1
└─ 降级方案：对话输出月度综览但不写入文件，标注"⚠️ 综览写入失败，已对话输出"

**写入前Read确认（前置防误）**：
- ✅DO：写入当前日志文件前必须 Read 全文确认现有内容——与日写入步骤2.5同级防御。
- ✅DO：Write 时输出内容须包含全部现有内容+月度综览新增条目，禁止只写新增部分。
- ⛔DO NOT：不先 Read 直接 Write——Write 是全量覆盖，跳步=原有日志内容可能丢失。
- 来源：v3.6.1 月度蒸馏防御对齐——TE-20260702-001 同类风险必须覆盖蒸馏写入路径。

```
📊 月度系统蒸馏
━━━━━━━━━━━━━━
📅 上月：YYYY-MM | 📝 N条任务 | 🛠️ N个工具

🟢/🟡/🔴 [一句话态势判断——基于真实数据]

对比上月：[数字变化/核心一句话定性/首次运行则"无（基线月）"]

├─ 佐证：
│   ├─ 按工具：[工具分布]
│   ├─ 按类型：[类型分布]
│   ├─ 按周：[周分布]
│   └─ 连续：[如N周同趋势←需标注]
│
├─ 异常：[发现/无]
├─ 趋势：[方向/无]
└─ 关联：[模式/无]

建议：
├─ [行动建议一]
└─ [行动建议二]
```

> 无显著模式时标注"未检测到显著模式"。
> 写入当前日志文件作为一条记录（类型=分析），便于下个月蒸馏时回溯。

#### 步骤 D4：写入蒸馏中心

**写入前Read确认（前置防误）**：
- ✅DO：追加蒸馏中心前必须 Read `[记忆共享中心]/记忆蒸馏/蒸馏中心.md` 全文确认现有内容。
- ✅DO：Write 时输出内容须包含全部现有内容+本月蒸馏新行。
- ⛔DO NOT：不 Read 直接 Write——蒸馏中心是跨月累积记录，覆盖=已归档蒸馏数据丢失。
- 来源：v3.6.1 月度蒸馏防御对齐——与日写入步骤2.5同级Poka-Yoke防覆盖。

追加一行到 `[记忆共享中心]/记忆蒸馏/蒸馏中心.md` 对应月份表格，格式：

```
| 执行日期 | 📊 系统日志蒸馏 | ✅ | [一句话摘要：任务量N条，对比上月±N%/首次基线] | [次月1日] |
```
> 注意：追加内容为新增一行表格行，Write 时须包含原文件全部内容+新行。

📦 **产出物**：蒸馏中心.md 已追加

🔌 **熔断器**：成功=追加写入后Read验证 | 失败=对话输出"⚠️ 蒸馏中心写入失败，请手动补录" | 不阻塞，可跳过
