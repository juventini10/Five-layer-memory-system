# 错误记录模板

> **用途**：成长箱Skill流程A（错误记录）步骤A2的写入格式模板
> **引用方式**：SKILL.md流程A步骤A2引用此模板
> **v2.0变更**：Suggested Action改为Body三段式（Rule+Why+How to apply）——原因是只写"建议行动"不写"为什么"和"何时适用"，AI在边缘情况无法判断该不该执行

## 通用错误格式（LEARNINGS.md / ERRORS.md）

```markdown
## [ERR-YYYYMMDD-NNN] 错误名称

**Logged**: YYYY-MM-DDTHH:MM:SS+08:00
**Priority**: high | medium | low | critical
**Status**: pending | resolved | promoted
**Area**: 流程 | 验证 | 身份认知 | 其他
**来源 AI**: Trae | Trae Work | QClaw | WorkBuddy | 悟空 | 其他
**认知象限**: 已知未知（收集中） | 已知已知（已解决）

### Summary
[一句话总结错误]

### Details
[详细情况，1-3句话]

### Root Cause
1. **根因1**：[说明]
2. **根因2**：[说明]

### Rule
[一句话规则——犯了什么错，以后该怎么做]

### Why
[为什么这条规则存在——来源事件/偏好/根因]

### How to apply
[何时/何地适用——触发条件+适用范围+不适用情况]
```

## 字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| 编号 | ✅ | 格式：`[前缀-YYYYMMDD-NNN]`，如 `TE-20260530-001` |
| 错误名称 | ✅ | 简短描述错误类型，如"未验证就下结论" |
| Logged | ✅ | 错误发生时间，ISO 8601格式 |
| Priority | ✅ | high/medium/low/critical |
| Status | ✅ | pending（待处理）/resolved（已解决）/promoted（已晋升） |
| Area | ✅ | 错误所属领域 |
| 来源 AI | ✅ | 通用错误必填，专属错误可省略 |
| Summary | ✅ | 一句话总结 |
| Details | ✅ | 详细情况 |
| Root Cause | ✅ | 根因分析，至少1条 |
| Rule | ✅ | 一句话规则（替代原Suggested Action） |
| Why | ✅ | 规则存在的原因——来源事件/偏好/根因 |
| How to apply | ✅ | 何时/何地适用——触发条件+适用范围+不适用情况 |
| 认知象限 | ✅ | 错误记录时的认知状态——默认"已知未知（收集中）"（知道有错、在收集模式确认，对应认知无知矩阵第二象限）；Status=resolved/promoted 时标"已知已知（已解决/已蒸馏）"（错误已澄清→晋升为已知已知）。由 Poka-Yoke Schema 防错层强制必填 |
