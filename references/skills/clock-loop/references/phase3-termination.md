**v2.2.0新增：触顶判定（交付时自动计算）**

> 触顶 = 文档侧修复空间耗尽，继续修文档只能获得1-2pp提升，无实质改进意义。

| 指标 | 计算方式 | 触顶阈值 |
|------|---------|:---:|
| 维度饱和度 | 得分≥90%的维度数 / 总维度数 | ≥16/20 → 触顶 |
| 剩余可修复空间比率 | (100% - 各维度得分)之和 / 维度数 | <8% → 触顶 |
| 功能侧vs文档侧空间比 | 功能维度剩余空间 / 文档维度剩余空间 | >3:1 → 文档侧触顶，追分须转功能侧 |

触顶判定后：
- ✅DO：在交付建议中标注"文档侧已触顶，追分须转[功能侧/运行时测试/端到端验证]"
- ✅DO：建议用户下一轮评估用不同方式（如对话测试、运行时验证）
- ⛔DO NOT：继续建议文档修补类修复——浪费Token
