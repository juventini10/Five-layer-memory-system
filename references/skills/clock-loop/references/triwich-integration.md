## L1 第一性原理（评分前必做）

### 方法论定义

把评估对象拆解到最底层——不可再分的功能原子。

### 四问拆解模板

评分前必须回答以下四个问题，拆解结果写入评分表前言：

```
1. 核心功能是什么？
   → 不可再分的功能原子（一句话，不是"它是一个XX系统"）
2. 依赖什么？
   → 前置条件/输入（列出具体依赖项）
3. 输出什么？
   → 产出物/结果（列出具体输出）
4. 核心矛盾是什么？
   → 要解决的真正问题（一句话，不是表面问题）
```

### 执行规则

- ✅DO：L1拆解在Phase 1评分前执行
- ⛔DO NOT：跳过L1直接打分——原因是"凭感觉打分"是评估最大陷阱
- 来源：triwich SKILL.md「Step0判定→Step1衔接」熔断器段

## L2 批判验证（评分后必做）

### 方法论定义

对评分结果做自爆检查——不是验证"评分对不对"，是质疑"评分所依赖的假设对不对"。

> 🔴 **自爆触发判据统一（v3.11.0·M3修复·v3.17.0 补悬置档）**：自爆触发条件 = **8要素/各维度的「评估结论」全部为正面表述**，与置信度颜色（🟢/🟡/🔴/🔵）**无关**。置信度全 🟢 但结论有负面 → 不触发；置信度有 🟡/🔴/🔵 但结论全是正面 → **触发**，强制复检至少找出 2 条非正面发现。复检后仍全员正面 → 签名标 ❌。
> **🔵悬置档（v4.0.0 新增）**：证据不足，暂不下结论（权衡8确信程度四级·机制化你"行动前掌握足够信息才行动"）——⛔DO NOT 用🟢/🟡/🔴 替代🔵，悬置=承认"暂无结论"是独立状态。
> ⛔DO NOT 把"绿灯"理解成置信度颜色——原因是置信度衡量的是"我多确定"，评估结论衡量的是"它好不好"，两者混用会让"全绿=没问题"这条假阳性通道永久开着。

### 四项自检清单

评分完成后必须逐项检查：

| # | 检查项 | 通过标准 | 来源 |
|:-:|-------|---------|------|
| 1 | 锚点对立面 | 评分没有过度乐观（高分时）或过度悲观（低分时）。具体做法：写出当前评分的对立面论据，看是否成立 | triwich references/shared/anchor.md |
| 2 | 证据链完整性 | 每个维度的评分依据可追溯到具体文件/行号。具体做法：逐维度检查"依据"列是否有行号 | triwich references/shared/8element.md |
| 3 | 假设验证 | 评分所依赖的假设是否成立？假设错了评分会变吗？具体做法：列出评分依赖的假设，逐个验证 | triwich references/shared/8element.md |
| 4 | 结论块门禁锁 | 评分前已输出结论块（结论+依据+签名一致性）。具体做法：检查结论块是否存在且三问通过 | triwich SKILL.md「结论块门禁锁」段 |
| 5 | 心理轨·认知偏误扫描（v4.0.0 新增） | 三张表（穷查理误判25倾向+决策的艺术七大陷阱+逻辑学非形式谬误18种）至少各命中1项或明标"本轮无命中"·全"无命中"触发自爆 | triwich references/l1/critical-verify.md Step3.5 |

### L2签名

```
L2自检签名：✅/❌
  ├─ ✅ = 评分结果可信，进入下一环节
  └─ ❌ = 评分结果存疑，回退重评
```

> 🔴 **签名两轴分离（v3.11.0·M1/M2修复）**：签名轴与内容轴是两码事，不得互相污染。

| 轴 | 载体 | 取值 | 含义 |
|---|------|------|------|
| **内容判定轴** | 结论块 | ✅ / 🟡 / ❌ | 评估对象本身的好坏（🟡=部分成立/有条件成立） |
| **流程完整性轴** | 签名 | ✅ / ❌（二值，无第三态） | 本轮规定步骤是否全部走完 |

- 结论 🟡 + 流程完整 → 签名 **✅**（摘要里写清 🟡 的理由），不因结论不漂亮就签 ❌。
- 缺步 / 降级执行 / 子Agent超时 → 签名 **❌** + 输出缺失清单，⛔DO NOT 用 `✅ ⚠️降级` 混过去——原因是加一个 ⚠️ 就等于给二值签名开了灰区，防错阀失效。

### 执行规则

- ✅DO：L2自检在Phase 1评分完成后执行
- ✅DO：总分≥85%时尤其需要执行——原因是高分可能是锚定效应
- 来源：triwich SKILL.md「Step0 格式排他」段+「结论块门禁锁」段

### v3.8.6 新增：L3内联转发门禁锁

主agent 签名前必须已内联转发 Agent A 完整推导（段头+8要素），**未内联即输出签名 = 违规**（类比结论块门禁锁）。

| 要素 | 说明 |
|------|------|
| 文件通道定位 | 服务 Agent B 盲审隔离（subagent 看不到主聊的架构必需），**绝不替代对话内联**——两者都是必须项，不是二选一 |
| 主agent角色锁 | 主agent 只转发 Agent A/B 内联、不另写步骤段头 |
| 签名前置条件 | 内联转发完成 → 签名；未内联 → 签名=违规 |

> 🔴 **盲审隔离归一（v3.11.0·H3修复）**：Agent A 产出文件是 **Agent B 的唯一输入源**，不是"可选/备份"。原表述允许 Agent B"优先从对话上下文获取"——那等于把隔离寄托在"要求它别看"，而 LLM 的服从是概率的。改为**结构性隔离**：只喂文件、不给上下文，隔离靠"没给"实现，不靠"别看"实现。
