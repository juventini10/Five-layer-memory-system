## L1 第一性原理（评分前必做）

### 方法论定义

把评估对象拆解到最底层——不可再分的功能原子。

### 四问拆解模板

评分前必须回答以下四个问题，拆解结果写入评分表前言：

```
1. 核心功能是什么？
   → 不可再分的功能原子（一句话，不是"它是一个XX系统"）
2. 依赖什么？
   → 前置条件/输入（列出具体依赖项）
3. 输出什么？
   → 产出物/结果（列出具体输出）
4. 核心矛盾是什么？
   → 要解决的真正问题（一句话，不是表面问题）
```

### 执行规则

- ✅DO：L1拆解在Phase 1评分前执行
- ⛔DO NOT：跳过L1直接打分——原因是"凭感觉打分"是评估最大陷阱
- 来源：triwich SKILL.md L249-258（L1第一性原理路径）

## L2 批判验证（评分后必做）

### 方法论定义

对评分结果做自爆检查——不是验证"评分对不对"，是质疑"评分所依赖的假设对不对"。

### 四项自检清单

评分完成后必须逐项检查：

| # | 检查项 | 通过标准 | 来源 |
|:-:|-------|---------|------|
| 1 | 锚点对立面 | 评分没有过度乐观（高分时）或过度悲观（低分时）。具体做法：写出当前评分的对立面论据，看是否成立 | triwich references/shared/anchor.md |
| 2 | 证据链完整性 | 每个维度的评分依据可追溯到具体文件/行号。具体做法：逐维度检查"依据"列是否有行号 | triwich references/shared/8element.md |
| 3 | 假设验证 | 评分所依赖的假设是否成立？假设错了评分会变吗？具体做法：列出评分依赖的假设，逐个验证 | triwich references/shared/8element.md |
| 4 | 结论块门禁锁 | 评分前已输出结论块（结论+依据+签名一致性）。具体做法：检查结论块是否存在且三问通过 | triwich SKILL.md L277-281 |

### L2签名

```
L2自检签名：✅/❌
  ├─ ✅ = 评分结果可信，进入下一环节
  └─ ❌ = 评分结果存疑，回退重评
```

### 执行规则

- ✅DO：L2自检在Phase 1评分完成后执行
- ✅DO：总分≥85%时尤其需要执行——原因是高分可能是锚定效应
- 来源：triwich SKILL.md L256（L1批判验证路径）+ L277-281（结论块门禁锁）

## L3 抽象建模（跨周期沉淀，累计≥5次后激活）

### 方法论定义

从多次评估中提取模式——不是评单个对象，是从N次评估中发现共性规律。

### v3.8.6 新增：L3呈现骨架锁（设计端防误·接触法）

L3全流程思考内联/输出时，✅DO复用固定段头骨架——

| 段头 | 对应Step | 内容 |
|------|---------|------|
| 【抽象建模】 | Step1 | 问题抽象+变量识别 |
| 【第一性原理】 | Step2 | 原理推演+结论 |
| 【苏格拉底诘问】 | G1 | 五问批判验证 |
| 【批判验证】 | Step3 | Agent B盲审结果 |
| 【具象落地】 | Step4 | 可执行方案 |

**段头写死不可改，由 Agent A 在执行链内写出。** 主agent 无 Step 段头编写接口，只转发 Agent A 内联、不另写步骤。

⛔DO NOT在Skill执行链之外自造带Step编号的L3流程复述——编号与思维模块严格绑定，反贴即错。

### v3.8.6 新增：L3内联转发门禁锁

主agent 签名前必须已内联转发 Agent A 完整推导（段头+8要素），**未内联即输出签名 = 违规**（类比结论块门禁锁）。

| 要素 | 说明 |
|------|------|
| 文件通道（/tmp）定位 | 仅服务 Agent B 盲审隔离（subagent 看不到主聊的架构必需），**绝不替代对话内联** |
| 主agent角色锁 | 主agent 只转发 Agent A 内联、不另写步骤段头 |
| 签名前置条件 | 内联转发完成 → 签名；未内联 → 签名=违规 |

> 来源：triwich SKILL.md v3.8.6 L3呈现骨架锁 + L3内联转发门禁锁

### v3.8.9 新增：L3全量审查·前提核验指针

L3 阶段2·全量审查新增「前提核验」子弹：凡结论依赖可测量 artifact 事实（精确行数/标记密度/阈值跨越/真实计分），✅DO 先实测或要求提供真实数字；未测则在结论标 ⚠️前提未实测，不与已验证结论同权。

- ⛔DO NOT 让自然语言推理在可测事实未经实测的前提下拍板动手——原因是 NL 擅长逻辑/结构/缺陷，不擅核验 artifact 可测量事实，错前提上完美推理=结论崩。
- 来源：triwich `references/l3/full-flow.md` 阶段2·全量审查 + clock-loop 缺口3 实测（2026-07-11，L3 错前提被脚本推翻）

### 沉淀流程

```
积累N次评估结果 →
  ├── 扫描评估知识库test_results/目录中的历史评估数据
  ├── 提取反复出现的问题（≥3次的问题模式）
  ├── 评估维度是否需要调整（权重校准建议）
  ├── 知识库是否补充了足够支撑（知识缺口分析）
  └── 输出L3沉淀报告 → 写入评估知识库evolution/目录
```

### 执行规则

- ☑SHOULD：L3沉淀在累计≥5次评估后激活
- ⛔DO NOT：样本不足时强行提取模式——原因是少量样本的偶然性不能代表真实模式
- ⛔DO NOT：主agent用present_files替代对话内联——原因是子Agent看不到主聊，文件通道会漏出推导上下文
- 来源：triwich SKILL.md L293-296（L3双Agent深度模式）+ v3.8.6 L3呈现骨架锁 + v3.8.6 L3内联转发门禁锁
