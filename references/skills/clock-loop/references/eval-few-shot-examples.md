## 示例1：禁令写法（坏→好）

### ❌ 坏例子（纯禁令，无正面建模，无因果链）

```
⛔DO NOT用AI味话术。
```

**问题诊断**：
- 只有禁令，没有正面建模（什么样才是"人话"？）
- 没有因果链（为什么不能用AI味话术？）
- 没有可验证的判断标准（AI味话术的定义是什么？）

### ✅ 好例子（禁令+正面建模+因果链+可验证标准）

```
⛔DO NOT用AI味话术——原因是AI味话术=用户不信任=沟通失效。
✅DO用人话版本，标准参考提问手册§四的好/坏对照表。
可验证标准：输出中不出现"赋能/抓手/闭环/打法/组合拳"等AI味词汇，用具体场景化表达替代。
```

**好在哪里**：
- 禁令有因果链（AI味话术→用户不信任→沟通失效）
- 有正面建模（人话版本参考提问手册§四）
- 有可验证标准（不出现特定AI味词汇）

## 示例2：正面+禁令双轨

### ❌ 坏例子（只有正面建议，无禁令边界）

```
✅DO在输出中使用表格优先。
```

**问题诊断**：
- 只有正面建议，没有禁令边界（什么时候不能用表格？）
- 没有因果链（为什么表格优先？）
- 没有适用场景和失效场景

### ✅ 好例子（正面+禁令双轨+因果链+适用边界）

```
✅DO在结构化对比/多维度数据展示时使用表格优先——原因是表格=信息密度高=用户快速对比。
⛔DO NOT在简单一句话结论/情感表达/叙事性内容中强行用表格——原因是表格=结构僵化=破坏叙事流畅性。
适用场景：多维度对比/数据展示/状态汇总
失效场景：简单结论/情感表达/叙事性内容
```

**好在哪里**：
- 正面建议有因果链（表格→信息密度高→快速对比）
- 有禁令边界（什么时候不能用表格）
- 有适用场景和失效场景（双轨制）

## 示例3：外行同事测试（失败→通过）

### ❌ 失败例子（外行无法执行，有隐含前提）

```
执行Skill的终检步骤，确认所有容器已回流。
```

**外行测试结果**：❌失败
- "终检步骤"具体指哪一步？没有明确指向
- "所有容器"是哪些容器？没有清单
- "已回流"的判断标准是什么？没有可验证的产出物
- 外行AI实例无法执行，因为缺少明确的操作对象和判断标准

### ✅ 通过例子（外行可执行，无隐含前提，有明确产出物）

```
执行以下终检步骤：
1. Read [记忆共享中心]/记忆蒸馏/五容器/自画像.md，确认文件非空且包含当月日期
2. Read [记忆共享中心]/记忆蒸馏/五容器/变化轨迹.md，确认文件非空且包含当月日期
3. Read [记忆共享中心]/记忆蒸馏/五容器/认知发现.md，确认文件非空且包含当月日期
4. Read [记忆共享中心]/记忆蒸馏/五容器/回避模式.md，确认文件非空且包含当月日期
5. Read [记忆共享中心]/记忆蒸馏/五容器/成就证据.md，确认文件非空且包含当月日期
6. 5个文件全部非空且含当月日期=终检通过；任一缺失=终检失败，阻塞月报输出
```

**外行测试结果**：✅通过
- 每一步都有明确的操作对象（具体文件路径）
- 有明确的判断标准（文件非空且包含当月日期）
- 有明确的通过/失败判定（5个文件全部通过=终检通过）
- 外行AI实例可以直接执行，无需任何隐含前提

## 示例4：对抗性防御声明的标准写法

### ❌ 坏例子（防御声明空泛，无具体机制，无可验证标准）

```
本Skill具有防误机制，确保操作安全。
```

**问题诊断**：
- "防误机制"具体是什么？没有描述
- "确保操作安全"的可验证标准是什么？没有
- 是空泛声明，不是可执行的防御机制

### ✅ 好例子（防御声明具体，有机制，有可验证标准，有熔断器）

```
防误机制（三层防护）：
1. 设计端防误：修改用户文件前必须先创建备份（cp {file} {file}.bak.{timestamp}），无备份=阻断修改
2. 检查端防错：修改后必须Read验证文件内容完整性，Read返回空或内容缺失=阻断并回滚到备份
3. 熔断器：任一防护层失败=中止操作并报告，不降级继续
可验证标准：每次修改操作必须有对应的.bak.{timestamp}文件存在，且修改后Read验证通过
```

**好在哪里**：
- 有具体的三层防护机制（设计端/检查端/熔断器）
- 每一层都有可执行的操作（创建备份/Read验证/中止报告）
- 有可验证标准（.bak文件存在+Read验证通过）
- 不是空泛声明，是可执行的防御机制
