    1. 对 1 个派生产物，抽 1-2 个字段做**语义级**人工核对（不是"脚本 exit 0"）——例：路径改写后的目标目录是否符合落位语义（A 域的路径不该归到 B 域）、统计数字抽 1 个对源实数
    2. 判别「自洽」与「正确」两层：包=变换(源) 全绿只证明**自洽**；变换规则本身错了（如把 A 域路径归到 B 域），自洽照样全绿
  评分标准（纳入"逻辑一致性"维度）：
    - 抽验字段语义全对 → ✅通过（派生语义=100%）
    - 1 处语义错 → ❌未通过（派生语义=<60%·⚠️此类错误是全库级：一个规则错=所有产物错）
  实证：relocate 把「个人AI档案/数字分身」派生为脚本族根 → 包内 118 文件路径被错改为脚本中心形态，verify_parity（包=变换(源)）自洽全绿不报——2026-09-20 修引擎后全库重同步修正（错形态清零·幂等验证 0 更新）
  依据：铁律-007（先质疑自己·含质疑自己的验证工具）+ 验证两层论（自洽≠正确·2026-09-20 devtools 根治轮实证）
  ⛔DO NOT把"机械全绿"当"语义正确"的证据——原因是变换规则错了自检照样通过（假绿的最深形态：连独立校验器都被同一错误规则喂饱）
  →
报错可读性检测（v2.6.0新增·成长箱反哺2026-09-20·vNone 实证·JOB-003-20260920-001） →
  适用对象：含脚本报错/门禁输出/校验失败提示的 Skill（有面向用户的错误信息即启用；纯文档 Skill 跳过）
  检测方法：
    1. 抽取 Skill 脚本/流程中 3 条报错分支（优先抽门禁/校验/文件缺失类）
    2. 核三点：①文案区分故障类型（无法解析/不存在/不一致/过期各说各话）②内嵌下一步动作指引（覆盖/重跑/检查路径）③不暴露内部原始值（None/裸变量/原始堆栈直出）
  评分标准（纳入"指令准确性"维度）：
    - 3 条全过 → ✅通过（报错可读性=100%）
    - 1 条未过 → ⚠️部分通过（报错可读性=60-80%）
    - ≥2 条未过 → ❌未通过（报错可读性=<60%）
  判据表（v3.47.0 A22补·范式同上·⛔不新造判据·只把上面已有定义拆到可操作）：

    | 故障分型 | 报错说人话 | 抽报错分支核文案——"vNone""未知"式内部值直出=不可读 |
    | 动作指引 | 看完知道怎么办 | 核报错是否带下一步（覆盖/重跑/检查路径）——只报错不带指引=半成品 |

  ⛔DO NOT 把 None/空值直接插值进用户可见报错——原因是 exit code 传达给调用链、文案传达给人，两条通道缺一=半成品
  →
测试夹具卫生检测（v2.7.0新增·成长箱反哺2026-09-20·triwich 3候选实证·JOB-003-20260920-005） →

  评分标准（纳入"逻辑一致性"维度）：
    - 夹具 name 全部唯一化+不占扫描路径 → ✅通过（夹具卫生=100%）
    - 1 处冒用 → ❌未通过（夹具卫生=<60%·此类一处即构成注册表分叉候选·无部分通过档）
  判据表（v3.47.0 A22补·范式同上·⛔不新造判据·只把上面已有定义拆到可操作）：
    | 检查点 | 白话 | 操作 |

  依据：用户端《落点主权方案》取证四真机命中 + test_skill_eval.py 防再犯断言（test_fixture_names_not_colliding·2026-09-20 落地）+ NC001 正确示范对照
  ⛔DO NOT 新建测试夹具时沿用被测 Skill 的真实 name——原因是夹具随包分发后，用户机技能注册表就多一个同名候选
  →
逐维度评分 →
  对每个维度：
    1. 读取该维度的 check_items
    2. 逐项核对产出物（不是凭感觉打分）

输出评分表
