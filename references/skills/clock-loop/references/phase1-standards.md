### 阶段1:标准收集(每次触发必走,不可跳过)

📦 产出物:任务标准清单(写入 references/task-standards.json)

**触发规则:**
- ✅DO:首次触发某类任务 → 必须走完整5问收集
- ✅DO:用户消息中包含部分标准描述 → 必须走完整5问,将用户已提到的标准预填到对应选项
- ✅DO:用户明确说"用上次的标准" → 可读 task-standards.json 匹配,展示后确认
- ⛔DO NOT:因用户消息中包含了某些标准词汇就判定"标准已完整"并跳过收集
- ⛔DO NOT:在用户未对标准清单做明确确认之前进入阶段2

**Poka-Yoke预填(设计端防误 - 接触法+定值法+步序法):**
> 任务类型 A-H 枚举唯一真相源见 `references/taxonomy-map.md` §三——⛔此处预填触发词是物理功能（保留），枚举定义不另存副本。
- ✅DO - 展示5问前,从用户输入中提取对象特征,自动预填第1问任务类型:
  - 含"文案/文章/内容/稿" → 预填 A.审核这个内容
  - 含"Skill/技能" → 预填 E.评估这个Skill
  - 含"数据/报表/指标" → 预填 C.分析里面的数据
  - 含"代码/程序/bug" → 预填 D.修复/改进
  - 含"文档/报告" → 预填 B.基于这个生成新的
  - 含"安装包/发布包/布洛陀包" → 预填 G.检查发布包
  - 含"知识体检/知识库Lint/概念层" → 预填 H.知识库体检
  - 无匹配 → 不预填,展示全部选项
- ✅DO - 接触法预填后,以定值法固定1次确认:"📋 检测到你要[预填内容],对不?" - 用户明确确认后才能展开第2问。
  - 确认→ ✅ 定值通过,进入步序法:任务类型已锁定→展开匹配的检查清单。
  - 未确认("不对/不是/其他")→ 退回展示A-H选项重新选。
- ⛔DO NOT在用户确认之前视预填为已确定。
- ⛔DO NOT跳过定值确认直接展示检查清单--原因是定值法=固定1次确认是防误层的物理约束,跳了等于检查清单可能跟任务类型不匹配。

**同类任务判定规则:**
- 任务类型匹配 + 检查清单条目完全一致 = 同类任务,展示给用户确认后复用
- ✅DO(v4.13.0 确认二分):同类任务且新增成分全为L1形态级(判据见SKILL铁律「确认二分」——全grep/diff/exit可判·不动维度/权重/考题)→展示后自动复用不等应答,报告专项分析段逐项留痕(可观测/可抽检/可收回);含任一L2成分→维持展示+等明确确认。⛔拆碎伪装逃确认=维度/权重/考题diff可核验
- 任务类型匹配但检查清单不同 = 用户确认是否复用上次标准

进入Loop模式后,先读 references/task-standards.json:
- 文件缺失或损坏 → 走初始化流程(问标准)
- 有匹配标准 → 展示给用户确认"是这个标准没错吗?" 确认后进入阶段1.5
- 无匹配标准 → Read `references/standard-collection-template.md` → 用5个问题收集标准

**学习进度恢复(v2.2.0新增):**
当任务类型为F.学习这个领域时,在展示5问前先检查:
- ✅DO: 读取 task-standards.json 中 last_learning_session 字段
- 有记录 → 主动提示:"📖 你上次学到第{N}轮/概念{A}/{B},从这里继续还是重新开始?"
  - 用户选"继续" → 从记录的轮次+概念恢复,跳过已完成的轮次
  - 用户选"重新" → 清除进度记录,从第1轮开始
- 无记录 → 正常走5问流程
- ⛔DO NOT:在有进度记录时直接走5问而不提示--原因是用户可能想断点续学

用户选完后,写进 references/task-standards.json。存储规则:同一任务类型只保留最新一条标准,覆盖旧配置。
