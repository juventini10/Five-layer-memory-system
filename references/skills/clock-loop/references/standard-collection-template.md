## 5问

```
① 你想怎么用这个Loop？（A-F单选，说字母或名称）
   A. 审核这个内容 —— 看质量、找问题、挑毛病
   B. 基于这个生成新的 —— 改写、扩写、翻译、创作
   C. 分析里面的数据 —— 找规律、出洞察、交叉验证
   D. 修复/改进 —— 修bug、改问题、优化、调整
   E. 评估这个Skill —— 全面打分、出评估报告
   F. 学习这个领域 —— 从零搞懂、验证掌握度
   F. 其他 —— 我来描述

② 检查清单（硬性门禁——自查逐项核对，全过才算自查通过）：

   【审核文案】
   □ 广告法合规（扫全文无"治愈""第一""最好"等违禁词）
   □ 产品信息准确（跟产品资料库逐字段比对）

   【生成文档】
   □ 章节完整性（对照大纲逐章确认）
   □ 格式规范（排版/标点/结构一致）

   【分析数据】
   □ 字段完整性（空值/缺失检查）
   □ 异常值检测（离群值/不合理值）

   【修复代码】
   □ 代码质量（lint通过+核心测试通过）
   □ 安全审查（注入/XSS/权限）

   【评估Skill】⚠️ 完整6维度35子项——用户确认后全部进入评估引擎
   ┌─ A. 开发规范符合度（8项，来源：Skill架构规范v5.7）
   │  □ A1. YAML元数据完整（name/description/version/compatibility/allowed-tools/author/source/version/license 共9个✅DO字段）
   │  □ A2. trigger词与description声明一致
   │  □ A3. 步骤间逻辑连贯（产出物锁覆盖每步）
   │  □ A4. 错误处理机制（熔断器+降级方案）
   │  □ A5. 四层契约完整（输入/输出/行为/演化）
   │  □ A6. Poka-Yoke三法齐全（接触法+定值法+步序法）
   │  □ A7. 无反模式命中（D1-D5设计/E1-E4执行/S1-S3安全）
   │  □ A8. 有Alternatives Considered段
   │
   ├─ B. 指令准确性（5项，来源：指令编写规范v3.6）
   │  □ B1. trigger词无歧义（精确匹配，非模糊包含）
   │  □ B2. 五级标注完整（✅DO/☑SHOULD/MAY/⚠SHOULD NOT/⛔DO NOT），无旧版NEVER/CRITICAL/MUST残留
   │  □ B3. 每条禁令附因果链（"不能X——原因是Y"）
   │  □ B4. 禁令+正面双轨完整（不只给否定，也描述"做对了什么样"）
   │  □ B5. 语义完整，不依赖上下文推断
   │
   ├─ C. 逻辑一致性（4项，来源：Skill架构规范+指令编写规范）
   │  □ C1. 步骤流程无断点（每步产出物是下步输入，含步骤编号连续性）
   │  □ C2. 条件分支覆盖完整（含正常+异常路径）
   │  □ C3. 输入输出定义清晰
   │  □ C4. 无内部矛盾（跨文件路径一致+字段数/编号/版本号一致+SECTION/模块计数一致）
   │
   ├─ D. 文档完整性（4项，来源：Skill架构规范v5.7）
   │  □ D1. references/CHANGELOG.md存在且非空
   │  □ D2. 无README.md（规范禁止）
   │  □ D3. 使用示例可运行
   │  □ D4. 依赖说明清晰（dependencies字段声明实际依赖）
   │
   ├─ E. 测试覆盖（3项，来源：指令编写规范v3.6）
   │  □ E1. 评估集存在（≥5条测试用例）
   │  □ E2. 应触发/不应触发/运行时行为三类覆盖
   │  □ E3. 边界条件覆盖
   │
   └─ F. 哲学评估（7项，来源：迁理之外v3.2.1 七项哲学检查）
      □ F1. 价值对齐：设计是否与用户价值观一致（有明确的用户价值声明+不损害用户利益）
      □ F2. 认知边界：是否清楚自身局限（有熔断器/降级方案/不确定性标注）
      □ F3. 语境理解：是否理解隐喻、语境和情感表达（trigger词考虑了语境区分）
      □ F4. 边界伦理：哪些事情是它明确不该做的（有禁止行为表+可逆性分级🟢🟡🔴）
      □ F5. 反思能力：能否对自己进行评估和修正（有反疲劳/卡死检测/自查机制）
      □ F6. 偏见觉察：是否意识到认知偏差（有Goodhart Law防御/引导偏差防御）
      □ F7. 意义完整性："为什么做"是否和"怎么做"一样清晰（有Goals/Non-Goals声明）

   【学习新领域】≤5轮，逐轮确认后再进下一轮
   第1轮 - 搭骨架
     ✅DO — AI根据用户主题查资料，输出3-5个核心概念+关系框架。
     用户确认方向对不对，方向偏了重置本轮。
     □ 知识骨架已建立 —— 能用3句话说清这个领域是干什么的

   第2轮 - 理边界
     ✅DO — AI列出该领域的主要观点派别、争议问题和未定论地带。
     用户评估："这个深度够吗？"不够→AI继续深入。
     □ 共识与分歧已分清 —— 知道哪些是定论、哪些还在吵

   第3轮 - 测盲区
     ✅DO — AI生成5-10道区分性测试题（能挖出真懂和假背的区别）。
     用户逐题作答，答错追问根源（为什么错、遗漏了什么概念）。
     □ 盲区已暴露 —— 发现了至少2个原来不懂的点

   第4轮 - 针对性补
     ✅DO — 针对第3轮暴露的盲区，AI集中查资料补齐，用户重新答错题。
     □ 漏洞已补上 —— 之前答错的题能重新通过了

   第5轮 - 费曼验证（可选路径A）
     【转场引导】→ "盲区已补完，接下来验证你能不能讲清楚——用自己的话复述核心内容，我来检查有没有跳跃或含糊的地方。"
     ✅DO — 用户用自己的话讲一遍核心内容，AI判断有无逻辑跳跃或含糊处。
     有卡壳 → 回到第1轮对应概念重新搭。
     □ 可复述通过 —— 能讲给外行听，不卡壳

   第5轮（替代路径B）- 寓言理解（用户说"用故事教我"时触发）
     【转场引导】→ "盲区已补完，换个方式验证——我用一个寓言故事测你，看你能不能听出背后的概念。"
     ✅DO — AI选一个核心概念，编寓言故事。⛔DO NOT在故事结束前揭示概念名。
     故事停 → 问用户："你觉得这个故事在说什么？"
     用户回答：
       ├─ 答对 → 进入隐喻映射
       └─ 答错 →
            第1次纠错：AI指出误解位置+给思考脚手架，⛔DO NOT揭示答案
            返回重新问→用户重新推导
               ├─ 答对 → 进入隐喻映射
               └─ 再次答错 →
                    第2次纠错：AI低格一次——给出更直接的提示后返回重问
                       ├─ 答对 → 进入隐喻映射
                       └─ 连续2次推导失败 → AI揭示概念名+解释为什么故事没帮到你
     ✅DO — 隐喻映射（概念揭示后执行，⛔DO NOT判对错）：
       AI说出自己的映射解读 → 用户说出自己的映射 → 两者对比
       用户能自洽说清"故事里{某元素}对应概念{某部分}"即通过
       ——原因是：隐喻没有标答，对撞比纠正更能帮用户建立认知深度。
     □ 寓言理解通过 —— 能自洽说清故事元素对应概念部分
     ✅DO — 寓言通过后，问用户"再用寓言学一个概念，还是继续其他轮次？"
       ├─ 再学一个 → 回到第1步重新选概念
       └─ 继续其他轮次 → 回到正常进度
     当用户说"够了""今天就到这"时 → 🛑 本轮终止，交付进度（已学概念+掌握度），保存

   ✅DO — AI在学习类任务中可使用WebSearch/WebFetch自主查资料补充知识骨架和出题。
   ⛔DO NOT让AI边学边自己编造知识点——每轮输出的核心事实必须可回溯到联网查询的真实资料。

   【自定义】
   □ 我自定义：[一句话描述检查内容和通过标准]

③ 审查严格度（你想多严格）：
   A. 吹毛求疵 —— 对标最高标准，小问题也揪出来
   B. 平衡 —— 主要问题搞定就行，不过于纠结细节

④ 你估计几轮能搞定？
   A. 1轮（快速过一遍）  B. 2轮（先做再修）  C. 3轮（默认，比较稳）  D. 5轮（深度迭代）  E. 我来说几轮

⑤ 成功标准（可选，填了之后会更准）：
   □ 没发现问题就是通过（只看负面约束）
   □ 能达到以下正面标准：[你写，如"读完后能一句话说出产品核心卖点"]
```

## 📋 框架方法论声明（不占检查清单，始终生效）

> 以下机制是clock-loop评估引擎的内建能力，不需要用户确认，每次评估自动执行。
> 向用户展示标准时，附带此声明让用户知道评估不只看清单，还有方法论加持。

| 机制 | 来源 | 做什么 | 何时执行 |
|------|------|--------|---------|
| L1第一性原理拆解 | 三明智v3.3.1 | 评分前四问拆解（核心功能/依赖/输出/核心矛盾） | 每次评估，评分前 |
| L2批判验证自检 | 三明智v3.3.1 | 评分后四项自检（锚点对立面/证据链/假设验证/结论块门禁锁） | 每次评估，评分后 |
| 五大哲学视角匹配 | 迁理之外v3.2.1 | 根据对象特征匹配主视角（斯多葛/存在主义/实用主义/分析哲学/唯物辩证法） | 对象类型为skill时 |
| 版本同步验证 | evaluation-framework.md | 4个固化引用文件与源规范版本号对比 | 阶段1.5知识网络构建时 |
| L3跨周期沉淀 | 三明智v3.3.1 | 从≥5次评估中提取模式 | 累计≥5次评估后 |
