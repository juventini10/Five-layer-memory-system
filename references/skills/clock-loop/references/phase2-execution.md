### 阶段2:循环执行(闭环核心)

📦 产出物:progress.md + 本轮产出 + 多维评分表

> **📋 progress.md**:每次Loop运行时自动创建,记录每一轮做了什么、子Agent发现了哪些问题、本轮修正了哪些。存储路径:`~/[记忆共享中心]/评估知识库/test_results/{对象类型}_tests/progress_{对象名}_{YYYY-MM-DD}.md`。评估完成后自动归档为评估报告(同目录),progress.md不残留在Skill目录。模板见 `references/progress-template.md`。

循环结构如下--每一轮自动执行,你全程不在场。每轮迭代的边界是:**子Agent给出审查结果**。

```
【第N轮】从执行开始,到子Agent给出审查结论结束

  │
  ├─ 1 读进度记录
  │    读取 progress.md(第一轮不存在则跳过)
  │    对上轮反馈的问题逐条确认,防止遗漏
  │
  ├─ 2 执行本轮工作
  │    ├─ 第1轮:按你给的标准从头做
  │    └─ 第N轮(N>1):基于上轮子Agent的反馈修正
 │        修正前先备份本次要改的文件清单逐一 `cp {文件} ~/[记忆共享中心]/记忆琥珀/技能升级备份/{文件名}_{YYMMDD_HHMM}.bak`——原因是修改不可逆备份是安全网;仅只读评估可跳
 │        如果触发过"策略切换"(反疲劳标志位=ON):换方法修
  │
  ├─ 3 自查:多维度专业评分(v2.0升级)
  │    Read references/evaluation-framework.md → 执行以下流程:
  │
  │    a) L0 结构画像(防回声,v2.1.2新增)
  │       触发条件:当前Session中已评估≥1个对象时必做
  │       目的:打断"上次修的=这次也要修"模板套用惯性
  │       三问(3秒,不深究):
  │       - 这个对象最独特的设计是什么?(一句话)
  │       - 它和上一个评估对象结构上最大的不同是什么?
  │       - 上一个对象修过的问题 → 哪些不适用于本次对象?
  │       → 输出L0防回声清单(适用于/不适用于),指导后续打分避免假阳性
  │
  │    b) L1拆解(评分前必做,Read references/triwich-integration.md L1段)
  │       核心功能是什么?依赖什么?输出什么?核心矛盾是什么?
  │       → 拆解结果写入评分表前言
  │
  │    c) 逐维度评分
  │       对每个维度:读取check_items → 逐项核对产出物 → 标注✅/❌/⚠️ → 维度得分=通过/总数
  │       维度来源:阶段1.5加载的patterns文件
  │
  │    d) 加权汇总
  │       总分 = Σ(维度得分 × 权重)
  │       权重来源:阶段1.5加载的weights文件
  │
  │    d2) 评分纪律·只信实际输出(2026-08-10 反哺·报告虚假完成记录盲区)
  │       评分依据只信实际运行输出+磁盘事实,⛔DO NOT信任被评文件自称的"已验证/已交付/已注册"
  │       ——声称类语句须有运行或磁盘证据才计分(CHANGELOG 声称已交付守卫脚本但磁盘不存在=不得计分)
  │       可运行性/卡死类结论须实跑或标"静态推演(未实跑)",未实跑不得与实跑同权(报告断言L1卡死被实跑证伪)
  │
  │    e) 哲学评估嵌入(对象类型为skill时,Read references/philosophical-evaluation.md)
  │       Read references/philosophical-evaluation.md → 七项哲学检查逐项评分
  │       v2.1.2新增规则：检查项先找显式声明→无则查功能层等价级联锁/人在回路/定值法=功能层实装
  │       v2.2.0新增规则：哲学评估总分≥85%→判定"哲学及格"，该维度按10%权重满分计入；<85%→判定"哲学不及格"，该维度按10%权重零分计入。不再逐项加分，消除虚假区分度。
      │
  │    f) L2自检(评分后必做,五问内联·细则见 references/triwich-integration.md L2段)
  │       锚点对立面?证据链完整(逐项带行号)?假设验证?结论块门禁锁?
  │       ⑤自爆判据(内联·v3.34.0):评分结论全正面 → 强制复检≥2条非正面发现;复检后仍全正面 → 签名标❌
  │       产出物:自爆复检表(触发时=非正面发现清单≥2条;未触发=声明"结论含非正面项,未触发自爆"——⛔DO NOT两者都不写)
  │
  │    评分门禁(固定值):
  │    ├─ ≥85% → ✅通过 → 强制进入4(子Agent审查),不可跳过
  │    ├─ 70-84% → 🟡部分通过 → 备份目标文件 → 修正→重评(内部循环,不占外部轮次)
  │    └─ <70% → ❌不通过 → 备份目标文件 → 修正→重评(内部循环,不占外部轮次)——v3.32.0由"记录→跳子Agent审查"改为与70-84%同路径：先修再评，修不动才跳审查（你拍板轮次内修复迭代）
  │
  │    ⛔DO NOT将自查≥85%视为可交付--自查通过≠交付条件,4审查通过才是。跳过4直接进入阶段3交付=步骤缺失=交付无效。
  │
  │    评分门禁后✅DO过完整性兜底清单(2026-08-10 反哺·C1):Read references/completeness.md
  │    按被评估Skill类别逐项核对评估器未点名项——评估器没点名的也必须过一遍,不许跳过
  │    (报告实证:分项结构错/护栏死/残留假过全是评估器没点名的)
  │
  │    内部循环最多3次(固定值--防自查死循环消耗Token)
  │    → 仍不过 → 实情记录 → 跳子Agent审查
  │
  ├─ 4 审查(子Agent可用时spawn,不可用时自检替代)
  │    v2.2.0新增：子Agent审查前必须执行L0防回声（与③a相同的L0三问），确保审查者不从自评者的判断框架出发
  │    **v3.17.0独立性协议**：spawn前✅DO Read `references/review-protocol.md`——⛔DO NOT向审查Agent传结论系信息(自评分数/自评结论块/修复宣称/上轮通过判定·按信息性质判定不按字段名)——原因是审查者见自评结论=锚定效应=独立性失效(双盲弱点①)；finding系(标准/清单/严格度/对象/上轮问题清单)可传。NoAgent降级时隔离条款失效,如实记录"隔离条款不适用"
  │    子Agent指令:
  │      "你是一个独立的审查Agent,只读不可修改。
  │       **首先执行L0防回声**：与③a同源三问(独特设计/结构差异/易误判项不适用清单)——以审查者视角独立作答,非复读自评者答案
  │       **然后按以下标准审查**[任务类型]的产出:
  │       严格度:[用户选的] | 检查清单:[用户选的] | 成功标准:[用户第5问]
  │       找茬视角:假设这个产出要发布,你会找出什么问题?
  │       审查结果格式:通过/不通过 + 问题候选清单(每条含证据+不确定性+初判严重度)
  │       **报告结尾强制负向声明**：'⛔本证据不能支持的结论'清单≥1条(写具体边界,⛔空泛凑数)
  │       **回声效应自检**：审查完毕后,按 review-protocol.md §六 的7种回声模式逐条标注是否命中(细则单一来源在协议·v3.27.1外置)"
  │    ├─ **lead裁决(v3.17.0·审查返回后)**：交叉比对(自评发现vs独立候选的差集显式列出)→逐候选定最终严重度+七态处置(采纳/合并[四同判据缺一不可]/降级/证据不支持/挂起/路由-悬置区/路由-交接待办·定义见review-protocol.md§四)→写入progress.md候选处置台账。⛔DO NOT丢弃候选无处置记录——原因是报告在案≠会被记起(QD-016)
  │    ├─ 审查通过（含回声自检无命中或命中已标注） → 本轮达标,准备终止交付
  │    └─ 审查不通过 → 分析反馈 → 记录进下一步
  │        ⚠️ 审查不通过后修正的产出必须进入下一轮重新审查
  │        ⚠️ 回声命中≥3条 → 标记本次审查为低置信度，要求重审
  │
  ├─ 5 反疲劳判定
  │    ├─ 首次不过 → 正常修正策略 → 反疲劳标志位=OFF
  │    └─ 同一问题连续两次不过 → 策略切换(换方法修)→ 反疲劳标志位=ON
  │
  ├─ 6 写入执行日志 → progress.md
  │    ├─ 本轮做了什么
  │    ├─ 多维评分表(v2.0:替换原"自查通过/未通过"为完整评分表)
  │    ├─ 子Agent发现了哪些问题
  │    ├─ 候选处置台账(v3.17.0:每条候选的七态处置+一句理由)
  │    ├─ 本次修正了哪些
  │    └─ 反疲劳标志位状态 + 本轮进步置信度
  │
  └─ 7 🧠 思考检查点(每轮终结点)
        本轮Token预估消耗 | 子Agent反馈质量评估 | 反疲劳触发状态 | 预算可控?
```

**卡死判定标准(子Agent反馈为主要依据):**
> 任务类型 A-H 枚举唯一真相源见 `references/taxonomy-map.md` §三——⛔此处判定条件是物理功能（保留），枚举定义不另存副本。

| 任务类型 | 判卡死条件（v3.19.0量化·双盲C2） |
|---------|-----------|
| 审核文案 | 本轮修正条目≤1条 且 子Agent问题数降幅=0 |
| 生成文档 | 新增/修改<50字 且 未通过检查项数不变 |
| 分析数据 | 结论变更=0项 且 质量分提升<2% |
| 修复代码 | diff<5行 且 问题数降幅=0 |
| 评估Skill | 评分提升<2% 且 子Agent发现同类问题 |
| 检查发布包(G) | pkg_report_check.py 连续两轮 exit 1 且 FAIL 项数不变（2026-09-05批6f补＝#200⑤任务类型4文件数量统一：4/5/7/8→8类A-H） |
| 知识库体检(H) | kb_concept_lint.py 连续两轮退出码相同 且 矛盾清单零新增（同上） |
| 学习领域(F) | 暂无量化判据——以子Agent反馈兜底（下方通用规则·学习路径产出无天然可量化指标·如实标注） |

> 若无法可靠量化--以子Agent反馈为唯一卡死依据:**子Agent连续两轮说"跟上一轮没差别"即判卡死。**

### 🧠 局部死循环自救（2026-08-20 你定·第一性原理）

> **触发**：同一调试路径连续 3 次以上无新信息/无进展，或单轮思考链超过 10 分钟仍未闭环。

**✅DO — 退一步抽象建模**：
1. 停止当前局部测试，回到全局视角重新问："Win FAIL 的根因链条是什么？"而非"这个文件为什么空"
2. 用第一性原理列出**所有可能根因**（路径/编码/环境/变量），按证据强度排序
3. 找**最快能判定或排除**的根因优先验证（如直接看 workflow 日志而非在 Mac 复现）

**⛔DO NOT**：在 Mac 上反复构造沙箱复现 Win 真机的行为差异——Win 真机暴露的问题应在 Win 真机定位（workflow 加调试输出），Mac 宽容度不同会漏掉编码/解析差异。

**来源**：Hermes 加强包 v0.1.2 发布包闭环，config 注入 bug 在 Mac 反复测试空文件无果，你提醒"先冷静跳出来用第一性原理分析"——根因是 workflow `$exit` 变量被 GHA 预展开，应在 Win 真机加调试输出定位而非 Mac 复现。

🔌 熔断器（自查内部循环）
├─ 成功条件：多维评分总分≥85% 且 L2自检通过
├─ 失败处理：重试
├─ 可修正参数：评分阈值(≥85%)与L2自检项 → 检查评分维度是否齐全、L2锚点对立面/证据链是否填妥
├─ 重试次数：3（内部循环上限，防死循环消耗Token）
└─ 降级方案：评分未达标→修正→重试(内部循环最多3次)。3次后仍未达标→实情记录→跳阶段4子Agent审查

🔌 熔断器（审查环节）
├─ 成功条件：子Agent返回"通过"
├─ 失败处理：重试
├─ 可修正参数：子Agent审查指令 → 检查L0防回声三问已注入、审查标准与用户选择一致
├─ 重试次数：1（重跑审查，非重做产出）
└─ 降级方案：子Agent返回"不通过"+问题清单→分析问题后修正。轮次用尽→**询问你是否延长轮次继续修**（v3.32.0·皮叔拍板轮次内修复迭代）；你拒绝→跳阶段3超限终止，交付当前版本+未通过项

🔌 熔断器（子Agent spawn失败）
├─ 成功条件：子Agent正常返回审查结果
├─ 失败处理：降级
├─ 可修正参数：子Agent spawn参数 → 检查模型/超时配置、指令长度是否超限
├─ 重试次数：1
└─ 降级方案：1次重试后仍失败→✅DO先切 CreateWorkflow（subagent_model=ListModels异质模型·其运行时对provider侧错误无限重试·抗captcha抖动/网络瞬断）→workflow亦不可用（如单agent长卡死→AmendWorkflow止损）→才降级为自检+自查清单核对，如实记录"子Agent未启动·切workflow亦失败,改用自检"
- 外显信号:触发降级时输出 `⚠️ 熔断器触发:子Agent spawn失败/超时 → 降级链:切workflow异质模型 → 不可用则自检替代,如实记录`
- 降级链依据（v4.12.13·2026-09-27）：Z.ai服务端captcha实例超时实证——spawn路径10s即死（retryable=false）·主对话11次重试扛住·workflow运行时无限重试扛住，单点spawn是最脆路径；审查独立性是Loop命门，降级到自检=独立性归零，切workflow可保独立性
