# system-logger · 月度系统蒸馏工作流（详细步骤）

> 渐进披露：仅当触发「系统月报 / 月度系统蒸馏」时按需 Read。
> 主文件：`../SKILL.md`

## 月度系统蒸馏工作流（Trigger: "系统月报" / "月度系统蒸馏"）

> 每月初（次月1号）运行一次，或用户主动触发时运行。从上月系统日志中提取**数据→模式→洞察→建议**四层递进分析。

### 蒸馏步骤（5步）

#### 步骤 D1：定位上月日志文件

📦 **产出物**：定位到的上月日志文件列表（绝对路径）

🔌 **熔断器**
├─ 成功条件：Glob返回至少1个匹配的日志文件
├─ 失败处理：中止
├─ 可修正参数：日志文件路径模式 → 检查 ~/[记忆共享中心]/工作日志/系统日志/ 目录是否存在
├─ 重试次数：1
└─ 降级方案：⚠️ "上月无系统日志文件，无法执行蒸馏"，中止流程不继续D2

**写入前Read确认（前置防误）**：
- ✅DO：定位文件后必须 Read 每个文件全文确认内容非空——空文件=物理阻断，中止流程。
- ✅DO：Read 返回的内容记录为蒸馏的原始数据源，后续D2-D4写入时以此为基准。
- ⛔DO NOT：跳过 Read 直接进入 D2 分析——原因是无数据源=分析是空中楼阁。
- 来源：v3.6.1 月度蒸馏防御对齐——与日写入步骤2.5同级Poka-Yoke防覆盖。

```bash
date -v-1m "+%Y-%m"  # macOS：获取上个月YYYY-MM
```

目标文件范围：`~/[记忆共享中心]/工作日志/系统日志/系统日志_{上个月}-*.md`

#### 步骤 D2：结论导向分析

📦 **产出物**：数据层统计 + 模式层发现 + 洞察提炼 + 行动建议（四层递进输出）

> 不是"先堆数据再找结论"，是"先问自己要验证什么，再去看数据"。
> 
> 三问定方向：
> 1. 这个月节奏健康吗？（比前月/基线，任务密度和方向是否一致）
> 2. 有什么反常？（异常点、趋势转折、跨工具/跨文件模式）
> 3. 下个月该停什么、启动什么、继续什么？（行动建议）

读取上个月所有日志文件，围绕上述三问提取：

##### 数据层（支撑结论的基础）

| 维度 | 提取方式 |
|------|---------|
| **总任务数** | 统计所有`### [标题]`条目（排除辅助条目如"格式完整性校验"） |
| **按工具分布** | 提取每条`- **工具**`字段 |
| **按类型分布** | 提取每条`- **类型**`字段，归类聚合 |
| **按周分布** | 按周统计任务数，看波动 |
| **对比上个月** | 如有上月蒸馏记录，读取并对比：总量变化(±N/±%)+一句话定性变化 | 首次基线月标注"无上月数据" |

##### 模式层（支撑结论的发现）

```
🔍 异常检测：找基线偏离——某天任务数翻倍或骤降、某类操作占比异常高、某周空窗
📈 趋势检测：上半月vs下半月对比——任务密度升/降、修改vs创建占比变化
🔗 关联分析：跨文件/跨工具协同——某文件反复修改、工具A→B→A的序列模式
```

> 三个方向按以下维度审视数据，无有价值发现时标注"无显著模式"。

##### 第三层：洞察提炼

```
🟢 好态势 / 🟡 混合态势 / 🔴 问题态势
[一句核心判断，纯数据驱动]
```

##### 第四层：行动建议

输出1-2条对下个月最直接的行动建议。**与每日伙伴的伙伴建议不重复**——每日伙伴建议个人效率，系统日志建议工作节奏和方向选择。

##### 🪞 成就证据提取（"最伟大的我"联动）

> 系统日志记"让AI做了什么工作"=人的工作成就。日记不会记这些，系统日志是成就证据的独立主数据源。

从本月日志中提取工作成就，写入 `~/[记忆共享中心]/最伟大的我/成就证据/`：

1. **筛选**：扫描所有任务条目，排除纯维护性操作（如版本号对齐、格式修正），保留有实质产出的条目
2. **视角转换**："AI做了什么" → "我决策并推动完成了什么"——每个日志条目背后都是人的决策
3. **补充字段**：日志只有"做了什么"，需补充"为什么能做成"+"反事实分析"（从日记/周报交叉验证）
4. **写入**：按 `成就证据/_模板.md` 格式写入 `~/[记忆共享中心]/最伟大的我/成就证据/{YYYY-MM-DD}-{事件简称}.md`
   - ⚠️ 文件须含 YAML frontmatter（格式见 `最伟大的我/文件格式约定.md` §3.2）

🔌 **熔断器**：成功=写入至少1条成就证据 | 失败=标注"⚠️本月无显著工作成就" | 不阻塞蒸馏流程

#### 步骤 D2.5：工作模式信号提取（每日伙伴联动 · 可观测信号）

> **定位**：从本月系统日志提取「工作模式信号」——只陈述日志里**可观测发生了什么**，不推断"你是什么样的人"。
> 对你的认知/评估由 daily-buddy 月报在其自有模块完成（见 daily-buddy 月报SOP「工作模式信号 PULL」步）——本步骤只产原材料，不越权评价。

**✅DO — 按以下固定 Schema 提取（每条信号 4 字段齐全）**：

| 信号 | 可观测证据 | 路由目标 | 关联维度 |
|------|-----------|---------|---------|
| 发布节奏突增/骤降 | 某周任务数 vs 全月基线 ±N%（如 W4 228条/占39%） | daily-buddy 模块5（系统建设·节奏） | 工作节奏 |
| 构建 vs 使用比 | 创建类占比 X% vs 修改类 Y%（全修改无创建→停留维护区） | daily-buddy 模块5 + 模块7（系统建设） | 创新 vs 维护 |
| 工具迁移轨迹 | 工具字段分布变化（如 Trae→QoderWork 占比转移） | daily-buddy 模块5（工具画像） | 工具生态 |
| 反复摩擦类型 | 某类操作/错误反复出现 N 次（如格式修正/路径问题） | SHADOW（回避模式）/ 伙伴建议 | 摩擦模式 |

**提取铁律**：
- ⛔DO NOT 推断你的性格/能力/态度——只写日志里可验证的事实（计数、占比、分布）。评估是 daily-buddy 月报的职责，不是本 Skill 的。
- ✅DO 每条信号带「路由目标」+「关联维度」——让下游消费方知道往哪并、并入哪个评估维度。
- ⛔DO NOT 编造信号——无显著模式时标注"本月无显著工作模式信号"。
- 与 🪞成就证据提取 去重：本步骤收"工作模式信号"，不重复写成就。

🔌 **熔断器**：成功=产出 ≥1 条信号表 或 明确标注"无" | 失败=标注"⚠️ 工作模式信号提取失败" | 不阻塞 D3/D4

#### 步骤 D2.6：忽略信号自查（黑匣子思维 · S1·v3.10.23 新增）

> **定位（防蒸馏变功劳簿）**：D2-D2.5 都在回答"这个月**抓到了**什么"，黑匣子思维要求再问一句——"这个月**漏掉了**什么"。只记录被看见的成果，蒸馏必然滑向功劳簿；主动找被忽略的信号，才是复盘真正的价值（吸收《罗辑思维·认知篇》卡片01-黑匣子思维）。
> **与愿景的关系**：本步骤是愿景④「越用越了解你」在系统层的盲区自查落点——系统不只记录高光，也承认自己没接住的东西。

📦 **产出物**：「这月哪些信号我忽略了」清单（≥1 条，或明确标注"本月无被忽略信号" + 一句核查依据）

**✅DO — 按以下三个方向自查（每问必答，无则写"无" + 一句依据）**：

| # | 自查方向 | 具体问法 | 典型被忽略信号 |
|:-:|---------|---------|--------------|
| ① | 出现但没追的信号 | 本月日志里出现过、但当时**没展开追查**的异常/苗头？（回看 D2「异常检测」里只写了"发现"没写"跟进"的项） | 某类错误首次出现、某工具任务数骤变、某文件反复修改 |
| ② | 承诺了但没闭环的事 | 本月条目里写了「待办 / 下轮 / 挂账 / PENDING」却没在后续日志里再见到的？ | 交接待办、待确认项、被新任务挤掉的旧承诺 |
| ③ | 该记却没记的空白 | 本月有实质工作但日志里**查无此条**？（对照 `git log` 提交 / 文件 mtime 抽查） | 跨端直写未过 `append_log_entry.py` 通道的条目、塌缩事故丢失的条目 |

**输出格式**（写入 D3 月度综览的「忽略信号」行）：

```markdown
### 🕳️ 忽略信号（YYYY-MM）
| # | 被忽略的信号 | 类别(①②③) | 当时为何没处理 | 现在是否仍需要处理 |
|---|------------|-----------|--------------|------------------|
| 1 | | | | |
```

**铁律**：
- ⛔DO NOT 把本段写成自我表扬或空话（如"本月工作充实、无遗漏"）——**无依据的"无"=根本没自查**。写"无"必须附一句核查依据（例："抽查本月 `git log` 5 条提交均已有对应日志条目"）。
- ✅DO 至少产出 1 条，或明确"无" + 核查依据。⛔DO NOT 留空。
- **与 D2.5 去重**：D2.5 收"抓到的模式"，D2.6 收"漏掉的信号"——方向相反，两者不重叠，⛔DO NOT 把同一条写进两边。
- **与悬置区分工**：本段只做**当月遗漏的复盘自查**；跨月未归因的毛坯归 `~/[记忆共享中心]/未知未知/悬置区.md`（由 daily-buddy 工作流C 3.9 捕获），⛔DO NOT 在此重复建仓（防第二本账）。
- 本段产出的"现在仍需要处理"= 是 的条目 → ✅DO 在下月首条日志中承接，形成"发现遗漏→补做"闭环（愿景②越用越好用）。

🔌 **熔断器**：成功=产出 ≥1 条 或 "无"+核查依据 | 失败=标注"⚠️ 忽略信号自查未完成" | **不阻塞** D3/D4，但 D3 综览须显式列出本段状态（不可静默跳过）

#### 步骤 D3：输出月度综览（结论先行）

📦 **产出物**：完整月度蒸馏报告写入独立文件 + 执行日日志写入摘要条目（含完整报告路径链接）

🔌 **熔断器**
├─ 成功条件：完整报告成功写入独立文件 + 执行日日志摘要条目写入成功
├─ 失败处理：降级
├─ 可修正参数：报告文件路径 → 检查 `~/[记忆共享中心]/工作日志/系统日志月度蒸馏/` 目录是否存在
├─ 重试次数：1
└─ 降级方案：对话输出月度综览但不写入文件，标注"⚠️ 综览写入失败，已对话输出"

**独立文件存储（v3.14.0新增·2026-09-02·根治月度蒸馏与日常日志混存）**：
- ✅DO — 完整月度蒸馏报告写入独立文件：`~/[记忆共享中心]/工作日志/系统日志月度蒸馏/系统日志月度蒸馏_YYYY-MM.md`
- ✅DO — 目录不存在时自动创建：`mkdir -p ~/[记忆共享中心]/工作日志/系统日志月度蒸馏/`
- ✅DO — 文件已存在时（补生成/重生成场景），先Read确认内容，再用Write覆盖（完整报告是整体文件，非追加场景）
- ⛔DO NOT — 把完整月度综览块写入执行日日志的结论字段——原因是完整报告与日常日志混存会导致执行日日志膨胀、月度蒸馏查阅困难
- 设计哲学：日常日志记"做了什么"，月度蒸馏报告记"一个月的分析结论"，两者分离存储、各司其职

**执行日日志摘要条目（v3.14.0新增）**：
- ✅DO — 执行日日志只写摘要条目（类型=分析），结论字段包含：一句话态势判断 + 核心数据（任务数/对比上月/关键发现） + 完整报告路径链接
- ✅DO — 摘要条目的结论字段格式：
  ```
  完成 YYYY-MM 系统日志月度蒸馏。[一句话态势判断]。[核心数据：N条任务(±X% vs 上月)，关键发现1，关键发现2]。
  > 📄 完整月度蒸馏报告：`~/[记忆共享中心]/工作日志/系统日志月度蒸馏/系统日志月度蒸馏_YYYY-MM.md`
  ```
- ✅DO — 追加姿势遵循「组头唯一性规则」（追加前 tail -5 确认末尾组归属），走 `append_log_entry.py` 委托通道
- ⛔DO NOT — 在执行日日志里重复完整报告的全部内容——摘要+链接即可，完整报告在独立文件里

**追加姿势（v3.10.1 对齐 SKILL.md 整体读回写禁令作用域）**：
- ✅DO：执行日日志摘要条目走 `append_log_entry.py` 委托（`cat >>` 物理追加），组头遵循「组头唯一性规则」。
- ✅DO：写前可 Read 文件尾部确认组上下文，⛔DO NOT「Read 全文→拼全文→整体 Write 回写」。
- ⛔DO NOT：整体读回写写执行日日志——原因是该禁令覆盖一切系统日志写入路径（v3.10.1 作用域显式化）。
- 来源：TE-20260702-001 同类风险由追加姿势 + 写前门禁（systemlog_gate_check.py）双防承接（替代整体拼回）。
