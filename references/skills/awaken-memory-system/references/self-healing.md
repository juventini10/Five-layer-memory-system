## §1 全量版本门禁体系（dual-mode.md 全量步骤1 引用）

### §1.1 版本门禁（1c）

🔌 熔断器（关键）
├─ 成功条件：`python3 ~/[记忆共享中心]/技能配置/awaken-memory-system/scripts/awaken_version_gate_check.py` 返回 exit 0
├─ 失败处理：中止
├─ 可修正参数：SKILL.md路径 → 检查权威源 `~/[记忆共享中心]/技能配置/awaken-memory-system/SKILL.md` 是否存在（脚本 AUTHORITY 即此路径·审查P3-6修正）
├─ 重试次数：0
└─ 降级方案：无——中止全量模式并报告

✅DO — 运行 `python3 ~/[记忆共享中心]/技能配置/awaken-memory-system/scripts/awaken_version_gate_check.py`（v7.22 脚本闸门·双查合一·绝对路径调用——cwd 无关）
- **调用预检**：运行前 `ls` 确认脚本文件存在；脚本文件不存在时 python 解释器也会 exit 2（与"缓存不一致"语义碰撞·审查P1-1）——故 exit 2 判定前必须先确认脚本自身可达，不可达按 exit 1 降级处理
- exit 0 = 版本门禁过（权威源可达 + 真实独立副本全部一致）+ 规则.mdc 无过期
  - ⚠️ 脚本按 realpath 去重：与权威源同 inode 的软链路径记为「软链同源」而非验证样本。1e 自愈后各平台通常全为软链 → 独立副本为 0，此时本项**只等价于权威源可达性**，脚本会明确声明"不构成跨平台一致性验证"（v7.25 修 D① 可比对性）
- exit 1 = 通用错误（权威源不存在/版本提取失败）→ 检查路径与 frontmatter
- exit 2 = 缓存版本不一致 → 备份旧版到记忆琥珀 → 读权威源覆盖缓存 → **从步骤1重新执行**
- exit 3 = 规则.mdc 过期 → 在报告输出中标注"规则文件过期"（不阻塞）

> **覆盖方向与覆盖范围声明（v7.28·v7.33扩五端）**：本门禁覆盖方向=权威源→缓存**单向自动覆盖**（exit 2→备份→覆盖→重来）；"覆盖权威源"无流程入口（禁止行为#3 防御的是该幻影动作被 AI 自行发明——缓存旧≠权威源错）。缓存探测覆盖=脚本 CACHE_PATHS 五端（.qoder/.qoder-cn/.workbuddy/.trae-cn/.zcode）；compatibility 其余端无本地缓存目录设计，漂移风险=不适用（随端注册扩展）。

### §1.3 软链接自愈（1e） `[Poka-Yoke防误层]` Fail-Fast后自愈——断链自动重建，不依赖用户介入。

📦 **产出物**：所有平台Skill缓存目录的软链接指向真实本地路径
🔌 熔断器
├─ 成功条件：脚本退出码 == 0
├─ 失败处理：降级（报告失败信息，不阻塞后续步骤）
├─ 可修正参数：脚本路径 → 检查 restore-my-skills.sh 是否存在
├─ 重试次数：0
└─ 降级方案：报告失败信息，不阻塞后续步骤

**为什么需要这一步**：历史上出现过软链接指向沙箱临时路径（`/sessions/{id}/workspace/...`）导致会话结束就断的问题。`深度模式`软链接指向已废弃目录也属于同类问题。

**执行命令**（按运行平台选择）：

```bash
# macOS / Linux
bash ~/[记忆共享中心]/技能配置/restore-my-skills.sh
```

```powershell
# Windows (PowerShell · 默认用 Junction，普通用户无需开发者模式/管理员)
.\restore-my-skills.ps1
```

> 📌 跨平台说明：软链接自愈已拆分为 macOS/Linux 版（`.sh`）与 Windows 版（`.ps1`）两份对称实现，参数策略一致——默认从脚本所在目录动态推导权威源，不绑定特定用户路径。Windows 用户必须走 `.ps1`（`.sh` 在 Windows 因路径含用户专属段与 `ln -s` 命令不兼容，无法运行），反之亦然。

**升级点（v7.3.1）**：
- 自动清理已知死链接（`深度模式`目录已迁移到`三明智`）
- 自动检测并修复沙箱路径软链接
- 幂等：每次执行结果一致，不会重复创建

**失败处理**：脚本返回非0 → 报告失败信息→ 不阻塞后续步骤（Skill可读但可能受限）

### §1.4 规则.mdc版本一致性检查（1f）

📦 **产出物**：`.workbuddy/rules/*.mdc` 版本号与权威源对比结果
🔌 熔断器
├─ 成功条件：匹配文件版本与权威源一致
├─ 失败处理：告警
├─ 可修正参数：—
├─ 重试次数：0
└─ 降级方案：标注🔴告警，不阻塞后续流程

**为什么需要这一步**：`.workbuddy/rules/` 下的 `.mdc` 文件设置了 `alwaysApply: true`，每次会话自动注入。如果内容过期（旧版铁律/旧格式模板），会与当前规则文件打架且AI不自知。2026-06-15发现了 `用户基本规则.mdc` 在v5.0.0停留22天未同步。

**执行方式**：`python3 ~/[记忆共享中心]/技能配置/awaken-memory-system/scripts/awaken_version_gate_check.py`（绝对路径·cwd无关·v7.22 脚本闸门·exit 3=规则.mdc 过期，见 §1.1 退出码语义）：

| 状态 | 动作 |
|:---:|------|
| exit 0 | ✅ 健康，跳过 |
| exit 3 | 🟡 告警（非阻塞·2026-08-30标注语义对齐C11），在报告输出中标注"规则文件过期" |
| .mdc文件不存在 | 🟢 跳过（可能已迁移） |

**输出格式**（追加到全量报告末尾）：

```
🔍 规则.mdc健康检查
├─ 用户基本规则.mdc | v[实际版本] | [✅同步/🔴过期N天]
├─ [其他.mdc] | ...
└─ 结论：[✅全部同步/🔴N个过期]
```

## §2 TTL注册表同步检查（dual-mode.md 全量步骤2 引用）

🧠 **为什么需要这一步**：TTL注册表自v1.1（2026-06-16）起在长达37天内从未与真实文件源同步——全量唤醒只读不写，各文件实际更新日期与注册表记录渐行渐远。2026-07-23实测：6/7可审计条目的日期全部落后真实数据29-48天。不加同步=每次轻量快报都基于过时数据做判定，TTL注册表的"今距天数"始终不准（见 dual-mode.md 轻量步骤1 结论块门禁锁「依据可追溯」要求）。

✅DO Read TTL注册表.md，逐行比对"上次实质性更新"与对应文件header的实际更新日期。发现不一致→同步注册表并更新版本号（用 Write 或端内等价编辑方式）。输出同步统计到全量报告。**轻量模式不执行**——轻量只读不写（见禁止行为#5·唯一例外为 v7.32 懒加载快照脚本）。

⛔DO NOT同步超出TTL注册表已声明的行范围——原因是越界写入=污染注册表，破坏单表单一结构（§一1.1 Poka-Yoke定值法：数量固定不可增删行）。

| 比对行 | 核对方法 | 不一致处理 |
|--------|---------|---------|
| CORE.md | grep file header修订日期 | 同步（Write 或端内等价），更新TTL来源说明 |
| SHADOW.md | grep file header `date:` 字段 | 同上 |
| 动态状态快照 | grep file header「最后更新」 | 同上 |
| 铁律版/详解存档 | grep file header「更新日期」 | 同上 |
| SOUL.md | `同源`类型跳过日期比对 | 仅验证路径有效 |
| insight-report.md | mtime/frontmatter | 同上 |

📦 **产出物**：TTL注册表同步统计（同步N条 / 全部一致跳过）  
🔌 熔断器
├─ 成功条件：Read TTL注册表.md返回非空
├─ 失败处理：🟡降级——跳过同步，记录⚠️TTL注册表不可读
├─ 可修正参数：路径 → `${MEMORY_BASE_PATH}/记忆规则/TTL注册表.md`
├─ 重试次数：0
└─ 降级方案：跳过同步，在全量报告中标注⚠️

## §3 健康探针（dual-mode.md 轻量步骤3.5 / 全量步骤3a.5 共用）

### §3.5 健康探针批量读取（v7.35 合并·一次调用）

下列五项互不依赖，✅DO 合并为**同一次 Bash 调用**输出——⛔DO NOT 逐项拆成多次往返，原因是每次工具往返=一次模型等待，逐项读取会把小美从目标 3 轮拖成 6 轮（2026-09-10 实测 6轮/13次调用）。一次调用同时输出：①记忆琥珀心跳（macOS/Linux `/tmp/guard-heartbeat-memoryamber.txt`；Windows `${MEMORY_BASE_PATH}/记忆琥珀/engine/logs/amber-watch.heartbeat`）②mirror-sync 心跳（先探测 `[记忆共享中心]/脚本中心/`：不存在→`N/A（发布者工具·未安装）`）③`bash [记忆共享中心]/脚本中心/changelog_guard.sh --check` ④`${MEMORY_BASE_PATH}/记忆琥珀/engine/amber-status.txt` 的 `MESSAGE=` 行 ⑤`${MEMORY_BASE_PATH}/记忆蒸馏/蒸馏中心.md`。

**判定口径（沿用各自原标准·不新增）**：心跳 <90s ✅ / 90-180s 🟡 / >180s 或文件不存在 ⚠️守护未运行；changelog `candidates`>0 → 概览加一行「📋 变更日志：N 条 LIVE 变更疑未记（说"变更日志体检"可补）」；琥珀 `MESSAGE` 含⚠️ → 概览加一行「🟠 琥珀：[MESSAGE内容]」，仅「✅ 琥珀双轨正常」→ 轻量概览静默不输出（指令编写规范 §7.5 静默幂等：有结果才出声；全量模式按 dual-mode 3a.5 固定成行输出，v8.1.2·审查A6限定适用域）；蒸馏待办按 patrol.md §2 三级阈值判定，无待办→静默。

**安装包降级**：changelog_guard 是个人工具、mirror-sync 是发布者工具——安装包用户无此二者，`N/A` 是合法终态非告警（复用 system-logger 降级范式）；琥珀体检文件不存在 → 加一行「⚠️ 琥珀体检未运行」，不阻塞。

**⛔DO NOT 在 Windows 上探测 `/tmp/`**——原因是 Windows 无 /tmp，永远误报⚠️。仅读不写，不违轻量铁律（依据：记忆琥珀设计哲学 §4.10 常态审计须脚本触发不靠 prose；琥珀 v1.7 保底渠道=体检脚本写盘、本 Skill 读盘）。

> **蒸馏待办判定逻辑不在本模块**——单真源在 `patrol.md §2`（巡检模块·阶段③生长点）。

## §4 判断标准（通用判定语义总表）

| 状态 | 定义 | AI怎么做 |
|------|------|---------|
| 文件读取成功 | Read正常返回+内容已加载 | ✅DO标注版本+日期 |
| 文件读不到 | Read报错/路径错误 | 🔴 标注🔴+原因+按熔断器处理 |
| 版本门禁不通过 | 权威源≠缓存 | 🔴 备份旧版→权威源覆盖→从步骤1重来 |
| 三层版本不一致 | 铁律/摘要/详解版本号不同 | ☑SHOULD告警不阻塞 |
| 文件陈旧 | 更新日期>14天 | 🟡/🔴 标注天数 |
| 核心文件缺失 | CORE/架构/快照/SHADOW读不到 | ⛔DO NOT继续执行——按熔断器降级 |
