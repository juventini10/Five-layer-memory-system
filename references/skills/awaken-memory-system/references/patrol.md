## §1 懒加载快照更新（dual-mode.md 轻量步骤1.① 引用）

### 调用方式与预检

运行 `python3 ~/[记忆共享中心]/技能配置/awaken-memory-system/scripts/update_snapshot_from_diary.py`（绝对路径·cwd无关），检查 exit code：
- **调用预检**：运行前 `ls` 确认脚本文件存在——脚本不存在时 python 解释器同样 exit 2（与"无需更新"语义碰撞），不可达按 exit 1 降级处理

### exit 语义

- exit 0 = 已更新（当日行新增/更新 和/或 回填历史缺失日 和/或 本轮归档行>0，至少1项·v8.1.4与脚本同源）→ 继续
- exit 2 = 无需更新（无缺失可回填日 且 当日行一致 且 无归档行 且 无守卫告警；含"今日日记尚未生成"情形）→ 继续
- exit 1 = 失败（快照文件不存在/表格未找到/写入异常/--today非法/归档守卫跳过·v8.1.4审查F-1/F-3回写SSOT）→ 降级：标注「⚠️快照更新失败，数据可能滞后」，继续输出（不阻塞）

### 跳过留痕

脚本对未回填的日期逐条打印原因（今日骨架未生成 / 占位骨架 / 历史日未封口 / 日记不存在）——✅DO 在概览的「关键发现」中如实转述跳过项，⛔DO NOT 把"跳过"当"已覆盖"（有痕跳过≠静默跳过·Skill架构规范 §2.1 设计验证③）。

### 设计依据（v7.32 懒加载·v7.35 扩缺失日回填）

**设计依据**：童灵裁决（2026-09-02）——懒加载=awaken自己负责快照实时更新（原"daily-buddy封口时调用"属跨Skill耦合，被否决）。**v7.35 扩缺失日回填**：默认回看14天窗口，只回填**已封口**日记（未封口=数据未定，填入=脏数据）；骨架日记（未封口+tomato=0）一律跳过；跳过的日期 stdout 逐条留痕。⛔DO NOT 用"逐篇读日记手工补数据"替代回填——原因是把债读进上下文=token与时间双膨胀（2026-09-10 实测：快照滞后7天→AI手读6篇日记才补出情境，工具链 6轮/13次调用）。**诚实边界**：纯AI环境不存在"绝对物理杜绝"快照滞后——两次触发之间的窗口期仍可能滞后；脚本只动「最近变更摘要」表格，不触碰快照其他部分（安全·原子性）。

## §2 蒸馏待办检测（dual-mode.md 轻量步骤3.5.1 / 全量步骤3b 引用）

从 §1 懒加载后经 self-healing.md §3.5 批量读取的蒸馏中心内容 → 动态解析所有月度蒸馏类型的"预期下次"日期，三级阈值判定：

- **🔵 即将到期**（提前3天）：当前日期 ≥ 预期下次-3天 且 ≤ 预期下次（**今天到期归🔵**·v8.3.3收口审查#10）→ 做前提醒
- **🟡 已逾期**（1-7天）：当前日期 > 预期下次 且 ≤ 预期下次+7天 → 逾期提醒
- **🔴 严重逾期**（>7天）：当前日期 > 预期下次+7天 → 最强提醒

**动态解析逻辑**（口径单一真源 = `scripts/distill_due_core.py`，本节是其人读视图·v8.3.3 审查收口同步）——**口径三要素=分桶+取行+阈值，缺一不可共**（v8.3.1 教训：只上移其中一两个，下一轮照样漂）：
- **分桶**：`normalize_type()` 字面归一（括号/方括号内的轮次/批次说明**不构成新类型**，如「统一蒸馏管道（终审落地+勘误）」归主类）；类型从账行动态解析提取，**不硬编码**，未来新增蒸馏类型自动支持
- **取行**：剔除 `DISTILLATION-TODO` 自生成区（防调度器自读自写粘滞）后，**全文按文档顺序倒序**扫，每种类型取**最后一条**账行的「预期下次」；⛔不按月段切分只取最新月段（scheduler 旧版盲区=旧口径，v8.3.1 已根治）；⛔不倒序回扫找日期——末字段非 `YYYY-MM-DD`（一次性任务 `—`）=该行无预期下次，静默跳过继续找更早有效行
- **阈值**：同上三级判定

**触发词指引**（从各Skill YAML提取，不凭印象）：每个待办项带「说"{触发词}"可触发」——📊系统日志蒸馏→"系统月报" / 📓日记月报→"月报" / 🧠成长箱月度蒸馏→"成长箱蒸馏"（P1修正后YAML支持）。

**已完成未登记检测**：蒸馏产出文件存在但蒸馏中心无对应记录 → 标注`⚠️已完成未登记`——日记月报检查`~/Local_Obsidian_Vault/1-每日计划/03-月报/YYYY-MM-月总结.md`；系统日志蒸馏检查成就证据文件；成长箱蒸馏检查晋升记录。**唤醒Skill只检测不越界写入**——提示用户补登，不替其他Skill写蒸馏中心（守跨Skill边界，童灵裁决原则）。

**无待办时静默**：所有蒸馏类型均未到期且未逾期 → 不输出「📋 蒸馏待办」模块（指令编写规范 §7.5 静默幂等：有结果才出声）。仅读不写，不违轻量铁律。依据：2026-09-02 用户提出月度蒸馏会忘——核实8月只做了月报，系统日志+成长箱蒸馏逾期；蒸馏中心只记录"做了什么"，没有机制提醒"该做什么了"。

## §3 自动巡检（8.0 阶段③·已实现 2026-09-17）

> 来源：`awaken-memory-system-8.0升级.md` §三 载体选型（2026-09-16 实测）·§五 T0 调查（S708 容忍度函数·PLOS 轻量周期优于频密打扰·Fogg B=MAP 补 P）。本段为自动巡检的**执行细节单真源**——本轮（阶段③）已实现，⛔逻辑改动须回写本段并同步 CHANGELOG。

**目标形态**（触发模型从"纯被触发"升级为"触发 + 自动巡检"·已上线）：

```
launchd plist com.buluotuo.awaken-patrol（每6小时·StartInterval=21600·RunAtLoad）
    → awaken_patrol.sh
        ├─ ①快照滞后检查 → update_snapshot_from_diary.py（§1 现成脚本·exit 语义原样保留）
        ├─ ②蒸馏待办三级检测 → awaken_distill_due_check.py（§2 逻辑脚本化）
        └─ ③osascript 通知你（有逾期🟡/🔴或缺口才弹·无事不打扰）
```

### §3.1 载体与运行环境（单真源）

| 项 | 值 |
|---|---|
| plist | `~/Library/LaunchAgents/com.buluotuo.awaken-patrol.plist`（StartInterval=21600 秒=6小时·RunAtLoad=true·StandardOut/Err → `~/buluotuo_bin/log/awaken_patrol_launchd{,_err}.log`） |
| 主脚本 | `scripts/awaken_patrol.sh`（编排：快照检查→蒸馏检测→触达·只提醒不写他者文件·自有快照经脚本属职责内——v8.1.3与§3.3同口径） |
| 检测脚本 | `scripts/awaken_distill_due_check.py`（蒸馏中心三级阈值·可选位置参数指定蒸馏中心路径·测试/运维用） |
| 巡检日志 | `~/buluotuo_bin/log/awaken_patrol.log`（每次运行四段留痕：快照/蒸馏/触达/完成·可观测） |
| 环境变量 | `DISTILL_CENTER_PATH`（可选·覆盖蒸馏中心路径） |

### §3.2 频率与触达阈值（试跑校准中）

- **频率**：每 6 小时轮询（S708 容忍度函数：快照巡检高容忍→轮询⛔不做事件驱动）+ 轻量周期优于频密打扰（PLOS）→ N=6h 为初值，**试跑一周后校准**（N 依据快照滞后实测与通知响应率调整）
- **触达阈值**：仅 🟡已逾期 / 🔴严重逾期 弹 osascript 通知；🔵即将到期 仅入日志不弹窗（无事不打扰·Fogg B=MAP 补 P）；快照脚本缺失/更新失败=【快照缺口】弹窗（失败显形·假绿防线）；检测脚本自身异常=【巡检异常】弹窗
- **静默纪律**：无待办时全程静默（指令编写规范 §7.5 静默幂等）·⛔不弹"一切正常"类通知

### §3.3 边界与收回

- **边界**：巡检本体=脚本+launchd（不依赖工具运行·愿景①全自动化）；工具内 Schedule 仅用于需要 AI 会话的环节（如逾期后的蒸馏调度触发）；⛔巡检只提醒不写他者文件（不替任何 Skill 写蒸馏中心/日记·跨 Skill 边界，童灵裁决原则；自有快照当日行经 update_snapshot_from_diary.py 既有脚本更新属职责内，v8.1.2·审查A14消歧）
- **与每日伙伴 4.0 边界**：蒸馏待办/快照更新归 awaken（记忆状态域）；日记封口/月报触发归 daily-buddy（记录域）——不重复建设主动泵（方案待决项#2·2026-09-17 你确认推进阶段③时关闭）
- **可观测/可抽检**：巡检=机检，检测对象已外化台账（立场卡 S1022：蒸馏中心/快照）；结果可观测（巡检日志+通知留痕）；可收回（`launchctl unload ~/Library/LaunchAgents/com.buluotuo.awaken-patrol.plist` 即停·删 plist 即永停）——愿景红线（自主≠黑箱）
- **跨端**：launchd/osascript = macOS 宿主依赖；非 macOS 端自动巡检不生效（该端走双模式会话内巡检 §1/§2），如实声明不迁移（版本命名规范兼容性声明口径）

## §4 巡检日志读取·对话内详情面板（8.0 B-2·轻量模式引用）

> **定位**：B-2 = 小美重定位为巡检的「对话内详情面板」（升级方案 §7.2）——巡检弹窗（B-1）是机制层入口（Fogg 补 P·提示即入口），小美输出是对话层详情（补 V·"愿意看"）。**小美使用次数 = 巡检发现问题数·不靠你记得**（愿景①不依赖人记得）。规格锚点：设计哲学 §9.5 B-2·升级方案 §7.2。

**读取方式**：`tail -30 ~/buluotuo_bin/log/awaken_patrol.log`（并入轻量步骤②读取轮的批量 Bash·⛔不单独增轮次——轻量预算约束"目标≤3轮工具往返"·dual-mode.md 轻量预算声明②读取轮已登记）

**解析逻辑**：以最后一次 `[完成]` 行为本次巡检运行段终点，取该段内容判定：
- `[触达] 已弹通知（...）` → 本次巡检有告警 → 输出「📋 巡检详情」模块（告警内容=括号内原文逐字转述·⛔不凭记忆重述·⛔不复制细节=单一真源）
- `[触达] 无事不打扰（静默）` → 无告警 → 静默不输出（指令编写规范 §7.5 静默幂等·有结果才出声）
