## 🔒 防跳步机制

### 接触式防错（Contact Method）

- **锚点**：记忆琥珀 4 索引+TTL 注册表+情境层快照（物理文件读不到标🔴，不依赖 AI 记忆）
- **执行位**：Step0 加载检查（索引缺失=流程不可启动）
- **可验证性**：awaken_version_gate_check.py 实测权威源可达性+独立副本比对；⛔通用核心层锚点缺失=全量模式中止并标注（见铁律#3/禁止行为#4），个人增强层载体缺失=降级跳过标注（见可分享性分层）——不存在"整模式自动降级为轻量"路径（v8.1.2·审查A5：旧措辞为无流程实现的死声明，与中止铁律打架）

### 定值式防错（Fixed-Value Method）

- **锚点**：轻量模式 1 步、全量模式 3 步——步数固定不可增删
- **执行位**：结论块门禁锁三问（结论明确/依据可追溯/签名一致性）——签名前强制过
- **可验证性**：⛔跳过步骤=签名❌；TTL 注册表同步越界行数=定值法阻断（禁止行为#6）

### 步序式防错（Motion-Step Method）

- **锚点**：Step0→Step1→Step2→Step3 串行不可逆；全量链熔断器串联（实物计数以 dual-mode/self-healing 为准·此处不双写数字——v8.1.3·审查N12：旧“6”与实物“全量链5+轻量1”不符）（版本门禁=核心实例）
- **执行位**：上步产出物 Read 回验+TTL 同步前置条件校验
- **可验证性**：awaken_version_gate_check.py 退出码语义（0=一致/1=通用错误/2=缓存不一致→备份覆盖重来/3=规则.mdc过期告警·细节见 self-healing.md §1.1）物理拦截·与1c段唯一口径（2026-08-30修复C1概览残留）；⛔前步缺失=后步熔断中止

> 三法机制/阻断条件已内嵌各工作流步骤（1c 版本门禁/1e 软链接自愈/结论块门禁锁等·细节在 dual-mode.md 双模式流程），此处仅留概览（v7.22 去重）

## 设计原则

**加载即校验。** 读取文件本身就是校验。读不到=不存在=标注🔴。读到=已加载=标注✅。

**轻量不写文件。** 轻量模式直接在对话输出情境概览。全量同样对话输出。（唯一例外见铁律#5：v7.32 懒加载快照更新经脚本限定操作「最近变更摘要」当日行。）

| # | 禁止 | 原因 |

| 6 | ⛔DO NOT TTL注册表同步超出已声明行范围写入 | 越界写入=污染注册表，破坏单表单一结构（Poka-Yoke定值法） |

> **来源**：唤醒记忆系统S级改造方案v1.5 §6.4 | **问题**：变更日志是你的个人实例文件，Skill 分享给别人时别人没有——漏检查还是对别人不重要？

本 Skill 的检查项分为三层。此分层确保 Skill 既是「你的定制体检仪」，又是「可发布的通用框架」。

| 层 | 检查项 | 缺失处理 | 绑定范围 |
|------|------|------|------|
| **通用核心层** | CORE / 架构卡 / 快照 / SHADOW | 🔴 中止 | 绑定 `~/个人AI档案/` 树，树内文件必检；他人无此树则🔴中止为预期行为（非 bug） |
| **个人增强层** | 变更日志 / 最伟大的我 / 成长箱主动自检 | 🟡 降级+标注 | 有则检查，无则跳过（可插拔） |
| **全量增强层** | 四象限载体（悬置区+断言台账+显形台账） | 🔵 全量必读 | 全量模式 Read 并填探针信号；轻量模式亦实时统计（v7.30/31起·经§3.5一次批量Bash取数·v8.1.3措辞随v8.0合并同步·见 dual-mode.md 轻量模式象限说明）（可插拔） |

> **语义消歧**：本 Skill 默认绑定 `~/个人AI档案/` 树。通用核心层 = **该树内文件**，不是「任何装了记忆系统的人都有」。分享给他人时，对方若无此树，通用核心层🔴中止是预期降级而非 Skill 缺陷。**拥有 `~/个人AI档案/` 树者即通用核心层全绿；缺树者按预期🔴中止，个人增强层自动跳过。**
