# 错误记录模板

> **用途**：成长箱Skill流程A（错误记录）步骤A2的写入格式模板
> **引用方式**：SKILL.md流程A步骤A2引用此模板
> **v2.0变更**：Suggested Action改为Body三段式（Rule+Why+How to apply）——原因是只写"建议行动"不写"为什么"和"何时适用"，AI在边缘情况无法判断该不该执行

## 通用错误格式（LEARNINGS.md / ERRORS.md）

```markdown
## [ERR-YYYYMMDD-NNN] 错误名称

**Logged**: YYYY-MM-DDTHH:MM:SS+08:00
**Priority**: high | medium | low | critical
**Status**: pending | resolved | promoted
**Area**: 流程 | 验证 | 身份认知 | 技术实现 | 其他
**来源 AI**: Trae | Trae Work | QClaw | WorkBuddy | 悟空 | Qoder Desktop | QoderWork | Qoder CN | AutoClaw | DeepSeek Harness | LobsterAI | 其他
**认知象限**: 已知未知（收集中） | 已知已知（已解决）

### Summary
[一句话总结错误]

### Details
> 🔴 **BIC 三段式（G1·v1.14.4 新增 · 防情绪化归因）**：错误描述必须拆三段写——**事实**（客观发生了什么·可录像、不含形容词与动机推测）→ **影响**（这次直接造成什么后果）→ **后果**（若反复，长期侵蚀什么）。⛔DO NOT 把"我太粗心了""我总是这样"这类**评价**写在描述位——评价是归因结论，占住描述位会锁死后续根因分析（吸收《可复制的领导力》卡片13-三级反馈与BIC工具；原文用于管理者对下属，**此处只借结构做自我记录**，⛔不作评价他人的话术）。

**事实（Fact）**：[客观行为——谁、什么场景、做了/没做什么。⛔不写"因为…所以…"，⛔不写性格/能力判断]
**影响（Impact）**：[这次直接造成的后果——返工/耗时/数据失真/信任损耗，尽量可量化]
**后果（Consequence）**：[若此模式反复，长期会侵蚀什么——哪条底线/哪类资产/哪个机制的可信度]

> 三段各 1 句话（总篇幅与原"1-3句话"一致，⛔不膨胀）。确实只有事实可写时，后两段写"无"+一句依据，⛔DO NOT 留空段。
> 与 `Root Cause` 的分工：本段只回答"**发生了什么**"（现象层·不归因）；归因归 `Root Cause`，⛔DO NOT 在描述段写根因（防描述即结论）。

### Root Cause
1. **根因1**：[说明]
2. **根因2**：[说明]

### Rule
[一句话规则——犯了什么错，以后该怎么做]

### Why
[为什么这条规则存在——来源事件/偏好/根因]

### How to apply
[何时/何地适用——触发条件+适用范围+不适用情况]
```

## 字段说明

| 字段 | 必填 | 说明 |
|------|------|------|
| 编号 | ✅ | 格式：`[前缀-YYYYMMDD-NNN]`，如 `TE-20260530-001` |
| 错误名称 | ✅ | 简短描述错误类型，如"未验证就下结论" |
| Logged | ✅ | 错误发生时间，ISO 8601格式 |
| Priority | ✅ | high/medium/low/critical |
| Status | ✅ | pending（待处理）/resolved（已解决）/promoted（已晋升） |
| Area | ✅ | 错误所属领域，固定5级：流程/验证/身份认知/技术实现/其他（与SKILL.md Poka-Yoke定值一致） |
| 来源 AI | ✅ | 通用错误必填，专属错误可省略 |
| Summary | ✅ | 一句话总结 |
| Details | ✅ | **BIC三段式**——事实(Fact) / 影响(Impact) / 后果(Consequence) 各一句；⛔不写评价、⛔不写归因（归因归 Root Cause）。G1·v1.14.4 新增 |
| Root Cause | ✅ | 根因分析，至少1条 |
| Rule | ✅ | 一句话规则（替代原Suggested Action） |
| Why | ✅ | 规则存在的原因——来源事件/偏好/根因 |
| How to apply | ✅ | 何时/何地适用——触发条件+适用范围+不适用情况 |
| 认知象限 | ✅ | 错误记录时的认知状态——默认"已知未知（收集中）"（知道有错、在收集模式确认，对应认知无知矩阵第二象限）；Status=resolved/promoted 时标"已知已知（已解决/已蒸馏）"（错误已澄清→晋升为已知已知）。由 Poka-Yoke Schema 防错层强制必填 |
