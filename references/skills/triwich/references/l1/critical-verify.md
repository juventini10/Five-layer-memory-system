## Step3：⚔️ 对抗性检查（v3.8新增）

> **理论基础**：Karl Popper 证伪主义 + Pre-mortem 事前验尸（Klein 2007）+ Steelmanning 钢人论证。详见白皮书§1.3"对抗性验证溯源"。
> **与现有框架的关系**：Popper 提供方法论（主动证伪），实践论提供认识论（终审裁判）。对抗性检查不替代自我批判——自我批判查偏差（原因导向），对抗检查查边界（结果导向），互补不重叠。

**⓪ 证据链三问（v3.15.3 新增 · 读书沉淀吸收 T1 · 对抗前置的证据质量检验）**

> 对抗性检查前，先验"支撑结论的正据质量"——正据弱则反证优先，正据强才值得对抗。与后续②"反方论证须有证据链"呼应成体系。

对结论据以成立的每条关键证据，✅DO过三问：

| # | 自问 | 目的 |
|---|------|------|
| ⓪-① | 这是**事实**还是**解释**？ | 区分原始事实与带判断的解释——解释可被再解释，不能当铁证 |
| ⓪-② | 有没有**替代原因**？ | 同一观察可有多个成因——排除混淆/幸存者偏差，勿将相关当因果 |
| ⓪-③ | 证据**效力**够吗？ | 证据效力≠证据存在——弱证据堆再多也撑不起强结论 |

🔒 **检查点**：⓪ 三问完成并得出"正据质量"结论后方能进入①。⓪ 判正据薄弱（任一关键证据✗）→ Step4 实践检验须含"补证/换证"路径，并在结论块"依据"中如实标注。⛔DO NOT 以"证据存在"代替"证据效力"——原因是存在≠支撑，弱证据堆不成强结论（三问标准取自科学方法：事实/解释分辨、替代解释排除、证据强度评估）。

| 子步骤 | 操作 | 产出 |
|:------|:-----|:-----|
| ① 假设推演 | 假设当前结论已经错了。问：最可能在哪个环节错的？为什么？ | 1个最脆弱环节 + 原因 |
| ② 反方论证 | 为"结论是错的"构建最强论证。**每条反论必须有具体证据/逻辑链条支撑**——不能只有立场声明，不能编假靶子。 | ≥2条反论 + 每条的证据链 |
| ③ 边界条件 | 当前结论在什么条件/场景/假设下不成立？当前场景距离这些条件有多远？ | 边界清单 + 距离评估（近/中/远） |
| ④ 综合判断 | 反方论证的破坏力多大？边界条件在当前场景内吗？ | 🟢经得起对抗 / 🟡需关注 / 🔴需修正 |

🛡️ **质量检查**：反方论证必须有证据链。无证据链的反对=无效反对。自检标准——每条反论能追溯到白皮书§1.3溯源表中的至少1个权威来源，或外部可验证事实。

🔒 **检查点**：4个子步骤全部完成才能进入Step4。综合判断为🟡或🔴时，标注"已识别对抗性风险"作为Step4（实践检验）的输入。

**呈现格式（v3.14.0 呈现精简：内部执行，⛔不渲染——对抗性检查4子步骤只在执行链内生成；综合🟡/🔴须在结论块体现）**

## Step4：实践检验（认识的完整回路）

> **认识论终极标准**：实践→认识→再实践→再认识（毛泽东《实践论》1937）。实践检验不是一次性"验证对错"，而是认识的辩证循环。

| 检验问题 | 回答 | 📦 产出物字段（必填·Fail-Closed） |
|---------|------|--------------------------------|
| 这个结论在实践中能被验证吗？ | | 【可验证性判定】(✅可/🟡部分/❌不可·理由) |
| 验证方式是什么？ | | 【验证命令/工具+预期结果】(具体命令/脚本/工具 + 通过/不通过判定标准) |
| 如果验证后发现结论不对，下一步是什么？ | | 【认识循环路径】(检验通过→升级为更可靠认识·不通过→修正→再检验) |

🔒 **检查点**：【验证命令/工具+预期结果】列空 或 只写"进一步观察"=无效验证=退回补全。——原因是"验证方式必须可操作"（§四.1根因·可操作无定义）：无具体命令+无预期结果=验证无法执行=实践检验失效。

**呈现格式（v3.14.0 呈现精简：内部执行，⛔不渲染——实践检验3问只在执行链内生成）**

## Step4.5：反八股检验 + 归因谦逊（v4.2.0 补齐·深度触发器命中时必走·L2/L3必走）

> **定位**：Step4 实践检验完成后、Step5 结论块前的质量门禁——查结论是不是"正确废话"（八股）+因果归因是否谦逊（可错主义）。
> **理论根**：矛盾论6"具体分析具体情况"（删掉具体对象仍成立=八股）+ 权衡14最佳解释论证 + 权衡3可错主义（波普尔：归纳推理的结论永远是暂定的）。

🛡️ **反八股检验**（对齐 abstraction.md/first-principles.md 同格式·单一真相源）：

结论块核心判断"删掉具体对象（文件名/字段名/场景/系统名）后仍成立 = 八股（正确废话）"→ ✅DO 退回重写。

| 示例 | 判定 | 理由 |
|------|:---:|------|
| "这个方案有风险需要谨慎评估" | ❌八股 | 删掉"这个方案"仍成立=正确废话（任何方案都有风险） |
| "碰撞候选管道的队列文件本质是缓存，SOP把缓存当真值源用，缓存被重置=统计归零" | ✅挖到底 | 删掉"碰撞候选管道"就不成立=具体分析 |

⛔DO NOT 用"需要进一步验证/有待观察"替代具体判断——原因是这本身就是八股（任何结论都可以说"需要进一步验证"）。

🧠 **归因谦逊**（v4.0.0 CHANGELOG 声称补了但本体0次·本次真正落地）：

结论块中因果归因 ✅DO 标"**目前最佳解释**"——⛔DO NOT 写"就是原因/证明了/确定了/根因是"。

| ⛔ 过度确定措辞 | ✅ 归因谦逊措辞 |
|---|---|
| "X就是Y的原因" | "X是Y的**目前最佳解释**（待实践检验确认）" |
| "证明了X导致Y" | "证据**支持**X→Y（当前最佳解释·可错）" |
| "确定了根因是X" | "根因**最可能是**X（🟡中置信度·需补证）" |

原因是：一次验证≠永远正确（《实践论》），归纳推理的结论是可错的（波普尔证伪主义），标"目前最佳解释"=认识论谦逊+为后续修正留空间。对齐 CHANGELOG v4.0.0 声称"结论块归因结论标'目前最佳解释'"——本次真正落地到 critical-verify.md 本体。

🔒 **检查点**：深度触发器命中时（或L2/L3），反八股+归因谦逊为必经步骤（Fail-Closed：缺=退回）。结论块含"就是原因/证明了/确定了"等过度确定措辞→退回改为归因谦逊措辞。L1默认轻量时本步 ☑SHOULD（建议但不强制·成本匹配复杂度）。
