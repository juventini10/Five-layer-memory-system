# 签名二值化模板

> **使用层级**：所有层级
> **设计来源**：Poka-Yoke顺序检查防错法
> **核心规则**：✅和❌是唯一的两个合法状态。禁止⚠️/部分✅/降级完成等灰色状态。

---

## 🔴 两轴分离（v3.11.0·消除"结论🟡怎么签"的歧义）

| 轴 | 合法值 | 判什么 | 谁用 |
|---|:---:|------|------|
| **内容判定轴** | ✅ / 🟡 / ❌ | 对被分析对象的判断（通过/有保留/不通过） | 结论块表格 |
| **流程完整性轴** | ✅ / ❌ | 本Skill步骤是否走完、产出物是否齐全、门禁锁是否通过 | **签名位** |

- 结论🟡 + 流程完整 → 签名 **✅**，但摘要✅DO写出 🟡 的具体理由。
- 结论✅ + 缺步/降级/超时 → 签名 **❌**，输出缺失清单。
- ⛔DO NOT把 🟡 搬进签名位，⛔DO NOT用 `✅ ⚠️降级` 这种复合写法绕过二值化。

---

## 签名格式

```
[🧠 三明智 {L1/L2/L3} ({路径}) {✅/❌} | 结论块浓缩版 | 日期]
                  ← 空行（必空）
—— 你的 {工具署名}
```
> 模板二值位说明（2026-08-10 第4轮复审补）：✅/❌ 必填（流程完整性轴，无第三值），路径名按层级示例（如 `L2 (第一性原理+批判验证)`），摘要=结论块浓缩版（禁超集/子集）。

| 层级 | 签名示例 |
|------|---------|
| L1 | `[🧠 三明智 L1 (第一性原理) ✅ | 结论块浓缩版 | 2026-05-29]` |
| L2 | `[🧠 三明智 L2 (抽象建模+第一性原理) ✅ | 结论块浓缩版 | 2026-05-29]` |
| L3 | `[🧠 三明智 L3 (深度模式) ✅ | Agent A✅ (n/N子目标) + Agent B✅ | 结论块浓缩版 | 2026-05-29]` |

## 签名规则（不可违反）

| 规则 | 说明 |
|------|------|
| 摘要必须引用实际内容 | 不能只写"已完成""已通过""无" |
| 摘要=结论块浓缩版 | L1/L2/L3 三层一致：摘要既不多写也不少写（对应 SKILL.md §禁止行为 #5）。⛔DO NOT写成"锚点摘要""分类摘要""验证摘要"这类只覆盖单步的表述 |
| 签名出现❌ | 不输出结论，仅输出缺失清单 |
| 签名造假 | 签了✅但实际步骤缺失=输出无效 |
| 灰区废除 | ⚠️/部分✅/降级=视为❌ |
| 单签名行（v4.10.0·F8） | 结论块之后只允许一行签名；重复签名/双行签名=格式违规（两本账） |
| L3 格式唯一源 | L3 签名格式以 `references/l3/full-flow.md §签名` 那一行为准（`(n/N子目标)` 口径·n=实际走完/N=4个📦子目标·v4.4.9 旧"含4/4"示例即全量快照特例）；本文件示例与 `l3/full-flow.md` 均为其副本，出现分歧以 full-flow.md 为准（2026-10-22 R2 修分家死锚） |
