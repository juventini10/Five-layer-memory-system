## 1. 模块结构

| 编号 | 模块名 | 核心内容 | 铁律 |
|------|--------|---------|------|
| 封面 | 📸 本周快照 | 主题/最值钱一件/三个数字/所以下周 | 置于正文首位（H2标题后、首模块前） |
| ❖ | 日记质量评估 | 7天完整率/Section健康/含金量[S/A/B/C/N]/感悟深度/数据准确性 | 数据源健康检查，下游分析基础 |
| 📌 | 月目标对齐 | 从月报「下月3件事」分解本周应交付+累计进度 | **置顶（context）** |
| 🎯 | 核心概览 | 整体评级A/B/C + 关键指标 + 本周亮点 + 本周挑战 | 含 `> 客观状态` 进度条 |
| 1️⃣ | 进度追踪 | 每日进度明细 + 核心项目进度 | |
| 2️⃣ | 数据分析 | 番茄效率趋势/睡眠健康/内容产出/**时间分配(重要轴分类)**/**📚阅读足迹** | 时间分配<40%必须点名；📚阅读足迹=仅列你日记记载"读了《X》"的书，AI蒸馏无日记记录不列 |
| 3️⃣ | 问题与解决方案 | 根因①小标题 + 落地动作表 | 必带落地动作，无动作=没分析 |
| 4️⃣ | 90天目标对齐 | 上周行动与90天目标关系/进度评估 | |
| 5️⃣ | 情景层卡点跟进 | 当前卡点进展/解决方案 | |
| 6️⃣ | 上周计划完成情况 | 对照周分解逐条检查交付 | |
| 7️⃣ | 本周计划 + 伙伴建议 | 本周计划(从月目标分解·不自列) + 伙伴视角 | **置底（行动指令）** |

### 📌 模块排序铁律

> **核心要求**：本周计划(7️⃣前半) + 伙伴建议(7️⃣后半) 是「下周行动指令」，✅DO 在周报中**置底输出**——排在 上周计划完成情况(6️⃣) 之后。📌 月目标对齐 置顶（context，非行动）。

⛔DO NOT 将行动指令排在分析类模块之前——原因同月报：置中会被进度/数据长内容淹没，用户在对话框内漏看。

**完整输出顺序（强制）**：
`封面本周快照 → ❖质量 → 📌月目标对齐 → 🎯核心概览 → 1️⃣进度 → 2️⃣数据 → 3️⃣问题 → 4️⃣90天 → 5️⃣情景 → 6️⃣上周完成 → 【7️⃣本周计划 → 伙伴建议】`

### S级处理铁律（v1.0·对齐总记录来源维度）

> **周报整体评级 ∈ {A, B, C}**——S 是月报维度里程碑判断（需30天跨场景证据/顿悟专区+6铁律），一周7天无法验证，周报在逻辑上"生产"不出S评级。
> **但含金量模块须 SURFACE S天**：从7天日记 YAML `rating:` 提取分布时，若含 `rating: S` 天，在含金量分布表标注 `S: N（详见S级顿悟总记录 #X·回链）`，**不计入周报整体评级**。
> 回链覆盖**所有** S天（申报S + 校准升S 均链，因都是 confirmed S 事实）；周报内**不内联来源**（总记录「来源」列是唯一真相源，避免双本账）。

### 格式铁律

**序号规范**：大模块 `1️⃣、2️⃣…7️⃣`（连续·⛔DO NOT 跳号）；子项目 `①、②、③`。
**标题规则**：`## 2026-WXX 周报（M/DD-M/DD）`。
**存储路径**：`{{OBSIDIAN_VAULT}}/1-每日计划/02-周报/2026-WXX-皮叔周报.md`

### ❖ 日记质量评估细则

**定位**：数据源健康检查。在所有下游分析前执行，评估本周7天日记可靠性。

⚠️ **铁律**：S级日记必须从 YAML `rating: S` 提取。rating字段为空 → 标注"数据缺失"。**禁止凭事件重要性推断评级。**

| 维度 | 指标 | 数据来源 |
|------|------|---------|
| ① 完整率 | 写了X天/7天，断更天数 | 当周日记文件列表 |
| ② Section完整率 | 含齐SECTION的日记比例 | 各日记 `<!-- SECTION: -->` 标签扫描 |
| ③ 含金量评级分布 | S/A/B/C/N各X篇（含S天回链总记录） | 各日记YAML `rating:` 统计 |
| ④ 感悟深度 | 空/一句话/中等/深度 | `<!-- SECTION: INSIGHTS -->` 内容量 |
| ⑤ 数据准确性 | 番茄对不上/睡眠缺失篇数 | 日记数据段交叉验证 |

**输出格式**（插入封面之后）：
```
❖ 日记质量评估
| 维度 | 数据 | 评价 |
|------|------|:----:|
| 完整率 | 7/7（100%） | 🟢 |
| Section完整率 | 95% | 🟢 |
| 含金量分布 | S:1 / A:3 / B:2 / C:1 / N:0 | 🟢（S:1→总记录#8回链） |
| 感悟深度 | 空:0 / 一句话:1 / 中等:4 / 深度:2 | 🟢 |
| 数据异常 | 0篇 | 🟢 |
```

## 2. 数据铁律

- ⛔DO NOT 凭记忆或推测补数据——必须逐行读取当周7天日记源文件。
- ⛔DO NOT 凭记忆编写系统建设/成就——必须读取当周系统日志提取。
- 统计流程：**读取全部日记 → 统一口径分类 → 交叉验证 → 自查一致性**。

### 读写分离三阶段

```
阶段1：只读（BATCH READ）——逐行读7天日记+当周系统日志，禁止写
阶段2：只算（COMPUTE）——汇总统计+占比+趋势+交叉验证，禁止读新文件
阶段3：只写（WRITE ONCE）——基于阶段2一次性输出完整周报，不回跳补写
```

## 3. 根因分析与伙伴建议

### 根因分析排版

- 每个根源观点独立一行，不挤同一行。
- 格式：`① **小标题**——具体说明`。
- 禁止用分号串联多个观点。
- **必须跟"落地动作"表**：没有落地动作的根因分析等于没分析。

格式：`| 根源 | 动作 | 怎么执行 |`

### 伙伴建议角度

- 不重复本周快照/高光内容。
- 从数据中发现用户自己没注意到的成长或模式。
- 保留"你"称呼（伙伴视角，非冒充）；可用子模块"我看到的你没看见的东西"。

## 4. 报告呈现规范（双声部 · 本周快照 · 进度条 · YAML）

> 来源：对齐月报改造思路（2026-08-01）· 同源文件格式规范 v2.2.0

### 4.1 文件格式铁律（强制）

- ✅DO 周报文件**必须含 YAML Frontmatter**（精简集 + `author`，对齐文件格式规范 v2.2.0 分层）：
  - 必留（检索+合规）：`rating`（A/B/C·周报检索核心）/ `summary`（跨文搜索首因锚点）/ `date`（报告实质生成日 ISO）/ `type`（reference）/ `source`（权威路径）/ `complies_with`（新建必含·文件格式规范 v2.2.0）
  - 建议：`author: 皮叔`（默认，⛔DO NOT 写「你」）/ `title`（规范兼容·文件名已含可省）/ `tags`（简，如 `[周报]`）
  - ⛔DO NOT 正文数据塞 YAML：`rating_reason`（正文本周快照已有评级依据）/ `total_tomatoes` / `daily_avg_tomatoes` / `sleep_pass_days` / `milestones` / `blockers` / `shadow_new_count`（正文客观状态块与 SHADOW 源文件已有——YAML 是检索索引非内容副本=双本账教训）
  - 可省（已查无消费者）：`week` / `period_start` / `period_end`（文件名 `2026-WXX` 已含周次）/ `status`（生成即定稿·无语义）/ `version`（无迭代史）/ `area` / `related`
- ⛔DO NOT 正文用 H1（`#`）；正文标题从 `##`(H2) 起。

### 4.2 双声部规范（内容级分离，非文件级）

- 温暖叙事声部：正常段落，讲洞察/战略/温度。**禁用第一人称"我"**描述用户自身状态（防 AI 冒充）；用独立客观观察表达。
- 客观数据声部：用 `> 客观状态` 引用块承载，内部用 Unicode 进度条 `█`(U+2588)/`░`(U+2591) + 关键数字。源文件零 emoji，保证任意查看器可读。
- 伙伴建议声部（7️⃣ 模块）：保留"你"称呼（伙伴视角，非冒充）。
- ⛔DO NOT 在报告**可见文本**（H2标题 / YAML `tags` / `summary` / section 小标题）写入「双声部」「进度版」「进度条」等设计概念字眼——双声部是内容级机制，不是输出标签。

### 4.3 封面 · 本周快照

> 标签定名"本周快照"（对齐月报"本月快照"）。⛔DO NOT 加「（四拍）」备注——四拍是月报概念，与周报快照无关（皮叔 2026-08-01 指令）。

置于报告正文首位（H2标题之后、首个数据模块之前）：
1. **[周次]，一句话**（主题）
2. **本周最值钱一件事**（转折/认知）
3. **三个数字**（客观）
4. **所以下周**（行动）

### 4.4 进度条规范（Unicode · 可移植）

- 年度进度条：`2026 年度进度  ██████░░░░  7/12 月 · 58%`（宏进度，周报可省略）
- 模块完成度条：`目标  ██████████░░  X/Y · Z%`（微进度，置于每模块 `> 客观状态` 内）
- ⛔DO NOT 用 emoji 进度条（如 🟩）——仅用 `█`/`░` 保证跨查看器一致。
- 口径：模块=实际/计划，缺数据标"未启动/待核实"不编。

### 4.5 📚 阅读足迹（2️⃣ 数据分析内·v1.2新增）

> **定位**：学用循环闭环的"应用足迹"轻提示——只反映你真正在读、想内化的书，克制不打扰。
> **来源**：2026-09-01 学用循环断裂点核查（知识池全 L1·无回流）+ 你拍板（周/锁定日记信号源）。

- **信号源（唯一）**：本周 7 天日记中，你**明确记录"读了《X》"** 的书。⛔DO NOT 把 AI 蒸馏产卡、但你未在日记记载的书列入——那是给 AI 学习的库存（供调用/引用），不占你注意力。
- **呈现位置**：2️⃣ 数据分析板块内、内容产出之后，作为一行嵌入（不新增外部模块）。
- **呈现格式**：`📚 阅读足迹：本周日记记载读了《X》《Y》。其中已在 SWT 复习升级 L2+ 的 → 附"✅已温/建议本周期再温"。`
- **克制原则**：仅列书 + 建议，不构成"拽着复习"的压力；是否进入 SWT 复习由你自主决定。
- **回流闭环**：周阅读足迹自然成为月报「北极星·质证升级数」判断你是否空转的数据源——周产足迹 → 月查升级，形成"读→用→反馈"闭环。
- **静默规则**：本周 7 天日记无任何"读了《X》"记载 → 本行不输出（不显示"零本书"，避免噪音）。
