#### 🗺️ 5阶段总览（v3.47.0新增·消灭Lost in the Middle·T0根治第四层）

> **设计哲学**：原17步流程过长，AI跑到中部时注意力衰减（Lost in the Middle，U型曲线），导致末尾第6.5步五容器回流整步跳步（8月实证）。精简为5阶段导航——AI先看5阶段总览明确全局，再按阶段执行子步骤（17步详细结构保留在下方）。阶段间有明确的产出物锁和物理Read前置条件，消灭跳步空间。

| 阶段 | 名称 | 子步骤（原编号） | 产出物锁 | 物理前置条件 |
|:---:|------|----------------|---------|------------|
| **1** | 数据采集快照 | 第0步 | 数据快照JSON | 当月日记≥28天 |
| **2** | 月报生成+全量审计 | 第1步→第1.1→1.25→1.5→1.6→1.7→阅读分析→Skill健康→第1.8→第1.9 | 完整月报文件（含13必含模块+4审计模块） | Read阶段1快照JSON（不存在=回溯） |
| **3** | 记忆层回流 | 第2步→第3→第4→第5→第6 | 动态状态快照更新+SHADOW统计+底线审计报告 | Read阶段2月报文件（不存在=回溯） |
| **4** | 五容器回流 | 第6.5步（distill_containers.py三阶段） | 五容器文件（自画像/变化轨迹/认知发现/回避模式/成就证据） | Read阶段3底线审计报告（不存在=回溯）；distill_containers.py --verify exit=0 |
| **5** | 终检收口 | 第7步（finalize_report.py）→第7.1步 | 蒸馏报告+确认JSON | Read阶段4五容器文件（不存在=回溯）；finalize_report.py exit=0 |

**阶段间物理阻断规则（状态机式·强制）**：
- 每个阶段的**第一个动作**必须是Read上一阶段的产出物文件
- Read失败（文件不存在/为空）= 硬阻断，必须回溯上一阶段补齐，不可跳过
- 阶段4和阶段5有脚本物理拦截（distill_containers.py --verify / finalize_report.py），exit≠0=无法进入下一阶段
- AI执行时先声明"当前进入阶段X"，再执行该阶段内的子步骤

**关键防误点（8月实证教训）**：
- 阶段4（五容器回流）是原流程中最容易跳步的环节——因为它在倒数第二步，AI注意力已衰减。现在阶段4有独立的产出物锁+脚本物理拦截（distill_containers.py --generate生成骨架确保文件存在，--verify校验完整性），跳步空间被物理消除
- 阶段5（终检收口）有finalize_report.py脚本物理拦截，缺容器=exit 3，缺字段=exit 4，AI无法绕过

**设计哲学**：把"数据准确呈现"从靠AI自觉变成靠系统机制强制。AI写月报时只能引用快照中的数据，每个数据自带定义+来源+采集时间，从源头消除字段歧义和误读。

**执行前检查**：
- [ ] 当月日记目录存在且≥28天
- [ ] `scripts/monthly_data_snapshot.py` 存在

**执行**：
```bash
bash [记忆共享中心]/技能配置/daily-buddy/scripts/dbbin.sh monthly_data_snapshot.py --month YYYY-MM
```
脚本自动采集以下维度数据，生成带时间戳的JSON快照：
- **日记维度**：总番茄/日均番茄/总睡眠/日均睡眠/评级分布/睡眠达标天数/周番茄分布/心情指数

- **视频维度**：视频发布条数+详情（严格完成态检测）
- **系统日志维度**：当月系统日志篇数

每个字段格式：`{"value": 值, "definition": 定义, "source": 来源路径, "collected_at": 采集时间}`

**执行后验证**：
- [ ] 快照文件已生成
- [ ] 快照中日记天数=当月实际天数
- [ ] 快照中关键数据（番茄总数/睡眠日均/概念卡总数）非零

**验证失败处理**：中止后续步骤，提示"第0步数据采集失败，请检查脚本和数据源"

> ⚠️ **强制约束**：第1步生成月报时，所有量化指标必须引用本快照数据，禁止AI自己去查数据然后写。如果月报中需要快照没有的指标，必须先扩展快照脚本，再重新采集。


**脚本校验内容（原子化·不可拆分）**：
1. 月报文件存在+非空+YAML frontmatter合法
2. 月报模块完整性（13必含模块+4审计模块，宽松关键词匹配）
3. 五容器存在性+必含字段+占位符检测（自画像7段/变化轨迹≥1条转折/认知发现含"发现"段/回避模式含"模式描述"+"认知象限"/成就证据含"我做对了什么"≥3条）
4. 生成确认JSON（AI蒸馏报告必须包含此JSON中的确认数据）

**退出码语义**：
| exit code | 含义 | 处理 |
|:---:|------|------|
| 0 | 收口成功 | 进入终检通过后执行 |
| 1 | 报告文件缺失/参数错误 | 中止，回溯第1步 |
| 2 | 报告模块不完整 | 中止，报告缺失模块，回溯补齐 |
| 3 | 五容器文件缺失 | 中止，报告缺失容器，回溯第6.5步（调用 distill_containers.py --generate） |
| 4 | 五容器必含字段缺失/含占位符 | 中止，报告缺失字段，回溯补齐后重新校验 |

**终检不通过处理**：中止输出，按脚本stderr提示回溯补齐后重新调用 `finalize_report.py`，直到 exit 0。⛔DO NOT 在 exit≠0 时输出蒸馏报告——原因是蒸馏报告必须包含脚本JSON中的确认数据，不调脚本=拿不到JSON=报告写不出来（接触法防误）。

#### 🔒 三级级联锁设计说明（来源：Skill架构规范v3.0 §4.1 · v3.46.0 T0根治升级为脚本物理拦截）

| 锁级别 | 名称 | 做法 | 目的 |
|:---:|------|------|------|
| **1️⃣** | 产出物锁 | 每步执行前声明产出物，完成后确认已生成 | 防单步跳步 |
| **2️⃣** | 上步校验锁 | 关键合并步骤前读取前一步产出物文件，缺失→回溯补齐 | 防跨步遗漏 |
| **3️⃣** | 报告终检锁（脚本物理拦截） | 最终输出前调用 `finalize_report.py`，exit≠0→不能输出（v3.46.0升级：原AI自检清单→脚本物理拦截） | 防输出残缺 |

**设计价值**：单锁只能防本步跳过，三级锁覆盖"单步→跨步→终检"全链路。v3.46.0 T0根治将第3级锁从"AI自检清单"（防错层·可被绕过）升级为"脚本物理拦截"（防误层·无法绕过），与日记封口 `finalize_diary.py` 同构。8月月报实证：AI自检清单可被绕过（第6.5步五容器缺4个，终检未拦截），脚本物理拦截是根治方案。

**五容器双脚本拦截链（v3.46.0）**：
1. `distill_containers.py --generate` → 骨架生成（文件物理存在+必含字段占位符）
2. AI填充认知蒸馏内容
3. `distill_containers.py --verify` → 完整性校验（缺字段/含占位符=exit 2）
4. `finalize_report.py` → 终检收口（缺容器=exit 3，缺字段=exit 4）
三层物理拦截，AI无法绕过。
