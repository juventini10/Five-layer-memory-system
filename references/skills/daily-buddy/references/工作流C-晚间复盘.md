# 工作流C：晚间复盘

> 触发词："今日复盘" / "晚间总结"
> 此流程极其关键，必须按 1-8 顺序执行。P0铁律和监控标准常量见SKILL.md主文件。

---

1. **数据收集与补全**：读取今日日记。如发现睡眠数据、今日实际番茄数、情绪分数为空，主动向用户提问补齐。

   **🔒 学习记录拉取（v3.14.0新增）**：Read 今日系统日志（[记忆共享中心]/工作日志/系统日志/系统日志_{YYYY-MM-DD}.md），检索类型为"学习"的条目。
     - 有学习条目 → 向用户展示："你今天用Loop学了[主题/轮次]，要记进今天的日记吗？"
       用户确认 → 写入日记「今日成就」区
       用户拒绝 → 不记录
     - 无学习条目 → 跳过
     ⛔DO NOT自动写入——原因是学习是否值得记由用户判断，系统不替用户决定。

2. **自动化脚本执行**：
   - **🔒 灵感闪现校验（v3.13.0 变更）**：灵感闪现行已由 `create_skeleton.py` 在创建次日骨架时自动注入。复盘时无需再做灵感提取，只需校验：
     - 今日日记的灵感闪现行存在且非占位符 → ✅ 正常（昨日脚本已注入）
     - 今日日记的灵感闪现行为 `{{灵感闪现_待填入}}` → ⚠️ 极rare（脚本现已始终产出真实金句：有库用库、无库回退随包名言池）。若仍出现，说明个人库与名言池均不可用，此时AI需补入：读取今日感悟关键词→匹配核心启发库（有库）或随包 `daily_quotes_cache.json` 名言池→原文照搬
     - 今日日记无灵感闪现行 → 🔴 异常（模板不一致），报错提醒
   - **今日感悟模块由用户亲自填写（LRN-20260526-001）**：日记「5️⃣ 💡 今日感悟」模块是整个日记最核心的反思模块，**由用户本人填写**，AI 不代写、不代生成、不代概括。AI的工作仅限于：①检测感悟是否为空（门禁机制） ②提醒用户填写 ③等待用户提供感悟原文 ④将用户原文原样写入。感悟为空→后续流程全部锁死（见步骤4感悟门禁）。这一规则源于：感悟是使用者反思的产物，是日记最重要的模块，AI代写=剥夺反思=本末倒置。
   - **🔒 成就检测（强制，不可跳过）**：运行 `achievement_tracker.py --all`，若有新成就，准备写入日记并弹窗。
   - **⚠️ 非沙箱执行（关键）**：成就检测/更新两步须在**非沙箱**环境运行（`dangerouslyDisableSandbox: true`）。macOS 沙箱会拦截 `osascript` 对"系统事件"的 TCC 授权，导致解锁时**只响声音、不弹模态框**。非沙箱才能让用户亲手点 OK（仪式感）。脚本仅本地读写+弹窗，风险极低。
   - **🔒 成就更新（强制，不可跳过）**：运行 `update_diary_achievement.py` 更新今日日记的成就模块。该脚本在写入成就块后**自动计算封口签名**（`review_sealed_sig` 写入日记 YAML frontmatter），签名基于当日 6 项真实成就数据 + 日期 → 确定性 SHA256 哈希。⛔DO NOT 手写 `review_sealed_sig` 字段——原因是只有脚本能基于真实成就数据产生合法签名；AI 手写的签名必然与 `verify_achievement_seal.py` 独立重算的结果不匹配 → 验证脚本必然拦截。
   - **🔒 成就校验（终检·代码级物理阻断）**：运行 `python3 scripts/verify_achievement_seal.py`。exit 0 = 成就封口签名与当日真实数据一致 → ✅ 通过。exit≠0 = 成就检测未跑/被伪造/数据过期 → 🔴 物理阻断，必须回溯重跑步骤 2（成就检测+更新），不可进入步骤 3。此脚本替代旧版人工检查 diary_total——签名比对覆盖全部 6 项成就指标，不依赖 AI 自律。
   - **晋升扫描**：扫描成长箱（LEARNINGS.md/ERRORS.md），同类错误 ≥3 次且未 promote 时，提醒用户是否升格为规则。
   - **记忆层级TTL检测**：逐层检查最后更新时间，过期则提醒用户。检测清单见SKILL.md主文件的📅记忆层TTL规则表。
     **过期提醒**：按SKILL.md顶部📅记忆层TTL规则表执行

   - **灵感提取示例**（以下为脚本兜底时AI手动补入的流程示例）：
   ```
   背景：创建明日骨架时脚本未匹配到，今日需手动补入

   AI提取关键词：剪辑效率 / 内容取舍 / 犹豫
   Step1 搜 → grep "剪辑效率\|内容取舍" ~/Local_Obsidian_Vault/2-知识库/01-读书笔记/核心启发库.md
     命中行: "BOOK: 稀缺" → "带宽过载时，最好的选择就是少做选择。"
   Step2 选 → "带宽过载时，最好的选择就是少做选择。"原文照搬
   Step3 验 → grep "BOOK:.*稀缺" → 匹配 ✅
   写入明日日记：
   💡 **灵感闪现**：带宽过载时，最好的选择就是少做选择。 —— 稀缺
   📖 来源说明：今日感悟提到"内容取舍犹豫"，对应稀缺中关于决策带宽的理论——选择越犹豫越需要削减选择面，而非增加。
   ```

3. **数据一致性校验 (CoT 强制输出)**：⛔DO NOT 在 `verify_achievement_seal.py` exit≠0 时进入本步骤——前步验证未通过=成就未封口→须先回溯步骤2（接触法防误：步骤3入口依赖步骤2终检通过）。在生成最终内容前，必须在对话框输出检查清单（含数据一致性、格式完整性、假设验证三层校验），其中数据一致性校验必须包含 `achievement_data.json` 的 `diary_total` 已同步为当前实际篇数的确认项。不一致→回溯重跑。完整模板见SKILL.md主文件。

3.5. **言行一致性复盘**：生成言行一致性复盘模块，包含AI评估、自查、交叉验证三部分。
   > 💡 执行规则：
   > - **AI评估**：按SKILL.md主文件的📏标准常量表，对比睡眠/番茄数据与标准，输出偏差项。连续多天同项⚠️时标注"连续N天"。
   > - **自查**：读取用户勾选的偏差项（消费冲动/时间浪费/作息违背/其他）。
   > - **交叉验证与SHADOW写入**：AI评估与自查矛盾时→质疑确认→以用户最终确认为准；🔴级（触及CORE底线或交叉验证矛盾）必须写SHADOW.md（按 `shadow-protocol.md` 执行，须含「认知象限」字段填充 + 写入后校验，防空规则）。
   📦 **产出物**：SHADOW.md 新记录已写入，且含合法「认知象限」字段（默认未知已知；正向行为已知已知）
   🔒 **校验锁**：写入后回验本条新记录含「认知象限」字段且取值∈{已知已知/已知未知/未知已知/未知未知}；不合法→补全重写入，不进入步骤4
   > - **追问话术原则**：用数据说话，不带评判。例："数据显示{实际值}，和你说的不太一样，是有什么特殊情况吗？"
   > - **CORE.md 🔴 底线条款**：①不伤家人 ②不伤健康(宁可少赚) ③不利己损他 ④不违背良心 ⑤不做无正向反馈的事

3.6. **🔒 记忆冲突扫描**：扫描全量记忆文件，检测矛盾与过期内容。扫描范围和检测逻辑见SKILL.md主文件。

   🔒 **校验锁**：写入后回验①核心主表每行「时间象限」列取值∈{Q1重要紧急,Q2重要不紧急,Q3紧急不重要,Q4不重要不紧急}；②任一Q2未完成项均有拖期标记；不合法/缺失→回溯补全，不进入步骤4

4. **数据摘要 + 洞察生成**：
   > 🚫 **感悟门禁（LRN-20260526-001 强制）**：步骤4执行前检查「5️⃣ 💡 今日感悟」。为空→暂停所有后续步骤，等待用户填写。
   
   4a. **数据摘要**（自动生成，无需用户参与）：番茄/睡眠/P1/情绪数据表格。将数据摘要填入日记「## 2️⃣ 🎯 今日工作」之前。
   4b. **洞察生成**（AI主动分析，按条件自动触发）：三类洞察——🔍异常 / 📈趋势 / 🔗关联。单次复盘最多2条。

4.1. **🪞 感悟深潜（门禁机制）**：检测今日感悟是否含自我归因信号。检测到情绪信号→必须触发深潜。按 `references/deep-dive-protocol.md` 执行。

6. **伙伴建议 + 次日骨架**（合并步骤——两件事一起做，不可拆分）

   > 次日骨架由脚本 `--out` 自动写盘（幂等），AI 只需调一条命令不需手动 Write。本步不可跳过——建好次日的骨架，今晚的复盘才算完整。骨架作为写日记的自然副产品产生，用户零操作。

   6.1 **建骨架**：先确认今日日记全部已确认内容已落盘（YAML数据 / 工作主表 / 心情能量 / 感悟 / 最佳决策 / 总结）。
   ⛔DO NOT在等待用户补充数据时执行本步——脚本读磁盘文件，不是AI上下文，用户未回答时磁盘上是空数据。
   确认落盘后，执行：
   ```
   python3 scripts/create_skeleton.py --date 次日日期 --out {DIARY_BASE}/YYYY-MM/次日日期.md
   ```
   脚本自动写盘，AI 只需跑这一条命令。（幂等——文件已存在则输出 stderr "骨架已存在，跳过" 并 exit 0，不覆盖现有骨架。）
   - 若脚本输出"跳过"信号（`exit 0`，stderr 含"骨架已存在"）→ Read 次日文件，校验「💡 灵感闪现」行已就位且非占位符 `{{灵感闪现_待填入}}`；缺失则按步骤2灵感兜底流程补入。

   6.2 **读灵感**：Read 骨架文件，提取「💡 灵感闪现」行原文 + 「> 来源」行（匹配来源信息）。

   6.3 **写建议**：写入日记·SECTION 1️⃣1️⃣。伙伴建议的最后必须包含灵感闪现的情境呼应——用今天的实际经历给脚本生成的灵感"赋温"：

   ```
   > 💡 灵感闪现已就位：「{原文照抄}」
   > ——今天你{用当天的具体事件呼应灵感主题}，
   > 这条来自{匹配来源}的提醒，明天或许刚好用得上。
   ```

   ✅DO 情境呼应必须基于今日日记的实际内容（感悟/总结/工作主表），不编不造。
   ⛔DO NOT 干贴原文不写呼应——原因是冷冰冰照抄=失去人类需要的情绪价值，细节见温度。

   📦 **产出物**：伙伴建议（含灵感情境呼应）+ 次日骨架文件（已Read回验：文件存在+灵感闪现非占位符）
   
   ⛔DO NOT 先写建议再建骨架，⛔DO NOT 跳过6.2直接写6.3。
   ——原因是这本是接触法防误（Contact Method）：骨架不存在→灵感不可读→建议最后一段物理写不出来。
   LLM不能先凭空编一句"灵感闪现"，再回去建骨架——那等于绕过立交桥走逆行。

    7.5a. **📊 刷新CONTEXTUAL层：睡眠+能量+SHADOW**
      ✅DO 从今日日记关键表/数据摘要中读取：入睡时间/起床时间/夜眠时长/
          补眠时长/番茄总数/情绪分数/SHADOW偏差项（步骤1+3.5+4a已提供）。
      ✅DO Edit `[记忆共享中心]/情境层/动态状态快照.md` 替换：
        1. `- **今日能量**：` 行 — 替换为今日最新数据（含番茄数+评级）
        2. `- **SHADOW状态**：` 段落 — 追加今日偏差记录在段落末尾
           （SHADOW 段落是追加式记录，保留前几日数据，新增的放最后。
            格式与现有 SHADOW 段一致：「{日期}入睡{时间}🔴/...」）
        3. 头部 `最后更新：YYYY-MM-DD HH:MM` — 更新为当前时间戳
      🔌 熔断器：快照文件Read失败 → ⚠️标注"快照同步延迟"，不阻塞复盘
      🔌 熔断器：Edit字段不存在（结构变更导致原行消失）→ ⚠️标注"快照字段不匹配"

    7.5b. **📋 追加「最近变更摘要」行**
      ✅DO Edit `[记忆共享中心]/情境层/动态状态快照.md` → 在 META 层「最近变更摘要」
          表格末尾追加新行。格式严格遵守快照现有表结构（| 日期 | 工具 | 文件 | 说明 |）：
      `| MM-DD | {当前工具名} | 7/{日期}晚间复盘 | {番茄总数}🍅/睡眠{h}m/P1 {N}/
       {M}✅/评级{字母} |`
      ——原因是追加行让所有工具可追溯当日收盘数据，替代"全量唤醒时才写"的设计。
      示例：
      `| 07-10 | WorkBuddy | 7/10晚间复盘 | 8🍅/睡眠6h15m/P1 2/2✅/评级B |`
      🔌 熔断器：最近变更摘要段不存在（结构损坏）→ ⚠️标注，跳过，不阻塞

    7.5c. **📋 更新「核心文件健康」陈旧天数**
      ✅DO 结合步骤3.6（记忆冲突扫描）的TTL检测结果与今天日期，刷新
          「核心文件健康」表中各文件的陈旧天数。
          仅更新天数数字（如 CORE.md 从 74→78天），不更新版本号或判定状态。
      ——原因是天数由晚间复盘每日刷新，版本号/状态由全量唤醒综合判断，
      两者各司其职，晚间复盘只做"精确的一刀"（日期计算）。
      🔌 熔断器：核心文件健康段不存在 → ⚠️标注，跳过

    📦 **产出物**：快照已包含当日睡眠/能量/SHADOW + 最近变更摘要新行 + 核心天数刷新
    🔒 **校验锁**：Edit后Read回验：
      ① CONTEXTUAL层「今日能量」数据已含今日信息
      ② 「最近变更摘要」表格末行日期==今日
      ③ 头部时间戳已更新
      任一未通过→回溯修正后重验，不进入步骤8

8. **系统健康检查（快速）**：版本号一致性检查 + 路径唯一性检查。仅显示异常，不阻塞任务。
