# 工作流C：晚间复盘

> 触发词："复盘" / "今晚复盘" / "今日复盘" / "晚间总结" / "总结今天" / "今日总结"
> 此流程极其关键，必须按 1-8 顺序执行。P0铁律和监控标准常量见SKILL.md主文件。

---

1. **数据收集与补全**：读取今日日记。如发现睡眠数据、今日实际番茄数、情绪分数为空，主动向用户提问补齐。

   **🔒 内容创作/运动/读书数据采集（v3.30.0新增·接通成就数据源）**：检测今日是否有①内容发布动作（视频/文章/笔记发布——来源：今日系统日志"发布/上线"类条目、工作区产出、你陈述）②运动记录（日记正文/你陈述中"运动/跑步/健身/锻炼/球类"等）③**读书记录（你明确说"今天读了/读完了《某书》"才记——⛔拆书/读书笔记/知识池拆解不算·皮叔 2026-08-08 纠正"拆解≠阅读"）** → 有则写入日记 YAML `achievement_data.content_creation` / `exercise` / `books_read`（content_creation/exercise 为当日计数 int；**books_read 为当日读完的书名数组 `["《书名》"]`**），无则保持 0 / `[]`。⛔DO NOT 替你臆断发布/运动/读书事实——有可追溯证据才填，不确定时问你确认。目的是接通 content_creation/exercise/books_read 成就数据源（2026-08-01 审计发现：8档成就因字段缺失成"空成就"，模板 v2.1 已加字段；2026-08-08 读书成就数据源从知识池拆书改回日记 YAML books_read·基线9本+YAML增量）。

   **🔒 学习记录拉取（v3.14.0新增）**：Read 今日系统日志（[记忆共享中心]/工作日志/系统日志/系统日志_{YYYY-MM-DD}.md），检索类型为"学习"的条目。
     - 有学习条目 → 向用户展示："你今天用Loop学了[主题/轮次]，要记进今天的日记吗？"
       用户确认 → 写入日记「今日成就」区
       用户拒绝 → 不记录
     - 无学习条目 → 跳过
     ⛔DO NOT自动写入——原因是学习是否值得记由用户判断，系统不替用户决定。

2. **自动化脚本执行**：
   - **🔒 灵感闪现校验（v3.13.0 变更）**：灵感闪现行已由 `create_skeleton.py` 在创建次日骨架时自动注入。复盘时无需再做灵感提取，只需校验：
     - 今日日记的灵感闪现行存在且非占位符 → ✅ 正常（昨日脚本已注入）
     - 今日日记的灵感闪现行为 `{{灵感闪现_待填入}}` → ⚠️ 极rare（脚本现已始终产出真实金句：有库用库、无库回退随包名言池）。若仍出现，说明个人库与名言池均不可用，此时AI需补入：读取今日感悟关键词→匹配核心启发库（有库）或随包 `daily_quotes_cache.json` 名言池→原文照搬
     - 今日日记无灵感闪现行 → 🔴 异常（模板不一致），报错提醒
   - **今日感悟模块由用户亲自填写（内部记录）**：日记「5️⃣ 💡 今日感悟」模块是整个日记最核心的反思模块，**由用户本人填写**，AI 不代写、不代生成、不代概括。AI的工作仅限于：①检测感悟是否为空（门禁机制） ②提醒用户填写 ③等待用户提供感悟原文 ④将用户原文原样写入。感悟为空→后续流程全部锁死（见步骤4感悟门禁）。这一规则源于：感悟是使用者反思的产物，是日记最重要的模块，AI代写=剥夺反思=本末倒置。
   - **🔒 成就检测（强制，不可跳过）**：运行 `achievement_tracker.py --all`，若有新成就，准备写入日记并弹窗。
   - **💰 成就→代价反馈（v3.40.0新增·v4.0方案§七）**：检测到新成就（"🎉 成就解锁！"）时，拉取达成窗口（近 7 天）日记 YAML 的睡眠/能量数据，在**对话框**成就播报后追加代价行（弹窗为脚本 osascript 产物·AI 不修改弹窗本身）：
     ```
     🏆 {成就名} 达成
     ⚠️ 达成期间代价：{连续X天睡眠<7h / 深睡异常 / 能量持续走低}（数据源：近7天日记 YAML·⛔DO NOT凭记忆）
     ```
     ✅DO 有真实代价才标 ⚠️——无异常不强行标注（有才显示）；⛔DO NOT 编造代价数据；🔌 熔断器：日记数据缺失 → 跳过代价行，不阻塞成就。
     📡 哲学依据：成就只看荣耀不看代价=反馈闭环断裂（v4.0 方案§七："达成期间的睡眠代价"）
   - **⚠️ 非沙箱执行（关键）**：成就检测/更新两步须在**非沙箱**环境运行（`dangerouslyDisableSandbox: true`）。macOS 沙箱会拦截 `osascript` 对"系统事件"的 TCC 授权，导致解锁时**只响声音、不弹模态框**。非沙箱才能让用户亲手点 OK（仪式感）。脚本仅本地读写+弹窗，风险极低。
   - **⚠️ 成就模块边界提示（v3.7新增·防E5声明-执行gap）**：若需手填成就模块非脚本渲染行（如"本日新增达成"），✅DO 先读 `diary-template.md` §成就模块「刚性规则」——核心：边界隔离铁律（仅客观数据，不写主观感悟/情绪/评价）。铁律内容单一来源在 diary-template.md，本处仅指针不重复——原因是复盘走本 SOP 路径撞不到模板里的铁律，E5 gap 靠此指针补上。
   - **🔒 成就更新（强制，不可跳过）**：运行 `update_diary_achievement.py` 更新今日日记的成就模块。该脚本在写入成就块后**自动计算封口签名**（`review_sealed_sig` 写入日记 YAML frontmatter），签名基于当日 6 项真实成就数据 + 日期 → 确定性 SHA256 哈希。⛔DO NOT 手写 `review_sealed_sig` 字段——原因是只有脚本能基于真实成就数据产生合法签名；AI 手写的签名必然与 `verify_achievement_seal.py` 独立重算的结果不匹配 → 验证脚本必然拦截。
   - **🔒 成就校验（终检·代码级物理阻断）**：运行 `bash $SKILL_ROOT/scripts/dbbin.sh verify_achievement_seal.py`。exit 0 = 成就封口签名与当日真实数据一致 → ✅ 通过。exit≠0 = 成就检测未跑/被伪造/数据过期 → 🔴 物理阻断，必须回溯重跑步骤 2（成就检测+更新），不可进入步骤 3。此脚本替代旧版人工检查 diary_total——签名比对覆盖全部 6 项成就指标，不依赖 AI 自律。
   - **晋升扫描**：扫描成长箱（LEARNINGS.md/ERRORS.md），同类错误 ≥3 次且未 promote 时，提醒用户是否升格为规则。
   - **记忆层级TTL检测**：逐层检查最后更新时间，过期则提醒用户。检测清单见SKILL.md主文件的📅记忆层TTL规则表。
     **过期提醒**：按SKILL.md顶部📅记忆层TTL规则表执行

   - **灵感提取示例**（以下为脚本兜底时AI手动补入的流程示例）：

3. **数据一致性校验 (CoT 强制输出)**：⛔DO NOT 在 `verify_achievement_seal.py` exit≠0 时进入本步骤——前步验证未通过=成就未封口→须先回溯步骤2（接触法防误：步骤3入口依赖步骤2终检通过）。在生成最终内容前，必须在对话框输出检查清单（含数据一致性、格式完整性、假设验证三层校验），其中数据一致性校验必须包含 `achievement_data.json` 的 `diary_total` 已同步为当前实际篇数的确认项。不一致→回溯重跑。三层校验清单模板（输出时逐项勾选）：
- 数据一致性：`achievement_data.json` 的 `diary_total` == 当前实际篇数；睡眠/番茄/情绪数据取值自日记原文（空值留空）
- 格式完整性：12 SECTION 齐全 + HTML 注释标记保留 + 版本号声明已输出
- 假设验证：复盘取值自"实际完成区"而非"早晨计划区"；无编造数据

   📦 **产出物**：SHADOW.md 新记录已写入（如有新偏差/矛盾），且含合法「认知象限」字段（默认未知已知；正向行为已知已知）；常规偏差不写SHADOW.md

7. **🔄 记忆层联动（日报）**：晚间复盘提交前，自动同步到多个记忆层（L4情境层/L5潜意识层/日志归档/成就证据）。

   📦 **产出物**（本步合计）：快照「当前情境」段已同步今日里程碑变更

   Poka-Yoke定值法防误——字段存在=数据可靠，无需AI判断"这个算不算变更"

   7a. **📊 里程碑反哺快照**：读取今日日记`📊 项目里程碑`字段，有变更则同步动态状态快照。
      ✅DO Read日记`📊 项目里程碑` → 提取项目名+最新状态+变更日期（表中有非空行才执行）
      ✅DO 触发词"发布"需确认上下文——后接名词（发布包/发布版/发布会）不算，后接无名词/已完成词（已发布/发布了）才算状态变更
      ⛔DO NOT：复合词内的"发布"（如"发布包""发布版"）不算状态变更——原因是复合词中的"发布"是名词成分，不是动词，"发布包修正" ≠ "项目已发布"
      ✅DO Write `[记忆共享中心]/情境层/动态状态快照.md`（Read原文→更新「当前情境」段对应项目状态→整文件Write）。格式：写入"🎉 [{项目} {状态}✅]"
      ✅DO 更新快照头部"最后更新"时间戳
      无变更（字段为空/所有行均为"—"）→ 跳过
      🔌 熔断器：快照文件不可读 → 标注⚠️快照同步延迟，不阻塞复盘
      🔌 熔断器：Write并发冲突（Write前Read与首次Read不一致，如其他人同时写入）→ 标注⚠️写入冲突，次轮重试

7.5. 🗺️ **快照每日情境刷新（v3.16.0新增——设计端防误：把快照更新焊进必然发生的晚间复盘，不再依赖偶发的全量唤醒）**

    > 设计意图：快照的 CONTEXTUAL 层（睡眠/能量/SHADOW）和 META 层（最近变更摘要/
    > 核心文件健康）此前仅在唤醒记忆系统全量模式步骤3c时更新。全量唤醒是
    > 偶发事件（07-02→07-10六天空窗），导致轻量模式读到过期数据。本步将这
    > 三个段的更新并入每日晚间复盘，让快照始终持有当天数据。
    > 原理：防误（设计端消除）> 防错（检查端发现）——加告警说"快照过期了"
    > 不如让快照不会过期。

    ⛔DO NOT 更新「当前情境」段（项目里程碑/战略目标等长期内容）——那是
      步骤7a的领地，本步只刷短期情境数据和 META 层元数据。

    7.5a. **📊 刷新CONTEXTUAL层：睡眠+能量+SHADOW**
      ✅DO 从今日日记关键表/数据摘要中读取：入睡时间/起床时间/夜眠时长/
          补眠时长/番茄总数/情绪分数/SHADOW偏差项（步骤1+3.5+4a已提供）。
      ✅DO Write `[记忆共享中心]/情境层/动态状态快照.md`（Read原文→按下述更新→整文件Write）：
        1. `- **今日能量**：` 行 — 替换为今日最新数据（含番茄数+评级）
        2. `- **SHADOW状态**：` 段落 — 追加今日偏差记录在段落末尾
           （SHADOW 段落是追加式记录，保留前几日数据，新增的放最后。
            格式与现有 SHADOW 段一致：「{日期}入睡{时间}🔴/...」）
        3. 头部 `最后更新：YYYY-MM-DD HH:MM` — 更新为当前时间戳
      🔌 熔断器：快照文件Read失败 → ⚠️标注"快照同步延迟"，不阻塞复盘
      🔌 熔断器：目标行不存在（结构变更导致原行消失·Write定位失败）→ ⚠️标注"快照字段不匹配"

    7.5b. **📋 追加「最近变更摘要」行**
      ✅DO Write `[记忆共享中心]/情境层/动态状态快照.md` → 在 META 层「最近变更摘要」（Read原文→追加后整文件Write）
          表格末尾追加新行。格式严格遵守快照现有表结构（| 日期 | 工具 | 文件 | 说明 |）：
      `| MM-DD | {当前工具名} | 7/{日期}晚间复盘 | {番茄总数}🍅/睡眠{h}m/P1 {N}/
       {M}✅/评级{字母} |`
      ——原因是追加行让所有工具可追溯当日收盘数据，替代"全量唤醒时才写"的设计。
      示例：
      `| 07-10 | WorkBuddy | 7/10晚间复盘 | 8🍅/睡眠6h15m/P1 2/2✅/评级B |`
      🔌 熔断器：最近变更摘要段不存在（结构损坏）→ ⚠️标注，跳过，不阻塞

    7.5c. **📋 更新「核心文件健康」陈旧天数**
      ✅DO 结合步骤3.6（记忆冲突扫描）的TTL检测结果与今天日期，刷新
          「核心文件健康」表中各文件的陈旧天数。
          仅更新天数数字（如 CORE.md 从 74→78天），不更新版本号或判定状态。
      ——原因是天数由晚间复盘每日刷新，版本号/状态由全量唤醒综合判断，
      两者各司其职，晚间复盘只做"精确的一刀"（日期计算）。
      🔌 熔断器：核心文件健康段不存在 → ⚠️标注，跳过

    📦 **产出物**：快照已包含当日睡眠/能量/SHADOW + 最近变更摘要新行 + 核心天数刷新
    🔒 **校验锁**：Write后Read回验：
      ① CONTEXTUAL层「今日能量」数据已含今日信息
      ② 「最近变更摘要」表格末行日期==今日
      ③ 头部时间戳已更新
      任一未通过→回溯修正后重验，不进入步骤8

9. **📋 复盘对话最终输出格式规范（v3.51.0新增·皮叔 2026-09-21 定版·手机端快速阅读友好）**：

   > **定位**：本步骤定义日记封口完成后，AI在对话中给用户的最终总结格式。目的是让用户躺在床上用手机也能快速看完当天复盘，不用再点源文件。
   > **设计原则**：分块呈现、信息密度高、有才显示、无则省略——用户扫一眼就知道今天记了什么。

   9.1 **✅DO 必须按以下8个模块顺序输出，缺任一模块=回复不完整**：

   | 序号 | 模块名 | 内容要求 | 有才显示规则 |
   |:---:|--------|---------|------------|
   | 1 | 📅 年度进度 | 进度条（`██████████████░░░░░░`格式）+ 百分比 + Day X/365 | 始终显示 |
   | 2 | 🏅 今日评级 | A/B/C/S级 + 一句话理由（P1完成率+番茄数+核心亮点） | 始终显示 |
   | 3 | ⏱️ 今日数据 | 表格：番茄（计划/实际/完成率）、心情指数（预计/实际）、睡眠（总时长+一句话评价） | 始终显示 |
   | 4 | 💼 今日工作 | 上午/下午分别做了什么，每项标注番茄数 | 始终显示 |
   | 5 | 💡 今日感悟 | 当天的核心感悟，最多3条，每条一句话 | 始终显示（感悟是日记核心） |
   | 6 | 🧠 今日新增概念卡 | 每张卡一句话摘要（格式：`**C-XXX 概念名**：一句话摘要`） | **有才显示，无卡则整块省略**——原因是无卡时显示"今日无新概念"是信息噪声，用户不需要知道"没有" |
   | 7 | 🦞 每日伙伴建议 | 三段式：👁️我看见的 / ❓我想问的 / 📌需关注 + 💡灵感就位 + 署名 | 始终显示（伙伴建议是日记的灵魂收尾） |
   | 8 | 🎯 明日目标 | 3件核心P1任务，每件一句话 | 始终显示 |

   9.2 **🔒 概念卡摘要格式铁律**：
   - ✅DO 每张概念卡浓缩成**一句话**，不超过30字——原因是用户要的是"知道记了什么"，不是完整定义，完整定义在卡片文件里
   - ✅DO 格式统一为：`**C-XXX 概念名**：一句话摘要`
   - ⛔DO NOT 把完整definition抄过来——原因是完整定义太长，手机端一屏看不完，失去"快速摘要"的意义
   - ⛔DO NOT 只给卡片编号不给内容——原因是编号需用户自己跳文件，一句话摘要才是真可见（对齐步骤5.5e"只给编号不算"铁律）

   9.3 **🔒 成就显示规则**：
   - ✅DO 当天有新成就解锁时，在「🏅 今日评级」模块后追加一行：`🏆 新成就解锁：{成就名}`
   - ⛔DO NOT 无成就时显示"今日无新成就"——原因是"没有成就"不是用户需要知道的信息，有才显示、无则省略（对齐日记模板"有才显示铁律"）

   9.4 **🔒 格式防错（Poka-Yoke设计端）**：
   - ✅DO 每个模块用emoji+加粗标题开头，视觉上一眼能区分模块
   - ✅DO 模块之间用`---`分隔线隔开，手机端滑动时视觉清晰
   - ⛔DO NOT 把多个模块合并成一大段文字——原因是大段文字手机端阅读体验差，分块才是"快速阅读友好"
   - ⛔DO NOT 在最终总结里重复封口确认块（步骤6.4）的内容——原因是封口确认块是给AI自己校验用的，用户要的是"今天记了什么"的摘要，不是技术确认信息

   📦 **产出物**：对话已输出符合本规范的8模块复盘总结（概念卡/成就按有才显示规则省略）
   🔒 **校验锁**：输出前自查①8模块齐全（概念卡/成就按规则省略不算缺）②概念卡每张一句话≤30字③模块间有分隔线④无重复封口确认块内容；不通过→修正后再输出
