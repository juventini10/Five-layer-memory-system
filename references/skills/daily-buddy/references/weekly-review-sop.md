### 📊 工作流 E：周报生成 (Trigger: "生成周报" / "周报时间")

> 📋 **呈现规范见 `weekly-review-spec.md`**（模块结构/双声部/本周快照/进度条/YAML 铁律/S级回链/重要轴时间分配）。本 SOP 只管生成流程（HOW），呈现细节（WHAT）以 spec 为准。

1. **数据采集**：读取最近 7 天日记（周一到周日），提取睡眠数据、工作事项、番茄数据。**（📚阅读足迹·v1.2新增）** 同步 grep 7天日记中"读了《X》"明确记载 → 收集本周阅读书单（⛔排除仅AI蒸馏未在日记记录的书）；与知识池核对每本 `reading_status` 是否已升 L2+。无任何阅读记载 → 跳过，不采集。详见 spec §4.5。
2. **情景层读取**：读取 `[记忆共享中心]/情境层/动态状态快照.md`，提取90天北极星目标、当前卡点、上周紧急任务等信息。
3. **月报目标读取（v2.0新增）**：读取当月月报的「下月3件事」模块（路径：`~/Local_Obsidian_Vault/1-每日计划/03-月报/YYYY-MM-月总结.md` → 8️⃣ 下月3件事），提取本月量化目标和周分解建议。月报不存在 → 标注"月报缺失，本周计划为自列任务"，跳过月目标对齐模块。
4. **成就更新**：运行 `achievement_tracker.py --all`，获取本周新增成就。
5. **生成周报**，保存到 `{{OBSIDIAN_VAULT}}/1-每日计划/02-周报/2026-WXX-周报.md`：
   > ⚠️ **YAML硬约束（v2.1新增）**：文件头必须包含 YAML front matter（精简集，对齐 spec §4.1 / 文件格式规范 v2.2.0 分层）：必留 `rating`/`summary`/`date`/`type`/`source`/`complies_with` + `author: 皮叔`；建议 `title`/`tags`。⛔DO NOT 把正文数据（rating_reason/番茄/睡眠/里程碑/blockers/shadow_new_count 等）塞 YAML=双本账。YAML 缺失核心字段 = 质量检查不通过。
   > 📌 **author 规范（v1.0新增）**：YAML 须含 `author: 皮叔`（默认，⛔DO NOT 写「你」），对齐月报规范。
   > 📌 **S级回链（v1.0新增）**：周报整体评级仅 A/B/C（S 属月报维度，一周无法验证）；但含金量模块须从7天 YAML 提取 rating 分布并 SURFACE 含 S 天（回链 `S级顿悟总记录 #X`），不计入周评。回链覆盖申报S+校准升S，周报内不内联来源。详见 spec §1 S级处理铁律。
   > ⚠️ **标题硬约束（v2.1新增）**：标题格式 `## 2026-WXX 周报（M/DD-M/DD）`（H2·⛔DO NOT H1，对齐 spec §4.1 / 文件格式规范禁 H1），日期范围缺失 = 标题不完整。
   - 📌 月目标对齐（从月报「下月3件事」分解本周应交付+累计进度）
   - 🎯 核心概览（**整体评级**+关键指标+本周亮点+本周挑战）
   - 1️⃣ 进度追踪板块（每日进度明细、核心项目进度）
   - 2️⃣ 数据分析板块（番茄效率趋势、睡眠健康分析、内容产出分析、**📚阅读足迹**——按 spec §4.5：仅列日记明确记载"读了《X》"且核对 reading_status，已升级 L2+ 附✅，未升级附"建议本周期再温"；无语义价值判断，仅足迹呈现）
   - 3️⃣ 问题与解决方案（问题、根因、解决方案）
   - 4️⃣ 90天目标对齐（上周行动与90天目标的关系、进度评估）
   - 5️⃣ 情景层卡点跟进（当前卡点进展、解决方案）
   - 6️⃣ 上周计划完成情况（对照上周月目标对齐模块的周分解，逐条检查交付）
   - 7️⃣ 本周计划 + 伙伴建议（本周计划从月目标分解而来·不自列；伙伴建议=数据洞察/行动建议/重点关注/关怀语/署名）
   > 📌 **伙伴建议署名铁律（v3.48.0新增·可追溯源头）**：伙伴建议模块末尾必须署名，格式 `—— {实际执行端署名}`（如 `—— 你的 豆包 🍵`）。署名从 `references/platform-paths.md` 多端署名库取，⛔DO NOT 用"每日伙伴"作为署名——每日伙伴是Skill名，不是执行端。原因：8月月报实证——豆包办公端执行但署名"每日伙伴"，无法追溯源头。署名=执行端，确保看系统日志就能确认是哪个端做的。
   > 📌 **模块排序铁律（v1.1新增）**：本周计划+伙伴建议(7️⃣) 是「下周行动指令」，✅DO 置底输出（排在 6️⃣ 上周计划完成情况 之后）；📌 月目标对齐 置顶（context）。编号连续 1️⃣-7️⃣（⛔DO NOT 跳号·对齐日报编号教训）。详见 spec §1。
   > 📌 **根因分析铁律（v1.0新增）**：3️⃣ 问题与解决方案 须用 `① **小标题**——说明` 格式 + 必带「落地动作表」（根源/动作/怎么执行），无动作=没分析。详见 spec §3。
   > 📌 **🧬 概念层快览模块（v3.32.0新增·L3方案S7·皮叔 2026-08-05"累积要有产出"）**：周报 7️⃣ 伙伴建议 前插入「🧬 本周概念层快览」小节（消费节拍·自动触发不依赖你手动）：
   >   - ✅DO Read `[记忆共享中心]/脚本中心/知识联邦引擎/log.md` 统计本周 ingest 新增概念数（周一起逐日 `新增N概念` 求和）；Read `collision_candidates.json` 统计 `status=pending` 候选数 + `total_concepts`。
   >   - ✅DO 同步统计 `[记忆共享中心]/最伟大的我/认知发现/` 目录下本周新增的 `.md` 文件数（v3.51.0新增·2026-10-07反哺）——认知发现是另一套产出通道（其他端在实战中产出的高价值认知文档），不算在概念卡数里，但你应该看到。
   >   - ✅DO 输出 Top3 pending 碰撞候选（按 effective_sim 降序，每条附：配对卡名×配对卡名 + 相似度 + 跨域/跨主体标记）——这是给你的"本周可开采的认知机会"清单，你可回复"去碰 C-XXX×C-YYY"走 good-good-study 池2 消费闭环（洞见卡带「碰撞来源」+ 回写 consumed）。
   >   - ✅DO 呈报消费健康：`本周新卡 X / 认知发现 Y篇 / 本周消费 Z（碰撞洞见卡+重蒸完成数） / 当前 pending W`——连续 2 周 `新卡>消费` 或 `pending>50` → 输出 ⚠️ 提示"概念库只进不出，建议本周主动消费一次（学/碰/蒸）"。
   >   - ⛔DO NOT 只报数不呈现候选——原因是消费节拍的价值=把候选顶到你面前，光有统计=健康仪表无输出（皮叔 2026-08-05"抽取了要告诉我记录了什么，结果要呈现"）。
   >   - 🔌 熔断器：log.md/collision_candidates.json 缺失或不可读 → ⚠️标注"概念层数据不可用"，不阻塞周报生成。

   > **📋 评级标准（v2.0新增·结果导向+健康天花板）**：
   >
   > | 评级 | 健康关（硬约束） | 执行关（结果导向） |
   > |:---:|---------|---------|
   > | **A** | 睡眠≥4/7天达标 | 本周承诺交付物≥70%完成 |
   > | **B** | 睡眠≥2/7天达标 | 有明确产出（至少1项交付物完成） |
   > | **C** | 睡眠≤1/7天 或 2天+<5h | **健康关不过 = 直接C** |
   > | **C** | 任意 | 交付物大部分未完成 |
   >
   > 流程：先过健康关 → 再过执行关 → 综合定级。番茄数是效率参考，不进评级。
   > 周报整体评级无S级——S级是"重大里程碑"判断，属于月报维度（需月报层验证）；但周报含金量模块须 SURFACE 含S天并回链总记录（见上方 S级回链铁律）。

6. **🧠 认知校准快照（v4.0新增）**：Read `[记忆共享中心]/记忆蓝图/01_思维方法论/认知边界探测协议.md`，对本周日记做二阶模式扫描：
   - P1完成率稳定性（均值+方差+趋势）
   - 能量预判偏差（高估/低估次数+方向）
   - 宣言vs行为矛盾（本周≥3天的系统性偏差）
   - 归因模式（成功时归因于X，失败时归因于Y——是否一致）
   - 框架效应信号（某模块本周完全空白）
   - 输出为 📊 认知校准快照表
7. **终检收口（脚本物理拦截·v1.3新增·2026-09-11 收口·T0根治对齐月报 v3.46.0）**：
   a. **完整性自检**：确认 7 天数据已完整读取、睡眠数据至少 4 天、KPI 已计算、YAML 精简集完整（rating/summary/date/type/source/complies_with/author·见 spec §4.1）、标题含日期范围。
      > ⚠️ 强制约束：严格按列出的模块生成（含📌月目标对齐+🎯核心概览含整体评级），不得遗漏或擅自增加。YAML 缺失或标题无日期 = 不通过。
   b. **脚本物理收口**：运行 `bash $SKILL_ROOT/scripts/dbbin.sh finalize_report.py --type weekly --week 2026-WXX`（脚本校验周报11模块完整性·exit 0=通过）。
      > ⚠️ **exit≠0 = 拒收周报**——按 stderr 提示补齐缺失模块后重新收口，⛔DO NOT 在校验未通过时输出周报。原因：AI 自检清单可被绕过（8月月报实证·第6.5步五容器缺4个终检未拦截），脚本物理拦截是防误层（设计端），AI 自检是防错层（检查端），防误>防错。与月报 T0根治同构（接触法防误：不调脚本=拿不到确认JSON=周报完整性锁不通过）。
8. **情景层更新**：基于周报内容，更新 `[记忆共享中心]/情境层/动态状态快照.md`：
   - **当前卡点**：从"情景层卡点跟进"模块提取
   - **本周紧急任务**：从"本周计划"模块提取紧急程度为高的任务
   - **上周进展**：从"上周计划完成情况"模块提取
   - **目标进度**：从"90天目标对齐"模块提取
9. **🔄 记忆层联动（周报）**：周报生成并提交后，同步到多个记忆层：
  - **L4 情境层**（动态状态快照.md）：
    - 读取 `[记忆共享中心]/情境层/动态状态快照.md`
     - 更新字段：**当前卡点**、**本周紧急**、**上周进展**（1-2句）、**目标进度**（百分比+说明）
     - 检查 L4 TTL：按📅TTL规则表执行过期检测
   - **L2 认知层**（用户基本规则-摘要版 认知层段）：
     - 从周报中识别本周是否出现**决策模式变化**（如：反复在同一类任务上拖延/同一类决策连续偏差）
     - 如发现 → 在认知模式段的"行为观察记录区"追加1句本周观察（不超过30字）
     - 如无显著变化 → 跳过，不强制写
   - **L3 行为层**（用户基本规则-摘要版 行为层段）：
     - 从7天日记数据识别**习惯漂移信号**（阈值见顶部📏标准常量表）：
       - 连续3天+ 睡眠不达标（时长<7h 或 入睡>23:30）
       - 连续3天+ 工作日番茄数 < 16
       - 连续3天+ 同一类型P1任务未完成
     - 如检测到任一信号 → 在行为模式段追加漂移标记和触发条件
   - **L5 潜意识层**（SHADOW.md 周审计）：
     - 读取 `[记忆共享中心]/潜意识层/SHADOW.md`，统计本周新增条目数
     - **条目数 ≥ 3 条** → 在周报"每周伙伴建议"中追加一条SHADOW提醒："本周有{N}条言行矛盾记录，建议回顾一下是否有深层原因"
     - **连续2周 ≥ 2 条** → 提升提醒强度，建议安排一次SHADOW复盘对话
     - 本周无新条目 → 静默，不提
   - **日志归档**：追加到当日日志文件，标记为 `[周报联动]`
