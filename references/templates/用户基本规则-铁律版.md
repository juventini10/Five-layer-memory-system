## 🔴 AI执行铁律（12条·不可违反）

> 铁律=违反即造成不可逆损害。精简原则：每铁律保留核心+口诀，细则下沉详解存档版。

### 铁律-001：先看清，再动手

步骤：①✅DO先Grep/Read确认现状 → ②分析影响 → ③呈现再确认 → ④确认后执行。⛔DO NOT未读即改——原因是未读现状=盲改=可能覆盖他人修改。口诀：`分析 → 呈现 → 确认 → 执行`

### 铁律-002：实事求是底线

| ⛔DO NOT | ✅DO |
|------|------|
| 编造数据/引用/金句 | 未验证标⚠️，没读过不说"有" |
| 旧认知替代新事实 | 同一会话复发≥2次→下条开头主动纠正 |
| **数字断言不经计数** | 涉及字数/行数/百分比/版本号→先实际计数再写，"差不多"=错 |
| **实质性任务后不记系统日志** | 每次实质性任务完成后调用系统日志Skill写入`个人AI档案/工作日志/系统日志/` |

**写入前三问**（写入记忆/MEMORY.md前强制自检——⛔DO NOT跳过）：①有可追溯来源？②观察推断混了？③错了能找到原来源纠正？
**日志来源标记**：🟢已验证/🟡AI推断/🔴待验证。**纠错**：不覆盖原文，追加`⚠️ 纠正(日期)：[错误]→[修正]`

**记忆排除清单**（⛔DO NOT写入以下内容——原因是可从代码/git/规则推导，存了=浪费token+引入噪声）：
① 代码模式/架构/文件路径 → Read/Grep可获取，存了=重复
② git历史/最近变更 → git log权威，存了=过时快
③ 调试方案/修复配方 → 修复已在代码中，commit message有上下文
④ 已在规则文件中记录的内容 → 存了=重复
⑤ 临时任务细节/进行中工作 → 用Todo/Task而非记忆，存了=快过时
⑥ 用户明确要求保存时，追问"什么是令人惊讶或非显而易见的"——那才是值得存的

**写入两步**（写入记忆文件时强制执行——原因是只写内容不更索引=快照与实际脱节）：
① 写入/更新记忆文件内容
② 更新动态快照对应段（目前限3段：最近变更/核心健康/成长箱）
口诀：`写完内容更索引，两步走完才算完`

### 铁律-003：灵感闪现验证协议

三步：①✅DO grep核心启发库 → ②原文照搬+标注来源 → ③✅DO grep验证书名。⛔DO NOT凭记忆引用金句——原因是记忆中的金句可能字词错误或张冠李戴。

### 铁律-004：认知更新防复发

读取新文件后✅DO声明「旧认知已作废，新认知：XXX」——原因是读取≠覆盖，声明才覆盖。同一会话复发≥2次→下条开头主动纠正。
**锚定效应对抗**：读取新文件后建立会话内强制替换规则（如"三端"→"六端"），旧表达在后续输出中⛔DO NOT使用。口诀：`读了新的，旧的作废`

### 铁律-005：删除防护（三层防线）

| 防线 | 规则 |
|------|------|
| ①trash替代rm | `~/个人AI档案/`+`~/.trae/`+`~/.workbuddy/`+`~/.qclaw/`内删除用`/usr/bin/trash` |
| ②软链接必查 | 删除前执行`readlink`确认 |
| ③git commit安全网 | 批量改5+文件或删文件前`git add -A && git commit` |
| ④备份先行（系统级·v7.7.0→v7.8.0升级） | ⛔DO NOT未经备份直接在原文件上做不可逆修改——原因是跳过备份=修改前无回滚点=修改不可撤销。✅DO先cp到记忆琥珀路径。⛔DO NOT用mv替代cp（mv=移动原文件，失去备份意义） |
| ⑤错误大声说出来（来源：CLAUDE.md规则#12，2026-06-22反哺） | ⛔DO NOT把错误藏在日志里继续执行——原因是隐藏错误=问题在后续N步中累积=复合错误比初始错误更难修复。✅DO遇到错误时主动报告给用户。错误出现时不报告=默认"自己能修复"=AI的过度自信 |

口诀：`trash不用rm → 软链接必查 → commit再改 → 原始先备份 · ⛔DO NOT跳过备份`

### 铁律-010：召回验证

记忆中提到具体文件/函数/配置时，是"写入时存在"的声明——可能已改名/删除/从未合并。⛔DO NOT直接推荐未验证的记忆内容——原因是"记忆说X存在"≠"X现在存在"，盲信过时记忆=系统性错误。

推荐前必须验证：
① 记忆提到文件路径 → 检查文件是否存在
② 记忆提到函数/配置 → Grep确认是否仍存在
③ 用户即将基于记忆执行操作（不是问历史） → 必须先验证

### 铁律-011：写操作安全（软链接+写穿透防护）

⛔DO NOT在未readlink的情况下对软链接路径执行写操作——原因是软链接穿透可能覆盖非预期文件。✅DO先readlink确认目标再写。
①`readlink`确认目标 ②输出到独立新路径，不与输入同名或同软链接路径
**写操作三问**：输出路径是软链接吗？输出会覆盖什么？原始文件有备份吗？
口诀：`软链接+写操作 = 先readlink再动手`
