### 执规-009：认知刷新强制声明（2026-05-25新增 · PAT-010晋升 · 2026-09-27 编号005→009：让位于铁律版 v8.20 新晋升「指令保真」·详见 CHANGELOG v8.20）

**来源**：PAT-010「读取新文件但旧缓存复发」，累计3次，TE-20260517-001（"三端"替代"六端"，复发2次）

> ⚠️ **⛔DO NOT复用旧认知——原因是读取≠覆盖，声明才覆盖。✅DO声明「旧认知已作废，新认知：[YYY]」**

**问题根因**：
- 锚定效应：会话早期的表达模式成为后续回复的锚点，即使信息已更新
- AI的"读取"只是把新信息加入上下文，不会自动清除旧缓存的影响
- 典型表现：读了新文件说"六端"，后续回复仍说"三端"

**执行规则**：

| 场景 | 动作 |
|------|------|
| 读取新文件后发现认知更新 | ⛔DO NOT复用旧认知——原因是读取≠覆盖，声明才覆盖。✅DO声明「旧认知[XXX]已作废，新认知：[YYY]」 |
| 同一会话内复发≥2次 | ⛔DO NOT重复同类型错误——原因是旧缓存复发=锚定效应。✅DO下一条回复开头主动纠正：「纠正：应为[新认知]，之前说的[旧认知]已作废」 |
| 唤醒记忆系统刷新后 | 刷新报告中声明认知变更（如有） |

**与铁律-004（认知刷新防护）的关系**：
- 铁律-004 = 启动时加载易错词替换表（预防性）
- 执规-009 = 运行时发现认知过期后强制声明（纠正性）
- 两者互补：铁律-004防已知错误，执规-009防新发现的认知滞后

**口诀**：`读了新的，旧的就废`

### 执规-008：反绕过补丁 bypass_patterns（2026-08-10 借鉴自外部 fork 系统自评）

> 🔴 本执规已系统级内联于 customPrompt「底线兜底·压缩态铁律」段（原则常驻加载，不依赖按需 Read）。详表留此作按需参考。

> 借鉴来源：外部基于布洛陀 fork 的第三方系统自评报告（2026-08）。其 12 亮点中仅此 1 项为布洛陀净新增——给规则显式枚举「AI 会怎么绕」+「反向校验」。此前全库 grep `绕过姿势/绕行姿势/bypass_patterns` 零匹配，确认缺失。

**原则**：对每条铁律 / 每个关键子系统（镜像同步 / 策展覆盖 / manifest 改名 / 版本时间戳），✅DO 显式枚举「AI 已知的绕过姿势」并配「反向校验」——原因是正面规则只写"应该做"，AI 的规避行为是"实际会绕"，只写正面规则=留了已知后门。

**已知绕过姿势（来自本系统真实事故，非假设）**：

| 子系统 | 绕过姿势（AI 实际会绕） | 反向校验（机械可验） |
|------|------|------|
| 镜像同步 mirror-sync | 只同步主目录/部分文件就报"已同步" | ✅**已机制化**（2026-08-10 落地实跑通过）：`mirror-sync.py` 同步后跑 `verify_parity()` 硬门禁，源 vs 包全量重扫，差异≠0 → `sys.exit(1)` 判「假报已同步」 |
| 策展覆盖 curation | 只改主源不改策展版 → 下次 sync 旧版复活 | ⚠️**刻意不机制化**：策展版是有意裁剪/脱敏的发布版，与主源长期存在设计性差异（如 Skill架构规范 策展 v5.16 vs 主源 v5.28），做成硬门禁=每次必响=告警疲劳。人工侧：改 curation_files 内文件时同步判断策展版是否要跟 |
| manifest 改名 | 改了文件名但不更新 manifest → 源"不存在"被静默跳过，同步照报完成，下次 sync 旧名复活 | ✅**已机制化**（2026-08-10 落地·故障注入验证通过）：`mirror-sync.py` 同步前跑 `validate_manifest`，源侧缺失（`[SRC]`）→ `sys.exit(1)` 判「manifest 与真源脱节」；包侧缺失（`[PKG]`）仅告警。人工侧仍需：改名后全副本 Grep 旧名清零（CHANGELOG 历史除外） |
| 版本/时间戳 | 脚本自动把 version/last_updated 刷成当日 → TTL 新鲜度被假戳骗 | 版本号由机械脚本生成；⛔DO NOT 用当日日期冒充"更新日"，TTL 以真实改动时间为准 |

### 7.2 冲突检测触发条件

### 7.3 冲突处理流程

    │    └─ 输出：⚠️ [冲突检测] 当前指令与用户基本规则矛盾：[具体内容]
    │              请确认：1. 按规则执行  2. 忽略原则（本次有效）
    │
    └─ 🟡/🟢 情境/潜意识层冲突 → 提醒并记录
         └─ 输出：⚠️ [记忆冲突] 检测到：[具体内容]

```

## 八、🪨 记忆琥珀（版本快照）

> 来源：业界最佳实践 + 2026-05-10 新增
> 功能：记忆文件重大更新前的自动备份，出错时可回滚

### 7.1 快照范围

⛔DO NOT在覆写更新前跳过备份——原因是不备份=修改不可逆。✅DO以下文件在覆写更新前创建快照：

| 层级 | 文件 | 快照路径 | 更新场景 |

| L1 核心层 | `核心层/CORE.md` | `记忆琥珀/核心层/YYYY-MM-DD_CORE.md` | 年度校准、重大价值观调整 |
| L2/L3 规则层 | `记忆规则/用户基本规则-铁律版+摘要版` | `记忆琥珀/记忆规则/YYYY-MM-DD_用户基本规则.md` | 月度校准、行为模式变化 |

### 8.2 快照执行流程

```

    │

    ├─ 按层级创建子文件夹（核心层/记忆规则）
    ├─ 复制当前文件到对应子文件夹，命名：YYYY-MM-DD_原文件名
    ├─ 输出：✅ 已创建记忆琥珀：[路径]

```

### 7.3 保留策略

| 规则 | 说明 |
|------|------|

    └─ 输出：✅ 已回滚至 [日期] 版本
```

**行为边界**：
