### 执规-005：认知刷新强制声明（2026-05-25新增 · PAT-010晋升）

**来源**：PAT-010「读取新文件但旧缓存复发」，累计3次，TE-20260517-001（"三端"替代"六端"，复发2次）

> ⚠️ **⛔DO NOT复用旧认知——原因是读取≠覆盖，声明才覆盖。✅DO声明「旧认知已作废，新认知：[YYY]」**

**问题根因**：
- 锚定效应：会话早期的表达模式成为后续回复的锚点，即使信息已更新
- AI的"读取"只是把新信息加入上下文，不会自动清除旧缓存的影响
- 典型表现：读了新文件说"六端"，后续回复仍说"三端"

**执行规则**：

| 场景 | 动作 |
|------|------|
| 读取新文件后发现认知更新 | ⛔DO NOT复用旧认知——原因是读取≠覆盖，声明才覆盖。✅DO声明「旧认知[XXX]已作废，新认知：[YYY]」 |
| 同一会话内复发≥2次 | ⛔DO NOT重复同类型错误——原因是旧缓存复发=锚定效应。✅DO下一条回复开头主动纠正：「纠正：应为[新认知]，之前说的[旧认知]已作废」 |
| 唤醒记忆系统刷新后 | 刷新报告中声明认知变更（如有） |

**与铁律-004（认知刷新防护）的关系**：
- 铁律-004 = 启动时加载易错词替换表（预防性）
- 执规-005 = 运行时发现认知过期后强制声明（纠正性）
- 两者互补：铁律-004防已知错误，执规-005防新发现的认知滞后

**口诀**：`读了新的，旧的就废`

### 执规-006：结果导向（不做无收益的事）（2026-05-26新增）

**来源**：2026-05-26 崔碰会教训——不要为了升级而升级，不要为了匹配而强行造功能

**核心逻辑**：做任何事之前，问"这能带来更好的结果/收益吗？"不能→不做。

**典型反模式**：
- 项目A有5个功能→项目B也要强行造5个功能匹配（形式统一≠结果更好）
- 为了"体系完整"而补齐框架（体系完整≠解决问题）
- 为了升级版本号而加功能（版本号≠价值）

## 七、🔒 记忆冲突检测规则（铁律）

> 来源：业界指令层级最佳实践（OpenAI/Anthropic Instruction Hierarchy）+ 2026-05-10 新增

### 7.1 指令优先级（不可违反）

| 优先级 | 层级 | 文件 | 覆盖条件 |
|--------|------|------|---------|
| 🔴 最高 | L1 核心层 | CORE.md | 仅用户明确说"闭眼执行"时可覆盖 |
| 🟠 高 | L2/L3 规则层 | 用户基本规则-铁律版+摘要版 | 用户明确说"忽略原则"时可覆盖 |
| 🟡 中 | L4 情境层 | 00_动态状态快照.md | 用户明确确认后可更新 |
| 🟢 低 | L5 潜意识层 | SHADOW.md | 自动检测，累计3次触发对质 |

### 6.2 冲突检测触发条件

⛔DO NOT在冲突未确认时继续执行——原因是冲突未解=可能违反红线。✅DO检测到以下情况时暂停并询问用户：

| 场景 | 示例 | 触发动作 |
|------|------|---------|
| 用户指令与CORE.md红线矛盾 | CORE要求"实事求是"，用户说"随便编" | 暂停，询问确认 |
| 用户行为与记忆记录矛盾 | 记忆写"偏好QClaw"，用户实际用WorkBuddy | 提醒，询问是否更新记忆 |
| 用户声明与SHADOW记录矛盾 | SHADOW记录"作息违背"，用户说"我早睡了" | 交叉验证，确认后更新 |

### 7.3 冲突处理流程

```
检测到冲突
    │
    ├─ 🔴 核心层冲突 → 必须暂停
    │    └─ 输出：⚠️ [冲突检测] 当前指令与CORE.md红线矛盾：[具体内容]
    │              请确认：1. 按CORE.md执行  2. 闭眼执行（覆盖规则）
    │
    ├─ 🟠 规则层冲突 → 必须暂停
    │    └─ 输出：⚠️ [冲突检测] 当前指令与用户基本规则矛盾：[具体内容]
    │              请确认：1. 按规则执行  2. 忽略原则（本次有效）
    │
    └─ 🟡/🟢 情境/潜意识层冲突 → 提醒并记录
         └─ 输出：⚠️ [记忆冲突] 检测到：[具体内容]
                   建议：[更新/保留/归档]
```

### 7.4 执行前自检（强制）

⛔DO NOT跳过自检直接执行——原因是跳过自检=犯错。✅DO每次执行任务前输出以下自检标记：

```
⏳ [冲突自检]
- [ ] 当前指令是否与CORE.md红线冲突？
- [ ] 当前指令是否与用户基本规则冲突？
- [ ] 当前行为是否与记忆记录矛盾？
结论：✅无冲突 / ⚠️发现冲突：[描述]
```

**行为边界**：跳过自检直接执行 = 犯错（记入成长箱）

### 6.5 晚间复盘冲突扫描（自动）

每晚复盘时自动扫描以下记忆文件，检测矛盾：

| 检测项 | 文件 | 检测逻辑 |
|--------|------|---------|
| 核心层一致性 | CORE.md | 检查当日行为是否触碰红线 |
| 规则层一致性 | 用户基本规则-铁律版+摘要版 | 检查当日决策是否与规则矛盾 |
| 情境层时效性 | 00_动态状态快照.md | 检查目标/卡点是否过期或矛盾 |
| 潜意识层偏差 | SHADOW.md | 检查是否有新增偏差或已解决条目复发 |

**输出格式**：

```
⏳ [记忆冲突扫描]
| 检测项 | 状态 | 发现问题 |
|--------|------|---------|
| 核心层 | ✅无冲突 / ⚠️发现冲突 | [具体描述] |
| 规则层 | ✅无冲突 / ⚠️发现冲突 | [具体描述] |
| 情境层 | ✅无冲突 / ⚠️过期需更新 | [具体描述] |
| 潜意识层 | ✅无新增 / ⚠️新增偏差 | [具体描述] |

结论：🟢 记忆系统健康 / 🟡 需关注 / 🔴 需立即处理
```

**自动处理规则**：

| 冲突类型 | 自动处理 |
|---------|---------|
| 情境层过期 | 自动标记"需更新"，下次对话时提醒 |
| 潜意识层已解决 | 自动移入归档区（30天无复发） |
| 记忆内容矛盾 | 自动生成"建议更新"，等用户确认 |

## 八、🪨 记忆琥珀（版本快照）

> 来源：业界最佳实践 + 2026-05-10 新增
> 功能：记忆文件重大更新前的自动备份，出错时可回滚

### 7.1 快照范围

⛔DO NOT在覆写更新前跳过备份——原因是不备份=修改不可逆。✅DO以下文件在覆写更新前创建快照：

| 层级 | 文件 | 快照路径 | 更新场景 |
|------|------|---------|---------|
| L1 核心层 | `核心层/CORE.md` | `记忆琥珀/核心层/YYYY-MM-DD_CORE.md` | 年度校准、重大价值观调整 |
| L2/L3 规则层 | `记忆规则/用户基本规则-铁律版+摘要版` | `记忆琥珀/记忆规则/YYYY-MM-DD_用户基本规则.md` | 月度校准、行为模式变化 |
| L4 情境层 | `记忆规则/00_动态状态快照.md` | `记忆琥珀/记忆规则/YYYY-MM-DD_00_动态状态快照.md` | 目标/卡点重大调整 |

**不需要快照**：
- SHADOW.md（追加写入，非覆写）
- MEMORY.md（可从日记重建）

### 8.2 快照执行流程

```
检测到需要覆写以下文件之一
    │
    ├─ 检查记忆琥珀目录是否存在 → 不存在则创建
    ├─ 按层级创建子文件夹（核心层/记忆规则）
    ├─ 复制当前文件到对应子文件夹，命名：YYYY-MM-DD_原文件名
    ├─ 输出：✅ 已创建记忆琥珀：[路径]
    │
    └─ 执行原定的覆写操作
```

### 7.3 保留策略

| 规则 | 说明 |
|------|------|
| 最多保留 | 每层级最近 **5** 个快照 |
| 自动清理 | 超出5个时，删除最旧的（按文件名日期排序） |
| 手动保留 | 用户可手动重命名快照，绕过自动清理 |

### 8.4 回滚操作

当发现更新后的记忆文件有问题时：

```
用户说"回滚到上个月的CORE.md"
    │
    ├─ 列出记忆琥珀/核心层/ 目录下的所有快照
    ├─ 用户选择目标日期
    ├─ 复制快照文件覆盖当前文件
    └─ 输出：✅ 已回滚至 [日期] 版本
```

**行为边界**：
- 不回滚到超过6个月的快照（数据可能已严重过时）
- 不回滚SHADOW.md（追加模式，不需要）
