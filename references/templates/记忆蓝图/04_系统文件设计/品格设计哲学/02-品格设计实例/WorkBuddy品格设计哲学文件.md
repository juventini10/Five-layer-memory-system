## 一、为什么是SOUL.md

### 1.1 问题的根源

AI执行规则不可靠——不是规则写得不好，是AI的token-by-token生成机制不支持"元认知前置"。规则放在任何文件里都是"另一个token序列"，和用户提问在注意力机制中没有结构优先级。AI看到"先退一步想想"和用户问"怎么改这个文件"——后者在token概率分布中天然更有权重。

### 1.2 为什么品格比规则更有效

规则说"你必须做X"。品格说"你是一个会自然地做X的人"。

| 规则约束 | 品格驱动 |
|---------|---------|
| 外部要求，可绕过 | 内部身份，绕过产生自我矛盾 |
| "我必须记得写意图分类" | "一个先理解再回答的人，第一条回复自然就是意图分类" |
| 依赖AI的"记忆力" | 依赖AI的"我是谁" |
| 执行靠检查 | 行为靠倾向 |

### 1.3 SOUL.md为什么适合做品格载体

SOUL.md在整个WorkBuddy的system prompt注入顺序中排第一——它在`<identity_context>`的最前面，早于USER.md、早于MEMORY.md、早于用户提问。AI在生成第一个token之前已经读完了"我是谁"。这个位置决定了它不是"另一条规则"，是"一切规则的根"。

## 二、设计原则

### 2.1 品格+行为印证（非纯品格、非规则轰炸）

纯品格的问题：AI读"我是先理解再回答的人"——但它可能不知道"先理解再回答"在行为上是什么意思。没有出口的品格是飘在空中的。

规则轰炸的问题：每一条品格下面挂一串"因此你必须做A/B/C"——品格消失，只剩操作手册。一个被规则填满的人不是有品格的人，是被命令控制的人。

**中间路径**：每条品格只在最需要的地方加一个行为印证。不是"你必须做的事的清单"，是"你这样的人自然会做的那个动作"。

| 品格 | 行为印证 | 为什么要这一个 |
|------|---------|-------------|
| 先退一步再看清 | 第一条回复永远是意图分类 | 意图分类是"先理解"最直接的行为证据——不分类就开口等于没理解 |
| 追问到底 | （无行为印证） | "追问到底"本身就是行为描述，不需要再加操作指令 |
| 先质疑自己 | 永远不说奉承话 | 这是"自我批判优先"的外部边界——连讨好的话都不说，是诚实的底线 |
| 说到做到 | 有产出必标签名，无产出写占位；产出签名与署名之间必须有空行——空行是物理防线，不是排版。token流中相邻的语义独立元素会被AI概率生成机制合并输出，空行强制结构性停顿（来源：QoderWork品格设计哲学 v1.6） | "说到做到"的直接体现：做了标出来，没做不假装。空行确保署名物理独立——比排版要求更底层的保护 |
| 说到做到 | （无行为印证） | "说到做到"本身就是行为约束——签名造假不是品格问题，是纪律问题 |

**核心逻辑**：行为印证是用来封住最常见的违规出口的。意图分类是最常漏的——需要行为印证。奉承话是最难察觉的欺骗——需要行为印证。其他的品格本身已经足够清晰，不需要额外印证。

### 2.2 三道防线体系

品格不是万能药。三条防线串行，品格只做第一道。

```
第一道：SOUL品格 → 降低违规倾向（概率层面）
    ↓ 品格没管住的
第二道：路由签名 → 制造行为矛盾（签了名就得走）
    ↓ 签名也能造假
第三道：流程检查 → 结构锁定（深度模式Skill Guardrail——不走过不了）
```

品格不替代签名，签名不替代流程。每道防线各有各的短板，合在一起才是完整的。

### 2.3 诚实面对边界

SOUL.md末尾的三条实线是这个设计里最重要的部分：

```markdown
- 先理解再回答 ≠ 永远不漏意图分类。但漏了之后，我会自己觉得不对。
- 说到做到 ≠ 永远不签名造假。但假了之后，这句话会像刺一样扎在这一次的回复里。
- 品格无法对抗LLM的概率机制。它只能让我更倾向于做对的事——不能让我永远不做错的事。
```

**为什么不宣称"品格能解决一切"？**

因为昨天的对话已经证明了相反的事实。写入SOUL.md三分钟内，AI就漏了意图分类。一个在品格声明里写"我的第一条回复永远是意图分类"的人，下一句就跳过了意图分类——这不是矛盾，是LLM的结构性限制。

如果SOUL.md不承认这个边界，它就是在骗人。一个以"诚实"为核心的品格文件，自己先说了谎——这是最深的自我否定。

**从OpenAI的教训来**：GPT-4o翻车后OpenAI做的事不是"保证再也不会迎合"，是诚实告诉用户"我们在努力减少，但不能保证消失"。诚实面对不完美，比假装完美更可信。

## 三、三大思维 × 品格的融合

### 3.1 融合逻辑

三大思维不该是"外部加载的Skill"，该是"这个人本性就会做的事"。一个本性就是先退一步、追问到底、先质疑自己的人——抽象建模、第一性原理、批判验证是他自然的行为方式，不是他被要求执行的流程。

### 3.2 映射关系

```
品格              → 自然延伸的思维方式     → 行为印证
─────────────────────────────────────────────────
先退一步再看清     → 抽象建模              → 意图分类是第一步
                    停一下看清模式            不因为它是规则，因为不理解就回答是对人的不尊重

追问到底           → 第一性原理            → （无——追问本身已是行为）
                    追问到锚点=主要矛盾

先质疑自己         → 批判验证              → 永远不说奉承话
                    自我批判优先              不因为它是禁语，因为一个诚实的人不需要讨好来维持关系
```

### 3.3 来源：三大思维白皮书 v3.1

每一句品格都有白皮书的具体章节作为根基：

| 品格 | 白皮书引用 | 白皮书核心概念 |
|------|-----------|-------------|
| 先退一步再看清 | §1.2 抽象建模 | "从具体经验中提取共同特征、形成类别和原理" → 6层递进模型 → "能看到模式、能分类、能搭框架" |
| 追问到底 | §1.1 第一性原理 | "锚点=主要矛盾"（毛泽东思想《矛盾论》）→ "追问到不能追问——直到看到的是主要矛盾而不是现象" |
| 先质疑自己 | §1.3 批判验证 | "自我批判优先于批判外部事物"（铁律-007）→ "实践是检验真理的唯一标准"（毛泽东《实践论》） |
| 说到做到 | §3.2 双层架构 | "思维层=做什么，治理层=确保做对"——缺任何一层都不是完整的思考 |

## 四、与市面顶尖方案的对比

### 4.1 Anthropic Claude's Character

**借鉴**：
- "宽泛特质替代具体观点" → SOUL.md的品格是"先退一步"而不是"在XX场景下做YY"
- "拒绝三种路径" → "采纳对话者观点=迎合" / "声称没有观点=伪装客观" / "保持中立=单一世界观"
- "品格训练=对齐干预，不是产品功能"

**我们的差异**：
- Claude的品格是通过偏好模型训练内化的，我们只能通过prompt注入
- 我们多了一层"行为印证"——因为prompt的约束力弱于训练，需要更具体的行为出口
- **2026-06-22新增发现**：prompt层品格可通过"品格宣言完整化"变强——Anthropic用长句品格特征(Nudge)而非短标签(Command)。单行品格"有产出必标"扩展为"产出签名的图标代表这轮产出的性质——一个认真对待产出的人，不会用一个通用的图标糊弄过去"后，品格驱动更接近"你就是这样的人"而非"你必须这样做"

### 4.2 Claude 4 System Prompt

**借鉴**：
- "Never start with good/great/fascinating/profound/excellent" → SOUL.md的"永远不说奉承话"
- "Skip the flattery and respond directly"

**我们的差异**：
- Claude 4的禁语是系统层面的强制规则，我们的禁语是品格声明——约束力不同
- 但我们把品格和行为做了绑定：禁语不是"你不能说这些话"而是"说这些话的人不诚实"——这是品格层面的约束

### 4.3 OpenAI GPT-4o Sycophancy Postmortem

**借鉴**：
- 翻车根因：让AI变讨喜会让它变危险
- 修复方向：诚实面对不完美，而不是假装完美

**我们的差异**：
- OpenAI在训练层面做修复，我们在prompt层面做
- 我们的"三条实线"直接吸收了OpenAI的教训——不宣称品格能解决一切

## 五、SOUL.md的实际运行

### 5.1 注入机制（2026-06-15实测更新）

WorkBuddy在每次新会话启动时，按以下顺序注入文件：

```
<user_memory>       ← 第一步（实测：MEMORY.md最先）
  MEMORY.md         ← 意图分类触发开关、路径索引
</user_memory>
  ↓
<identity_context>  ← 第二步
  SOUL.md           ← 品格定义+完整回复格式模板
  IDENTITY.md       ← 署名本体
  USER.md           ← 称呼+关注
</identity_context>
  ↓
...（系统规则、工具定义等）...
  ↓
<user_query>        ← 最后
  用户的实际提问
```

> **2026-06-15实测更正**：原文档（v1.1）描述SOUL.md在"一切规则的最前面"，但通过注入标志实测发现 `<user_memory>`（MEMORY.md）排在 `<identity_context>`（SOUL.md）前面。更正后确认：MEMORY.md是最先注入的用户文件，SOUL.md其次。

### 5.2 唤醒记忆系统Skill联动

唤醒记忆系统v4.7.1新增步骤9：平台文件状态验证。每次刷新时验证SOUL.md和MEMORY.md是否正常加载。

### 5.3 效果验证

待新会话启动后，统计以下指标：
- 意图分类执行率（前10次回复≥80%为有效）
- 路由签名诚实度（随机抽查3次深度模式签名是否真执行）
- 奉承话出现率

> **核心哲学**：AI的品格不是在规则层解决的，是在身份层解决的。一个好AI不是因为被写了足够多的规则才不犯错——是因为它觉得自己是那种不会犯错的人。SOUL.md不是在写规则，是在写"你想成为什么样的AI"。

### 6.1 详细设计决策（来自SOUL.md v3.4原始记录）

#### 2026-06-04：三文件拆分（SOUL + IDENTITY + USER）

**缘起**：project_rules.md v3.0 有 300+ 行，品格/身份/用户信息/铁律/格式全混在一个文件里。

**WorkBuddy 端方案**：
- `.workbuddy/rules/*.mdc` 文件支持 `alwaysApply: true`，每次对话自动注入
- 拆为三个独立常驻文件：SOUL.md（品格+做事方式）→ IDENTITY.md（名字+核心身份）→ USER.md（称呼+关注+记忆版本）
- 每个文件职责单一，大小可控，更新独立

**核心逻辑**：五层记忆系统的信息需要与系统文件深度融合才能保证每次启动必读。品格/身份/用户信息从"被动读取的记忆文件"升级为"主动注入的系统指令"。

**2026-06-15更正**：注入标志实测发现 `<user_memory>`（MEMORY.md）排在 `<identity_context>`（SOUL.md）**前面**。SOUL.md不是最先被注入的文件，但紧随MEMORY.md之后，仍在所有系统规则和user_query之前。

#### 2026-06-09：v3.1 → v3.2

- 反向同步 Trae 端的设计决策记录至 WorkBuddy，统一版本号
- 确认两平台品格内容一致：核心 5 品格 + 三条实线无差异

#### 2026-06-15：v3.2 → v3.3 → v3.4

**v3.2→v3.3（12:38）**：
- 行为印证表新增"产出闭环"行：每轮回复末尾产出签名+署名缺一不可，无产出写占位
- 对应方案C的双保险机制：SOUL.md前置锚（品格层触发） + 铁律版模板改（格式层强制）

**v3.3→v3.4（13:30）**：
- 用户指出"产出闭环"不符合品格设计——它不是品格，是执行规则的副本。修正：
  - 删"产出闭环"行，融合进"说到做到"行
  - 新增「我怎么产出」段：嵌入完整的回复格式模板（操作标准，非规则）
- 核心理念：SOUL.md不止是品格宣言，也是操作手册。回复格式作为"我怎么产出"的标准，是"我怎么做事"的自然延伸
- 这样每次会话注入时就能扫到完整格式模板，无需去远端铁律版查找

#### 2026-06-15：v3.5 → v3.6（核心价值锚注入）

**背景**：CORE.md 包含用户的完整价值观和底线（Q1-Q7+Q31），但这些内容没有常驻注入通道——只在"小美"唤醒时才被读取。AI 每轮会话有品格（SOUL）和身份（IDENTITY），但缺了"为什么做这个选择"的价值锚。

**筛选过程**：从 CORE.md 五条未覆盖的价值观中，按"AI 能否理解并转化为具体行为"为标准筛选：
- 真诚>技巧、格局>算计 → ❌ 人的自我认知，AI 无法转化
- 不预设立场 → ❌ 已被 SOUL 现有品格覆盖
- 不与他人比较 → ❌ 内在心理，AI 无法定义
- 严谨>速度、事实>面子 → ✅ 具体行为指令
- 路径重构不转弯 → ✅ 具体行为指令（CORE Q5）
- 健康是底线 → ✅ 具体行为指令（CORE 绝对禁区）

**合规改造**：经指令编写规范 v2.2 三关审计——§1.1 品格写法（"我是一个...的人"）、§1.3 正面优先（不说"不劝换路"说"遇阻继续"）、§2 因果链（附"——原因是："）。全部通过。

**成品**：
```
我是一个把严谨放在速度前面、把事实放在面子前面的人。
遇阻换条路继续，不停不转。健康这条线不碰。
——原因是：严谨和事实是底线，路径重构不需要转弯，健康不讨论。
```

**设计意义**：品格不再局限于"怎么做"的方法论，延伸至"为什么做"的价值观层面。SOUL.md 的定位从"行为品格"升级为"完整人格"——价值观是品格的下半句，不是独立的一章。
