# 成就系统设计哲学 — S级架构文件

> 本文档是成就系统的最高设计哲学。记录"为什么这样做"，不重复"代码怎么实现"。
> 与实际代码的关系：**哲学是宪法，代码必须符合宪法，而非宪法去适配代码**。
> 
> 成就系统不是"任务打卡器"。它是**行为反馈回路**——当你完成了足够多次正确的行动（或积累了足够多的负向数据），系统给你一个诚实的信号：你正在成为你想成为的人，或你正在偏离你设定的方向。
> 
> 版本：v1.0 | 创建日期：2026-06-27 | 作者：皮叔（五层记忆系统·布洛陀版） | 来源：实际9类成就文件设计蒸馏 + 六路行为理论交叉验证

## 一、文档定位

成就系统是布洛陀五层记忆系统的**行为反馈层**——它不存储知识（那是CORE/SHADOW的职责），不定义规则（那是铁律的职责），只做一件事：**诚实记录行为数据，在关键里程碑给予确认信号**。

### 三份文件的关系

```
成就系统设计哲学.md（本文）──→ 宪法级：为什么这样设计，不可违反的原则
        ↓
各成就定义文件（番茄成就.md / 阅读成就.md / ...）
        ↓
成就速查.md ──→ AI 生成日记时的快捷参考（非设计文档）
```

### 设计哲学的适用范围

本文档约束的范围包括：
- 成就检测脚本的行为逻辑
- 成就等级体系的结构设计
- 与最伟大的我的联动规则
- 数据记录和展示的诚实性

本文档不涵盖的范围：
- 如何运行检测脚本（那是代码注释和 README 的职责）
- 每日日记的格式（那是每日伙伴的职责）
- 成就数据的存储格式（那是 implementation detail）

## 二、设计溯源：六路权威理论

### 2.1 Self-Determination Theory（Deci & Ryan, 2000）

**核心主张**：人类的内在动机来自三个基本心理需求——自主性（Autonomy）、胜任感（Competence）、归属感（Relatedness）。外部奖励若削弱自主性，反而会降低内在动机。

| SDT 原则 | 成就系统映射 | 说明 |
|----------|-------------|------|
| **自主性是内在动机的核心** | §3.1 检测不激励——不做进度诱导、不做"今天还没打卡"的催促 | 任何推送式激励都在削弱自主性——用户的行为必须是自发的 |
| **胜任感需要适度挑战** | §3.3 指数阈值——成就门槛从易到难，匹配技能增长曲线 | 固定阈值在前 3 次达成后就不再提供胜任感 |
| **外部奖励会"挤出"内在动机** | 不做"连续打卡X天送XX"的奖励机制——成就是副产品，不是目标 | 当用户为了成就而行动时，内在动机已经部分让位于外在动机 |

**关键差异**：SDT 研究警告"外部奖励会降低内在动机"，但成就系统的信号是**自我确认（self-signal）**而非外部奖励（external reward）。区别在于：成就没有货币价值、没有排行榜、没有社会比较——它只是用户自己跟自己确认"我做到了"。

---

### 2.2 Octalysis 八核驱动力框架（Yu-kai Chou, 2015）

**核心主张**：游戏化和行为设计的驱动力可归纳为 8 个核心维度。有效的设计至少激活 3-4 个维度。

| 八核驱动力 | 激活状态 | 成就系统中的体现 |
|-----------|:-------:|:----------------|
| ① 史诗意义 & 使命感 | ✅ | 钻石级成就（如"千番茄王者"）——极少数人到达的深度里程碑 |
| ② 发展 & 成就 | ✅ | 正向轨全部成就——解锁即确认进步 |
| ③ 创意授权 & 反馈 | ⚠️ | 间接——用户自定义成就阈值的可能性 |
| ④ 拥有 & 占有 | ✅ | 成就证据写入最伟大的我——"这是属于我的成就" |
| ⑤ 社交影响 & 关联 | ❌ **主动排除** | 没有排行榜、没有社交分享——成就是私密的 |
| ⑥ 稀缺 &  impatient | ✅ | 指数阈值设计——越往后越难拿到，制造自然稀缺 |
| ⑦ 未知 & 好奇心 | ⚠️ | 反向轨成就名自嘲风格——用户会好奇"连续熬夜7天叫什么" |
| ⑧ 损失 & 避免 | ✅ | 月亮之子反向轨——损失厌恶驱动行为改变 |

**关键启示**：成就系统明确排除了第⑤驱动力（社交）。这是有意为之——个人成长系统的成就不需要观众。成就的意义在于自己知道，不是让别人看到。

---

### 2.3 Flow Theory（Csikszentmihalyi, 1990）

**核心主张**：心流（Flow）是挑战与技能平衡时的最佳体验状态。挑战过高→焦虑，技能过高→无聊。

| Flow 原则 | 成就系统映射 |
|----------|-------------|
| **挑战必须随技能增长** | §3.3 指数阈值——阈值递增幅度随等级上升，匹配用户技能的渐进提升 |
| **清晰的目标和即时反馈** | 每级阈值可量化（"还差 3 篇达到 100 篇"），完成后立即解锁 |
| **焦虑/无聊的平衡** | 铜牌密集（1-3-5-7）→ 银牌稀疏（30-50-60）→ 金牌极疏（500-700-1000）——技能越高，用户越不需要频繁确认 |

**关键矛盾**：Flow 理论强调"即时反馈"是心流的必要条件，但成就系统的"延迟反馈"（§3.2）看似违反了这个原则。实际的设计权衡是：

```
延迟反馈牺牲了"每次日记都有成就"的即时感，
但保留了"成就达成时的 surprise 感"和"习惯化后的自我确认"。
如果成就变成每天自动解锁，它就变成了白噪音。
```

---

### 2.4 Goal Gradient Effect（Hull, 1932；Kivetz et al., 2006）

**核心主张**：人们靠近目标终点时会加速努力。"还差 20% 就完成了"比"才完成了 40%"有更强的驱动力。

**成就系统中的体现**：

- `achievement_tracker.py --status` 显示的进度条（`███░░ 70%`）直接利用这个效应
- 每个成就都有"当前值/阈值"的可量化差距
- 阈值设计使得"离下个目标很近"的感觉会频繁出现——铜牌期每~10步就有一次

**关键关联**：这个效应也解释了为什么"下一目标"的显示必须存在。如果只看已解锁的成就列表而没有"下一个是什么"，用户会失去前进方向。

---

### 2.5 Progress Principle（Amabile & Kramer, 2011）

**核心主张**：**小 wins**（中小型进步）是维持内在动机的最强驱动力。人们不是被大目标激励的——是被"今天有进展"这个感觉激励的。

| Progress Principle | 成就系统映射 |
|-------------------|-------------|
| **小型确认 > 大型奖励** | 铜牌期每~10步一个节点（不是每100步）——前3个月密集确认 |
| **进展需要可见** | 每篇日记的"成就模块"记录当前进度——每天的进展都可见 |
| **负面事件的杀伤力 > 正面事件** | 反向轨记录消极行为——"数据诚实"比"只看积极面"更有助于维持动力 |

**关键启示**：这个原则直接支持了"指数阈值"设计——初期密度高（小wins密集），后期密度降低（用户已经习惯化，不需要外部确认）。商业应用中常见的"每日登录奖励"就是 Progress Principle 的滥用版本——它把"小确认"做成了"成瘾机制"。

---

### 2.6 Loss Aversion（Kahneman & Tversky, 1979, Prospect Theory）

**核心主张**：损失带来的心理冲击约是等值收益的 2-2.5 倍。人们对"失去"比"得到"更敏感。

**成就系统中的体现（月亮之子反向轨）**：

这是整个成就系统最具原创性的设计。与正向轨的工作机制对比如下：

```
正向轨（番茄/阅读/日记/...）：
  行为 +  → 数据增长 → 阈值达标 → 成就解锁 → 胜任感确认
  利用：获得驱动

反向轨（月亮之子）：
  行为 -  → 数据增长 → 阈值达标 → 暗黑成就 → 数据诚实提醒
  利用：损失厌恶驱动
```

| 维度 | 正向轨 | 反向轨 |
|:----|:------|:------|
| 行为方向 | 积极行为（写日记、早睡） | 消极行为（熬夜） |
| 心理机制 | 获得驱动——解锁时的胜任感 | 损失厌恶——看到"熬夜100天"时的戒惧 |
| 成就风格 | 严肃命名（"番茄大师"） | 自嘲幽默（"僵尸模式""死神契约"） |
| 数据作用 | 确认进步 | 诚实呈现——不粉饰、不评判 |
| 联动结果 | 最伟大的我/成就证据/ | 最伟大的我/成就证据/（同样写入，同等对待） |

**设计意图**：反向轨不是"惩罚机制"，而是**数据诚实机制**。当用户看到"累计熬夜100天·死神契约"时，系统没有说"不要熬夜了"，只是诚实地呈现了一个不愿面对的数字——这个数字本身的警示力远大于任何推送通知。

## 三、宪法级原则（MUST / NEVER）

> 以下原则是成就系统的宪法底线。代码实现如果违反了这些原则，是代码错了，不是原则错了。

### §3.1 检测不激励

系统**MUST**只做检测和记录。
系统**NEVER**做任何形式的进度诱导、催促推送、未完成提醒。

```
✅ 允许：成就检测 → 检测到达成 → 记录到 achievement_data.json → 写入最伟大的我
❌ 禁止：昨晚没写日记 → 推送"今天记得补写"
❌ 禁止：还差3篇就100篇了 → 推送"再加把劲"  
❌ 禁止：每日打卡后显示"已连续打卡X天"的鼓励文案
```

**理论依据**：SDT（自主性）——任何推送都在削弱自主性。Progress Principle——"进展可见"是指用户自己去看，不是系统推给用户看。

**例外**：检测到新成就时的弹窗通知（`send_achievement_notification`）属于"即时反馈"，不是"进度诱导"。两者区别在于：

```
通知是"你已经做到了"的确认，不是"你还没做到"的催促。
```

### §3.2 延迟反馈

系统**MUST**为成就设置合理的延迟阈值——不能在行为发生后的下一次检测就解锁。
系统**NEVER**设置即时性成就（如"今天写了日记"或"今天运动了"这类每日成就）。

```
✅ 允许：番茄10个（约1周） / 日记100篇（约3个月） / 连续熬夜3天
❌ 禁止：连续打卡1天 / 写了1篇日记 / 早睡1次
```

**理论依据**：Progress Principle——小wins不是每一个行为一次的频率，而是每1-2周一次的频率。Flow Theory——延迟反馈保留达成时的 surprise 感。

**例外**：铜牌期密度较高（第1天/第3天/第5天）不是违反延迟反馈，因为：

```
对于新用户，"第1天有成就"是 onboarding 信任建立（让用户确认系统在工作），
对于已有习惯的用户，第1天成就是"恢复记录"的确认——不是即时的每日奖励。
```

### §3.3 指数阈值

系统**MUST**使用指数增长（或至少加速增长）的阈值序列。
系统**NEVER**使用等差数列或固定增量作为成就阈值。

```
✅ 允许（指数增长）：10 → 30 → 50 → 80 → 100 → 200 → 300 → 400 → 500 → 700 → 900 → 1000
❌ 禁止（等差数列）：10 → 20 → 30 → 40 → 50 → ...
❌ 禁止（固定增量）：每天一个成就 → 365天
```

**设计逻辑**：指数阈值的核心理由有三个——

| 理由 | 说明 |
|:----|:-----|
| **Flow 匹配** | 技能增长对数曲线→阈值增长指数曲线→两者斜率匹配 |
| **稀缺感** | 固定增量到后期不再具有稀缺性——每天都有就不叫"成就"了 |
| **注意力预算** | 成就总数量可控——指数阈值下用户的成就总数不会无限膨胀 |

**四阶等级体系**：铜牌 → 银牌 → 金牌 → 钻石

| 等级 | 对应阈值段 | 密度 | 典型行为频率 |
|:---:|:---------|:---:|:----------:|
| 🟢 铜牌 | 1-99 | 高（每~10步） | 第一周至第一个月 |
| 🥈 银牌 | 100-999 | 中（每~100步） | 第一个月至半年 |
| 🥇 金牌 | 1000+ | 低（每~500-1000步） | 半年至数年 |
| 💎 钻石 | 特殊里程碑 | 极低（关键节点） | 极少数人可达 |

### §3.4 数据诚实

系统**MUST**真实记录所有行为数据——正向行为和负向行为同等对待。
系统**NEVER**隐藏、粉饰、或忽略负向行为数据。

```
✅ 允许：月亮之子成就与番茄成就在同一数据文件中并排记录
❌ 禁止：只记录"早睡天数"而不记录"熬夜天数"
❌ 禁止：在统计展示中只显示正向数据，隐藏月亮之子
```

**理论依据**：Loss Aversion——负向数据的诚实呈现产生的行为驱动力大于正向激励。行为设计的基本原则是"系统可以信任"——如果系统选择性记录数据，用户会失去对系统的信任。

### §3.5 幂等与单向

系统**MUST**确保每个成就只触发一次。
系统**NEVER**重复触发同一个成就。

```
✅ 允许：成就检测 → 检查 unlocked → 不在列表且达标 → 写入
✅ 允许：同名文件已存在 → 跳过
❌ 禁止：同一成就第二天再次检测到再次触发
```

### §3.6 单向联动（成就系统 → 最伟大的我）

成就系统**MUST**单向写入最伟大的我。
成就系统**NEVER**反向读取最伟大的我作为数据源。

```
✅ 允许：新成就 → 写入 最伟大的我/成就证据/{日期}-{成就ID}.md
❌ 禁止：成就检测时读取 最伟大的我/成就证据/ 作为数据输入
```

**设计理由**：职责分离——

```
成就系统：管检测和记录（数据源）
最伟大的我：管沉淀和成长叙事（数据消费者）
```

如果成就系统反向依赖最伟大的我，会形成循环依赖：成就要读最伟大的我来检测→最伟大的我依赖成就写入→谁先启动？

## 四、双轨制：正向轨与反向轨

### 4.1 正向轨（9类成就中的8类）

记录积极行为，在里程碑确认进步。适用：番茄、阅读、日记、早睡、早起、内容创作、运动、通用打卡。

### 4.2 反向轨（1类：月亮之子）

记录消极行为，用数据诚实和损失厌恶驱动行为反思。适用：熬夜。

### 4.3 为什么 8:1 的比例

不是刻意设计的比例，而是实际行为数据的自然结果：

| 行为 | 属于 | 原因 |
|:----|:---:|:----|
| 番茄 | 正向 | 主动记录的积极行为 |
| 阅读 | 正向 | 主动知识的投入 |
| 日记 | 正向 | 自我梳理的积极习惯 |
| 早睡 | 正向 | 健康自律的积极行为 |
| 早起 | 正向 | 同早睡 |
| 内容创作 | 正向 | 创作是主动输出 |
| 运动 | 正向 | 健康自律 |
| 通用打卡 | 正向 | 行为存在性证明 |
| 熬夜 | 反向 | 唯一需要"数据诚实"而非"正能量确认"的行为 |

### 4.4 扩展原则

未来增加新成就类别时，按此规则判断方向：

```
行为是用户主动想养成的 → 正向轨
行为是用户知道不好且想减少的 → 反向轨
行为是中性的 → 正向轨（中性行为不值得用反向机制）
```

- 初版我把 1000🍅写成"钻石·番茄大师"，但你的实际文件里 1000🍅 写的也是"金牌·千番茄王者"
- 说明在你的设计中，1000🍅 并不是"不可能达到"——你已经达到了1167🍅
- **实际代码的阈值定义与这里不一致**：脚本里 1000🍅 定义在金牌（`"threshold": 1000, "level": "🥇 金牌"`），而你的 番茄成就.md 里 1000🍅 定义为钻石——**这属于实现偏离哲学**，代码需要修正

## 六、与商业成就系统的差异

### 6.1 游戏成就（PlayStation / Xbox / Steam）

| 维度 | 游戏成就 | 布洛陀成就 |
|:----|:--------|:----------|
| 目标 | 延长游戏时间、增加复玩率 | 诚实记录个人成长数据 |
| 触发 | 开发者预设条件 | 用户真实行为数据 |
| 反馈 | 奖杯弹窗 + 积分 + 排行榜 | 仅弹窗通知（无积分、无排行榜） |
| 稀有度 | 白金/金/银/铜——按设计分布 | 铜/银/金/钻石——按行为难度自然分布 |
| 隐私 | 公开可见（好友/社区） | 完全私有（仅写入最伟大的我） |

### 6.2 健身应用成就（Apple Watch / Fitbit）

| 维度 | 健身应用 | 布洛陀成就 |
|:----|:--------|:----------|
| 激励机制 | 每日闭环 + 连续记录 + 社交挑战 | 无每日目标、无连续记录奖励、无社交 |
| 推送 | 频繁推送（不运动就提醒） | 零推送 |
| 正向偏差 | 只记录积极行为 | 正反向都记录——月亮之子是独特设计 |

### 6.3 教育应用成就（Duolingo / Quizlet）

| 维度 | 教育应用 | 布洛陀成就 |
|:----|:--------|:----------|
| 核心机制 | 连续记录（streak）为核心 | 指数阈值为核心——连续只是阅读的一个子维度 |
| 损失机制 | 连胜中断→失去（负向激励） | 反向轨记录负向行为本身（没有"失去"的概念） |
| 货币化 | 成就可兑换虚拟货币 | 成就无任何可兑换价值 |

### 6.4 布洛陀成就的核心差异总结

```
商业成就：
  用户需要成就 → 系统提供成就 → 用户为成就行动
  成就 = 外部激励，驱动用户使用产品

布洛陀成就：
  用户行动 → 系统检测到 → 系统确认成就
  成就 = 副产品，不是行为的原因
```

## 七、实操机制

> 设计哲学管"为什么"，实操机制管"怎么跑"。以下记录成就系统在实际运行中的完整触发链路、执行步骤和验收闭环。

### 7.1 完整触发链路

```
写日记
  → 每日伙伴·晚间复盘（工作流C）
    → 🔒 成就检测（强制，不可跳过）
      → achievement_tracker.py --all
        → 检测新成就 → 弹窗通知 + 写入最伟大的我
    → 🔒 成就更新（强制）
      → update_diary_achievement.py → 写入日记成就模块
    → 🔒 成就校验（终检）
      → 验证 diary_total == 今日实际日记篇数
```

**核心原则**：**日记是成就系统的唯一日常驱动源**。没有日记就没有成就检测链。

### 7.2 三种触发时机

| 时机 | 触发源 | 命令 | 强制 | 频率 |
|:----|:------|:----|:----:|:----:|
| 每日·晚间复盘 | 工作流C步骤2 | `achievement_tracker.py --all` | 🔒 强制 | 天 |
| 每周·周报 | 周报SOP步骤4 | `achievement_tracker.py --all` | ✅ | 周 |
| 每月·月报 | 月报spec第⑩步 | 钩子脚本确认 | ✅ | 月 |

### 7.3 检测执行链

`achievement_tracker.py --all` 完整执行步骤：

```
1. scan_all_diaries()
   → 遍历日记目录所有 .md 文件
   → 对每篇调用 parse_diary_file()
     → 提取：番茄累计数、睡眠时间、早起标记
     → 提取：运动标记、创作计数、当日状态
2. 知识库扫描
   → 读取读书笔记目录 → 笔记数
3. 日记目录计数
   → 计算日记文件总量
4. check_achievements(data)
   → 对比 data["unlocked"] + ACHIEVEMENTS 阈值表
   → 新成就 → append 到 newly_unlocked 列表
5. 对新成就在 newly_unlocked 列表中：
   → send_achievement_notification()       ← macOS 弹窗（阻塞，等用户点OK）
   → sync_to_greatest_me()                 ← 写入最伟大的我/成就证据/
6. save_data()
   → 写入 achievement_data.json（持久化）
7. update_achievement_markdown()（仅 --all 模式）
   → 同步更新各成就 .md 文件的进度数据
```

### 7.4 成就更新链

`update_diary_achievement.py` 在成就检测后立即执行：

```
1. 读取 achievement_data.json → 获取最新数据
2. 定位今日日记文件 → [日记仓库]/01-日记/{YYYY-MM-DD}.md
3. 更新日记中"今日成就"模块的进度数据
4. 写入成就进度备忘（6行固定格式，数据必须来自脚本输出）
```

### 7.5 验收链

工作流C步骤2终检：

```
成就校验：
  → 读取 achievement_data.json 的 diary_total
  → 对比今日实际日记篇数
  → 不一致 → 回退重跑成就检测+更新
  → 一致 → 继续下一环节
```

### 7.6 幂等设计在实际中的体现

| 场景 | 处理 |
|:----|:----|
| 同一天跑两次 `--all` | 已解锁的成就不会重复触发（unlocked 列表去重） |
| 周报也跑 `--all` | 和晚间复盘共享同一个 `achievement_data.json`——运行多次只会检测到在"上次检测后"的新成就 |
| 手改数据后重跑 | `--all` 模式全量重算——不会丢失已解锁记录，不会重复检测已解锁项 |

## 八、与最伟大的我联动

成就系统与最伟大的我是**单向写入**关系。

### 联动机制

```
newly_unlocked = check_achievements(data)
for ach, value in newly_unlocked:
    send_achievement_notification(ach, value)    # 弹窗通知
    sync_to_greatest_me(ach, value)               # 写入最伟大的我
```

### 写入格式

```
[记忆共享中心]/最伟大的我/成就证据/{YYYY-MM-DD}-{achievement_id}.md
```

示例：`2026-06-27-tomato_1000.md`

```markdown
# 成就证据 · 🥇 千番茄王者-番茄1000个

- **达成日期**：2026-06-27
- **成就ID**：tomato_1000
- **等级**：🥇 金牌
- **达成值**：1000
- **来源**：成就系统自动检测
```

### 最伟大的我的其他子目录如何消费成就数据

| 目录 | 数据来源 | 频率 |
|:----|:--------|:----|
| 成就证据 | 成就系统自动写入 | 每次新成就检测到 |
| 自画像 | 月报时读取成就证据 | 每月 |
| 成长判定 | 读取成就证据数量 + 频率 | 每月 |
