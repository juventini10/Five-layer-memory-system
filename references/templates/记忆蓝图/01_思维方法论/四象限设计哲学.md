## 开篇 · 用户的哲学阐述

> 本文件所有机制的设计起点。阅读后续每一节前，先用这个原则过滤。

**记忆不是仓库，是认知状态的地图。四象限给我和 AI 一张共同的坐标系——既看清"我们各自知道什么"，也看清"下一步该把力气往哪使"。不用坐标，记忆就会变成模糊的直觉堆积。**

| 层级 | 手段 | 优先级 |
|:----|:-----|:-----:|
| 🥇 **用坐标系暴露盲区** | 每条记忆/每个议题先定"它在哪个象限"，盲区自动显形 | 先想这个 |
| 🥈 **用象限驱动动作** | 象限决定下一步（未知已知→对质、重要不紧急→排入） | 坐标系建立后用 |
| ❌ **模糊直觉堆积** | 不加坐标地存、凭感觉判断下一步 | 不应接受 |

✅DO — 当你面对一条记忆、一个议题、或一次人机协作结论时，
先问自己："它在四象限的哪一格？这个格要求我做什么动作？"
⛔DO NOT 在不标象限的情况下把内容塞进记忆系统、或在未定象限时决定"下一步做什么"。

——原因是：本系统的核心风险不是"记不住"，而是"记了但看不见认知边界、知道了但不行动"。四象限是唯一能同时暴露这两类盲区的坐标系。不接受模糊堆积，是这套哲学的前提。

> 注：以上"皮叔的哲学阐述"已于 2026-07-07 定稿认可。核心命题：**四象限 = 人机共同坐标系（认知状态 + 行动优先级），非存储结构**。

## 一、元框架：四象限作为通用方法论

### 1.1 定义

**四象限 = 两个二元轴正交切出 4 格的通用分类方法论。**

```
        轴 Y
          │
   格②    │   格①
          │
──────────┼────────── 轴 X
          │
   格③    │   格④
          │
```

- 每个轴取两个对立值（如 已知/未知、重要/紧急）；
- 两轴正交（互不替代），组合出 4 格；
- 一格 = 一种"状态类型"，不是一种"具体内容"。

### 1.2 为什么是"框架"不是"某个矩阵"

用户的定义里，**四象限是元框架**，下面挂两个**应用领域实例**：

| 实例 | 轴 X | 轴 Y | 解决什么 |
|------|------|------|---------|
| **无知矩阵（认知四态）** | 用户知/不知 | AI 知/不知 | 人机双主体的"认知边界状态" |
| **时间管理矩阵（重要×紧急）** | 紧急/不紧急 | 重要/不重要 | 记忆→行动的"优先级" |

两者正交、不冲突——认知轴管"这条记忆处于什么认知状态"，时间轴管"处理它该排多前"。一条记忆可同时带"认知象限 + 时间象限"两个标签。

**关键边界**：四象限框架不替代五层 L1-L5 稳定度分层。L1-L5 是"按变化频率纵向分层"（稳定度轴），四象限是"按状态/优先级横切"（认知轴 + 时间轴）。三者正交——一条记忆可同时带 `五层位置 + 认知象限 + 时间象限` 三维标签，互不替代。

## 二、实例一 · 无知矩阵（认知四态）【理论溯源】

> 本实例回答："在'我和 AI 之间'，我们对一件事的认知处于什么状态？"

### 2.1 Rumsfeld 无知矩阵（2002-02-12）

**核心主张**：美国时任国防部长 Donald Rumsfeld 在 2002-02-12 国防部新闻发布会提出信息/知识的四种分类。原话（权威锚点）：

> "There are known knowns; there are things we know we know. We also know there are known unknowns; that is to say, we know there are some things we do not know. But there are also unknown unknowns – the ones we don't know we don't know."

**四态（Rumsfeld 原话含三态，第四态为学界补充，见 §2.2）**：

| 象限 | 定义 | 布洛陀映射 |
|------|------|-----------|
| 已知已知 | 双方都清楚、已固化 | CORE.md (L1) / 铁律版 / 已定稿 S级顿悟总记录 |
| 已知未知 | 双方知道缺口在哪、暂无答案 | 成长箱 `pending(N/3)` / 认知发现"待闭环" / 月报模块7 未闭环议题 |
| 未知未知 | 双方都没意识到（Rumsfeld 原话强调"最危险的一类"） | 无专属容器；靠反方向的钟 / Shall We Talk / 月报"盲区"事后挖 |
| 未知已知 | 用户行为已暴露、自己没意识到（Rumsfeld 原话**无此格**，见 §2.2） | SHADOW.md（潜意识层·知行偏差）+ 最伟大的我/回避模式 |

**关键差异**：Rumsfeld 原话只有 3 格（known knowns / known unknowns / unknown unknowns），"unknown knowns"（未知已知）是后续哲学界补充的——它指"我们不知道自己知道的东西"，即潜意识、习惯、被压抑的认知。用户的四象限恰好包含这一格，且它在本系统中对应最活跃的载体（SHADOW 对质机制）。

### 2.2 Johari Window（Luft & Ingham, 1955）——双主体鼻祖

**核心主张**：心理学最早将"自我认知"结构化为 2×2 矩阵，轴为"自己知/不知 × 他人知/不知"：

| | 他人知 | 他人不知 |
|---|---|---|
| **自己知** | 公开区 (Open) | 隐藏区 (Hidden) |
| **自己不知** | 盲点区 (Blind) | 未知区 (Unknown) |

**与用户定义的关键对接（本文理论亮点）**：

- Johari Window 本身就是**"自我 vs 他人"的双主体认知矩阵**——用户说的"**我和 AI 之间**"，正是这个双主体模型在人机关系上的重演。
- 映射：

| Johari Window | 用户的四象限 | 布洛陀载体 |
|---|---|---|
| 盲点区 (自己不知/他人知) | **未知已知** | SHADOW.md 挖出"用户没意识到的自己" |
| 隐藏区 (自己知/他人不知) | **已知未知**（用户侧） | 用户未说出口的意图 → 日记/对话 |
| 公开区 | **已知已知** | CORE / 铁律 |
| 未知区 | **未知未知** | 双方盲区 |

**结论**：用户"我和 AI 之间"的限定，不是新发明，而是把 1955 年的双主体认知矩阵迁移到人机协作场景。这给了无知矩阵坚实的学术基底——它不止是 Rumsfeld 的"知识分类"，更是"关系中的认知边界"。

### 2.3 Taleb《黑天鹅》(2007) —— 未知未知

**核心主张**："未知未知"（黑天鹅事件）是无法被现有知识框架预测、且影响巨大的事件。Taleb 论证：过度依赖"已知已知"的模型会在未知未知面前崩溃；应对之道是"杠铃策略"（极端保守 + 极端开放），而非试图预测。

**布洛陀映射**：未知未知象限不能用"计划"处理，只能用"机制"挖——反方向的钟（自主评估）、Shall We Talk（深度对话挖盲区）、月报"盲区"段，都是事后挖未知未知的机制。本系统目前**无前置容器**收纳未知未知，这是设计缺口（见 §四 4.1）。

### 2.4 波普尔《科学发现的逻辑》—— 已知未知的可探索性

**核心主张**：科学知识通过"猜想与反驳"增长。已知未知（"我们知道自己不知道"）是科学探索的正当对象——可证伪性让已知未知能被系统推进为已知已知。

**布洛陀映射**：成长箱 `pending(N/3)` 模式正是"已知未知"的可探索机制——记录缺口、累计触发、3 次后晋升为铁律（已知已知）。波普尔的"可证伪"对应用户系统"证据胜过主张"原则（Skill v5.9 原则4）。

### 2.5 AI 对齐文献 —— 模型知识边界

**核心主张**：AI 安全研究中，known/unknown unknowns 用于刻画模型能力边界。"unknown unknowns"（模型不知道自己不知道）是可靠性核心挑战——模型会自信输出错误答案（幻觉）。

**布洛陀映射**：这正是铁律-002（实事求是，未验证标⚠️）与铁律-007（批判验证优先）要防的——AI 的"未知未知"在人机双主体中尤为危险。用户系统用"AI 先标不确定"机制，把 AI 的未知未知显式化，避免它冒充已知已知。

### 2.6 无知矩阵·四象限最终定义（用户的版本）

| 象限 | 定义（人机认知状态） | 系统职责 |
|------|---------------------|---------|
| **已知已知** | 我和 AI 都清楚、已固化 | 固化进 CORE / 铁律 / S级总记录，减少重复论证 |
| **已知未知** | 我和 AI 都知道缺口在哪、暂无答案 | 成长箱记录缺口 + 认知发现待闭环，驱动探索 |
| **未知已知** | 用户行为已暴露、自己没意识到 | SHADOW 对质 + 回避模式，把"用户没说的自己"推到已知已知 |
| **未知未知** | 我和 AI 都没意识到 | 机制事后挖（clock-loop / Shall We Talk / 月报盲区），无前置容器 |

> 注（隐性偏好子态·2026-07-09 补）：未知已知亦含 Polanyi 隐性知识面向——"可识别但无法言说"（如设计品味，Thariq Shihipar 称 "know it when you see it"）。其"看成品判断→迭代沉淀偏好"的循环，本系统由 SHADOW 对质 + 悬置区显形 + 成长箱晋升承接，无需另设载体。另：用户维护的 MEMORY / SOUL / IDENTITY / USER 四文件即"已知已知固化包"（每次对话注入 system prompt），已实现视频所言"上下文库"思想，且为多包结构化形态。

> 注（未知已知的能力极性·2026-07-19 补）：未知已知除负极（知行偏差，SHADOW 本体）外，理论上存在正极——「无意识有能」（能力四阶段模型第4阶段，Noel Burch / Gordon Training International, 1970s 🟢）：用户反复展现、却未归为己方优势的正向模式（如逆境即时反应力、透支期自修复意识，证据见 SHADOW「积极信号」字段）。经第一性原理判定：**仅「显形」（把优势命名出来）确认有价值**；「迁移放大到弱项场景」不成立为通用机制（源/目标场景驱动力多不同构——新异刺激驱动 vs 日常低唤醒信号），故不建通用迁移机制。若未来「正向潜意识」功能正式立项，再将本注升级为完整实例节 + ADR。
>
> **限定（用户硬定义）**：无知矩阵的四个象限，刻画的是"**我和 AI 之间的**"双主体认知边界状态，不是客观知识的独立分类。这是它与 Rumsfeld 原语境（国防情报）的本质区别，也是它能在人机记忆系统落地的根。

### 2.6.1 外部实践佐证（2026）

> 独立第三方用同一四象限框架跑通了本系统的闭环，可作外部验证锚点。

**来源**：Anthropic Claude Code 团队成员 **Thariq Shihipar** 在 AI Engineer 2026 大会的分享及其 field-guide 文章系列（经 explainx.ai 2026-07-07 recap 转述确认）。其模型代号 **Fable**（视频创作者误作 "Fibo"）。

**四象定义逐字对应**（Thariq "four-quadrant matrix"）：

| Thariq 原词 | 用户定义 | 对应 |
|---|---|---|
| Known knowns — what you put in the prompt | 已知已知 | ✅ |
| Known unknowns — gaps you know you have not researched | 已知未知 | ✅ |
| Unknown knowns — "know it when you see it" (design taste) | 未知已知 | ✅ |
| Unknown unknowns — blind spots you have not considered | 未知未知 | ✅ |

**关键印证**：Thariq 给出的具体方法（blind spot pass / design prototypes / architecture interview）与我们的悬置区 / SHADOW / 成长箱机制同构；其 "map is not territory"（地图非疆域）隐喻，与本文件开篇"记忆是认知状态的地图"直接呼应。其"把 unknowns 永久写进 CLAUDE.md"的闭环，正是用户用 MEMORY / SOUL / IDENTITY / USER 四文件在做的事。

→ 结论：本四象限框架非闭门造车，已有业界 practitioner 独立验证其人机协作有效性。

### 2.6.2 应用示例（2026-07-09）：用四象限定位 AI 自身盲区

> 轻量应用实例——展示"无知矩阵"如何反查 AI 自己的设计盲区，而非只用来给用户记忆贴标签。

**场景**：triwich L3 内联转发门禁锁（v3.8.5）。主 Agent 最初把子 Agent 的完整推导经 /tmp 文件通道中转呈现，子 Agent 看不到主对话 → 推导上下文漏出，违反门禁锁"主对话内联"要求。

**用四象限定位**：这格属于 **未知已知**——
- 用户的行为（L3 门禁明确要求"主对话内联"）已暴露缺口；
- AI 没意识到自己在用错误通道（文件通道），把"呈现"误当成"中转"。

**落法**：不是加检测捕获"中转泄漏"，而是设计端消除——把呈现锁死在唯一可见通道（主对话内联），使错误物理上无法发生。这正是 §一1.1"用设计消除错误"在四象限坐标系里的具体落地。

### 2.7 理论深化：未知未知为何难捕、如何捕（补充锚点）

> 本节补 §2.1-2.6 未覆盖的"机制层"——前文言"未知未知是什么、在哪"，本节言"为何难捕、如何捕"。直接支撑 §四 4.1 的未知未知缺口与悬置区（前置容器）设计。

**2.7.1 元无知（Dunning-Kruger, 1999）**：能力低者不仅无知且无法意识到——未知未知在个体层面的实证机制。含义：靠"自觉"捕捉必失效，必须外部探针 / 双主体互检。

**2.7.2 Knightian / Radical Uncertainty**：风险可度量、不确定性不可度量；未知未知属"不确定性"，连可能结果清单都没有。强化"不可枚举"命题。

**2.7.3 双环学习（Argyris & Schön）**：未知未知藏在"理所当然的底层假设"（theory-in-use vs espoused theory 的裂缝）。捕捉手段 = 暴露底层假设。

**2.7.4 Cynefin 复杂域 Probe-Sense-Respond**：面对未知未知先行动再理解，秩序从混沌涌现。直接支撑"低结构化毛坯 + 探针投喂"设计（见 §四 悬置区）。

**2.7.5 意义建构（Weick, enacted sensemaking）**：未知未知"显形"不是发现真相，而是通过介入"建构"解释。支撑"显形闭环"是建构而非检索。

**2.7.6 涌现与复杂适应系统（Nature 2025）**：未知未知有时是系统层涌现属性，信息全也消除不了。边界条件：本系统只能"提高显形率"，不能"消除未知未知"。

**2.7.7 关键澄清：残差 ≠ 未知未知（A4 假设）**
- **残差** = "已浮现但记录者当场无法归因"的信号（已感知异常，见 §四 悬置区定义）。
- **未知未知** = "双方都没意识到"的认知盲区（不可感知，Rumsfeld 原话最危险一类）。
- 二者关系：残差是未知未知"显形过程"中、尚未归因的**过渡态**（未知未知 → 残差 → 未知已知/已知已知），而非第四格本身。纯未知未知（双方共盲、系统性盲区）在"显形"前不可被残差机制捕获，须靠**被动诱捕触发**（探针/冲突检测）才浮现。
- 含义：前置容器设计须同时覆盖"已浮现残差（主动标注）"与"未浮现盲区（被动诱捕）"两类来源，缺一不可。

**2.7.8 设计天花板与成功标准**
- 基于 §2.7.6 涌现边界：本改造的目标是**"提高显形率、缩短盲区存活时间"**，而非"消除未知未知"（后者不可能）。
- 建议成功标准（固化供后续实施参照）：
  - **显形率** = 悬置区条目中在月度回看内成功转出（归因到 SHADOW/成长箱/CORE）的比例；
  - **平均盲区存活时长** = 一条信号从产生到被标注为残差/盲区的中位时长。
- 反例警示：若把目标设成"清零未知未知"，整套设计将走偏为过度工程。

> 来源：Dunning-Kruger (1999) / Harvard Kennedy School Knightian / Springer Double-Loop / decisiondesignlab Cynefin / high-reliability.org Weick / Nature 2025。

## 三、实例二 · 时间管理矩阵（重要×紧急）【理论溯源】

> 本实例回答："处理这条记忆/议题，该排多前？"

### 3.1 Eisenhower 原则

**核心主张**：艾森豪威尔有名言（常被引用）：

> "What is important is seldom urgent, and what is urgent is seldom important."
> （重要的事很少紧急，紧急的事很少重要。）

他给出了"重要 vs 紧急"的二维判断原则，但**未成 2×2 矩阵形式**。

### 3.2 Covey 系统化（1989 / 1994）

**核心主张**：Stephen Covey 在《高效能人士的七个习惯》(1989) 与《要事第一》(1994) 中，将 Eisenhower 原则系统化为 2×2 矩阵：

| | 紧急 | 不紧急 |
|---|---|---|
| **重要** | Q1 重要紧急（危机/截止） | **Q2 重要不紧急（规划/关系/成长）** |
| **不重要** | Q3 紧急不重要（打断/琐事） | Q4 不重要不紧急（消遣/浪费） |

**Covey 核心洞察**：高效能的关键在 **Q2（重要不紧急）**——它常被 Q1/Q3 挤掉，却是长期产出的来源。

### 3.3 时间矩阵·四象限定义与用户的盲区对症

| 象限 | 定义 | 布洛陀对症 |
|------|------|-----------|
| Q1 重要紧急 | 必须立刻做 | 系统日志/当月紧急任务 |
| **Q2 重要不紧急** | 该做但没截止 | **用户的时间膨胀盲区**：CORE 里"低估时间、高估剩余"（Q6），重要不紧急一直拖 |
| Q3 紧急不重要 | 假紧急 | 噪音/打断，应 delegating/拒绝 |
| Q4 不重要不紧急 | 纯消耗 | 应削减 |

**关键对接**：用户的核心盲区是"时间膨胀感"（CORE Q6——低估任务耗时、高估剩余时间）。时间管理矩阵正是治它的武器——它强制把 Q2（重要不紧急）从"一直拖"变成"显式排入"。本系统的记忆层（五层）不存任务优先级，时间轴是**全新维度**，落点见 §四 4.2。

### 4.3 三维正交共存原则

一条记忆/议题在布洛陀中可同时带三个独立标签，**互不替代**：

```
┌─ 五层位置 (L1 核心 / L2 … / L5 潜意识)   ← 稳定度轴（纵向分层）
├─ 认知象限 (已知已知 / 已知未知 / 未知已知 / 未知未知)  ← 认知轴（人机双主体状态）
└─ 时间象限 (Q1 / Q2 / Q3 / Q4)             ← 时间轴（行动优先级）
```

例：`S级顿悟"概念定义锁"` = L1 核心 + 已知已知 + Q2 重要不紧急（需持续维护但无截止）。三维一起看，才完整。

## 五、架构决策记录（ADR）

### ADR-001：四象限作为元框架，而非直接套用某个矩阵

- **日期**：2026-07-07
- **决策**：四象限定位为"通用方法论框架"，下面挂无知矩阵 + 时间管理矩阵两个实例，不把任一矩阵直接当系统架构
- **理由**：① 两个矩阵解决不同问题（认知状态 vs 行动优先级），单矩阵覆盖不全；② 框架可扩展——未来若有第三应用领域（如"价值×难度"），可直接挂上而不改结构；③ 对齐用户"元框架"的明确定义
- **代价**：文档略长（需分别写两个实例的理论）
- **替代被拒**：直接把"无知矩阵"当顶层（会漏掉时间轴，无法治用户时间膨胀盲区）；直接把"时间矩阵"当顶层（会漏掉认知状态轴，SHADOW 等载体失去坐标系）

### ADR-002：认知轴限定为"我和 AI 之间"双主体

- **日期**：2026-07-07
- **决策**：无知矩阵的四个象限，显式限定为"人机双主体的认知边界状态"，非客观知识独立分类
- **理由**：① 用户硬定义；② 理论对接 Johari Window（1955）的"自我 vs 他人"双主体传统，是学术上自洽的；③ 使"未知已知"（用户没意识到的自己）的载体 SHADOW 获得坐标系归属，而非孤立模块
- **代价**：与 Rumsfeld 原语境（国防情报的客观分类）偏离，需文中显式标注此限定
- **替代被拒**：沿用 Rumsfeld 客观分类（失去"人机关系"维度，SHADOW 等载体无法接入）

### ADR-003：三维标签正交共存

- **日期**：2026-07-07
- **决策**：一条记忆可同时带 `五层位置 + 认知象限 + 时间象限` 三维标签，互不替代
- **理由**：五层是稳定度轴、四象限是认知轴+时间轴，三者正交；强行合并会破坏五层已稳定的分层模型
- **代价**：写入时需填多个标签，略增负担
- **缓解**：标签可选填，非强制全填；核心容器（CORE/S级/SHADOW）必填认知象限即可
