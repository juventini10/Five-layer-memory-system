# 最伟大的我 · 文件格式约定 v1.0.0

> 本文件自身即遵守本约定（见上方 YAML 头），作为活样板。
> 所有「最伟大的我」子目录下新建/已有文件均须遵守本约定。

---

## 一、目的

1. 为**最伟大的我**全部子目录文件提供统一的 YAML frontmatter，使 AI 无需读正文即可快速检索（类型/时效/来源/自发现 vs AI观察）。
2. 为**安装包模板**提供可脱敏的标准样例（`{称呼}` 占位）。
3. 为**Skill 自动写入**（Shall We Talk / 每日伙伴月报 / system-logger 月报蒸馏）提供写入格式规范。

---

## 二、通用必填字段（所有子目录）

按 `文件格式规范 v1.0.2` §三推导：

| 字段 | 必/选 | 说明 | 示例 |
|---|---|---|---|
| `title` | 必 | 文件标题（与正文 H2 首节不重复） | `九个Skill中的系统治理者思维` |
| `type` | 必 | explanation / reference / plan（见 §三） | `explanation` |
| `date` | 必 | 最新实质更新日 ISO `YYYY-MM-DD` | `2026-07-18` |
| `version` | 必 | 语义版本 `vM.N.P` | `v1.0` |
| `status` | 必 | active / draft / deprecated | `active` |
| `summary` | 必 | ≤40字，给 AI 快速判断 | `WorkBuddy对皮叔Skill设计的三条新认知` |
| `source` | 必 | 来源描述（对话/月报/SWT/手动） | `2026-07-18 对话 \| 发现者：WorkBuddy` |
| `author` | 选 | 维护者/作者（包内模板用 `{称呼}` 占位） | `皮叔` / `WorkBuddy` / `{称呼}` |
| `tags` | 选 | 主题标签列表 | `[认知发现, AI观察, Skill设计]` |
| `area` | 选 | 归属子目录 | `认知发现` |

## 三、子目录专属字段

### 3.1 认知发现

新增字段 `discovery_type`（必填），区分来源：

| 值 | 含义 | 写入方 |
|---|---|---|
| `自发现` | 你自己想通的认知 | Shall We Talk / 迁理之外 / 日记 |
| `AI观察` | AI 在协作中对你的观察发现 | WorkBuddy / AutoClaw 等 |

**完整 YAML 样板**：

```yaml
---
title: {标题}
type: explanation
date: {YYYY-MM-DD}
version: v1.0
status: active
summary: {一句话摘要}
source: {来源描述} | 发现者：{称呼/AI名称}
author: {称呼/AI名称}
discovery_type: 自发现
tags: [认知发现, 自发现, {主题标签}]
area: 认知发现
---
```

## 四、脱敏约定（安装包模板）

包内模板文件的差异：

| 字段 | 源文件（你的） | 包内模板 |
|---|---|---|
| `author` | `皮叔` / `WorkBuddy` / 具体名称 | `{称呼}` |
| `source` 中的人名 | `发现者：WorkBuddy` | `发现者：{称呼}/AI名称` |
| `tags` 中的人名 | `皮叔思维模式` | `{称呼}思维模式` |
| 正文中的具体人名 | 保留 | 替换为 `{称呼}` |
| `discovery_type` | 自发现 / AI观察 | 不变（中性概念） |

镜像同步的 deident_rules.py 已配置自动脱敏（`用户→用户`、`用户名→用户名`）。本约定新增的 `{称呼}` 占位符适用于**包内用户拿到模板后自行替换**的场景。

---

## 五、Skill 写入合规要求

任何 Skill 写入最伟大的我时，必须：

1. 按本约定对应子目录的 schema 写入 YAML frontmatter（`---` 必须是文件绝对第一行）
2. `---` 闭合后空一行再写正文标题
3. 正文从 `##`(H2) 起
4. `summary` ≤40 字
